# BokriLog Product Brief — 후속 인계 부록

이 문서는 1~2페이지 제품 브리프에 넣지 않은 조사 근거와 PRD·계산 SPEC·아키텍처 인계사항을 보존한다. 제품 결정의 정본은 `forged-idea.md`이며, 이 부록은 해당 문서의 `INV-*`, `DEC-*`, `REJ-*`를 변경하지 않는다.

## 변경 금지 경계

- 다중 거래소, 코인·상품·전략별 공식 성과, 과거 계획 자동 복원, 주문·출금·이체, 24시간 수집, 투자 행동 추천은 현재 비목표다.
- 다중 거래소와 상품별 공식 성과는 단순 Later 항목이 아니며, 제품 방향을 다시 Forge하지 않고 되살리지 않는다.
- 공식 현재가치는 검증된 단일 UTA의 USD 환산 `totalEquity`이며, 쓰기 권한 키와 쓰기 API 경로는 허용하지 않는다.

## 보안 탐지와 범위별 중단 정책

| 사건 | 탐지 | 중단 범위 |
|---|---|---|
| 저장 전 쓰기 키 입력 | pending 상태에서 `readOnly=1`, UTA, UID, IP, 실제 읽기 성공 검증 | 해당 연결 시도만 거부하고 입력된 키를 메모리에서 폐기한다. 반복 시 사용자·IP 단위로 제한한다. |
| 활성 키의 권한 변경 | 각 동기화 전 권한 재검증 | 해당 연결의 복호화·동기화만 격리 |
| 쓰기 키 저장·사용 또는 공통 검증 실패 | 저장 불변식, 복호화 감사, 전체 키 메타데이터 검사 | 신규 연결과 동기화를 전역 중단하고 전체 활성 키 재검증 |
| 자격정보 노출 | 저장소·빌드·프런트 번들·로그·오류수집 비밀 스캔, 비정상 복호화 접근 | 영향 범위를 특정할 수 있으면 해당 연결만 격리한다. 공통 경로가 원인이거나 영향 범위가 불명확하면 연결·동기화·복호화를 전역 중단한다. |
| 중대 보안사고 | 교차 사용자 접근, 무단 복호화, 예상 밖 외부 통신, 관리자 설정 변경, 감사로그 중단·변조 | 영향 범위를 특정할 수 없으면 모든 민감 경로를 중단한다. 앱 밖의 인프라 통제 경로를 통해 외부 통신과 복호화 권한도 차단한다. |
| 중대 계산 오류 | 고정 정답 사례, 속성 테스트, 이전·신규 버전의 섀도(shadow) 비교, 결정성·중복·누락·비유한 값·신뢰 상태 검사, 사용자 신고 재현 | 개별 입력 데이터 문제는 해당 계획을 격리한다. 공통 문제는 해당 계산 버전의 결과 게시를 중단한다. 광범위한 API 정규화 문제는 동기화를 전역 중단한다. |

### 정지 불변식

서버에는 최소한 `CONNECT_OFF`, `SYNC_OFF`, `DISPLAY_MODE(normal/last_trusted_only/hidden)`가 필요하다. 모든 민감 작업은 실행 직전에 관련 정지 상태를 확인하고, 확인할 수 없으면 해당 작업을 차단한다. 정지는 자동화하되 복구는 자동화하지 않는다.

### 수동 복구 게이트

다음 조건을 순서대로 충족한 뒤 제한된 연결부터 수동으로 재개한다.

1. 원인과 영향 범위를 확인한다.
2. 노출 키와 내부 비밀을 폐기·회전한다.
3. 보안·계산 회귀 테스트와 영향받은 계획의 재계산 검증을 통과한다.
4. 합성 계정으로 안전한 읽기 전용 동기화를 검증한다.
5. 제한된 기존 연결, 전체 기존 연결, 신규 연결 순으로 재개한다.

### 시스템 밖 통제 경계

- **거래소 키 폐기:** BokriLog는 노출된 키의 사용을 중단하고 암호문을 삭제할 수 있지만, 거래소에 등록된 키를 대신 폐기할 수는 없다. 영향 사용자가 Bybit에서 키를 삭제하고 새 읽기 전용 키로 재연결해야 한다. [Bybit API Key 삭제](https://www.bybit.com/en/help-center/article/How-to-delete-your-API-Key)
- **탐지 불가능 영역:** 화면 캡처·클립보드 유출, 정상 권한을 탈취한 저속 접근, 프로세스 메모리 탈취, 명세와 테스트가 함께 틀린 계산 오류는 자동 탐지가 어려울 수 있다. 확인된 사고 0건은 발견 능력의 증거가 아니므로 정기 모의훈련과 사용자 신고 채널이 필요하다.

## 워크플로별 근거와 검증 한계

### PRD·제품 포지셔닝

[Delta](https://delta.app/en/features), [CoinTracking](https://cointracking.info/crypto/portfolio/crypto-portfolio-tracker/), [CoinTracker](https://www.cointracker.io/features) 같은 공개 경쟁 제품은 다중 거래소, 실시간 P&L, 세금·고급 분석의 폭을 강조한다. BokriLog는 이 폭과 경쟁하지 않고 계획 기준선 보존과 UTA 실제값 비교에 집중한다. 공개 경쟁 제품 조사에서 같은 기능 조합을 찾지 못했다는 사실은 차별화 가설일 뿐, 시장 전체에서 유일하다는 증거는 아니다.

### 계산 SPEC·기술 스파이크

- Bybit Wallet Balance의 `totalEquity`는 UTA 자산 equity를 USD로 환산한 계정 전체 값이다. UTA 버전과 마진 모드에 따라 포함되는 자산 범위가 다르고, 일부 계정 전체(account-wide) 필드는 격리 마진(isolated margin)에 적용되지 않는다. 따라서 지원할 UTA 버전과 마진 모드를 실제 계정으로 검증해야 한다. [Wallet Balance](https://bybit-exchange.github.io/docs/v5/account/wallet-balance), [Account Modes](https://bybit-exchange.github.io/docs/v5/acct-mode)
- Transaction Log는 요청 기간·페이지 크기·보존 범위가 제한되므로 커서, 페이지네이션, 누락 복구 규칙 없이는 사건 원장을 신뢰할 수 없다. [Transaction Log](https://bybit-exchange.github.io/docs/v5/account/transaction-log)

### 보안·운영

API Key Information은 `readOnly`, `uta`, UID, IP, `deadlineDay`, `expiredAt`을 제공한다. 응답에 API Key 자체도 포함되므로 원시 요청·응답 로깅을 금지하고 허용 필드만 기록해야 한다. [API Key Information](https://bybit-exchange.github.io/docs/v5/user/apikey-info)

### 검증 한계

공식 문서와 법령 검토는 API 지속성, 계산 정확성, 법률 적합성, 시장 수요를 보증하지 않는다. 외부 사용자 인터뷰와 실제 UTA 계정 검증은 아직 수행하지 않았다.
