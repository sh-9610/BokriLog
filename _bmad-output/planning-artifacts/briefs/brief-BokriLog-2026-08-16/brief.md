# BokriLog Product Brief

## 제품·사용자·베타 목적

BokriLog는 복리 목표를 세우고 Bybit에서 현물 또는 USDT 무기한 계약 등을 운용하는 개인 투자자를 위한 읽기 전용 웹 서비스다. 최초 계획과 입출금 조정 이력을 보존하고, Bybit Unified Trading Account(UTA)의 공식 USD 환산 계정가치인 `totalEquity`를 계획선과 비교한다. 사용자는 “오늘 얼마여야 하는지, 지금 얼마나 앞서거나 뒤졌는지, 남은 기간에 어떤 등가수익률이 필요한지”를 확인할 수 있다.

핵심 문제는 계산식이 아니라 기준선의 소실이다. 현재 잔액으로 계산기를 다시 돌리면 최초 목표와 조정 이력이 사라지고, 거래 뒤 엑셀이나 계산기를 갱신하는 흐름은 오래 유지되기 어렵다. BokriLog는 범용 포트폴리오 분석기가 아니라 **계획 보존과 실제 계정가치 자동 비교**에 집중한다. 최초 계획을 움직이지 않고 UTA 경계를 넘은 사용자 자본만 원금으로 조정한다. 입금은 수익이 아니며 계정 내부 손익·가격변화·미실현손익·펀딩비·수수료·이자·리베이트는 계정 성과다.

사용자는 목표 기간, 복리 주기, 주기별 목표율을 직접 정하고 첫 정상 연결 시점부터 계획을 시작한다. 서비스는 투자 행동을 추천하지 않고 수학적 차이만 중립적으로 보여준다. 현재 근거는 창업자의 반복 경험과 Bybit 공식 API·관련 법령 검토이며, 외부 수요·API 키 온보딩·설명 이해도·시장성은 미검증 상태다. 공개 베타는 이 가설들을 월 30,000원 이하의 운영비로 검증한다.

## MVP

| 기능군 | 범위 |
|---|---|
| 연결·자격정보 | 서버는 `readOnly=1` 여부와 UTA·UID·IP 상태를 확인하고 실제 조회 성공 여부를 검증한다. 쓰기 권한 키가 입력되면 저장 전에 해당 연결 시도만 거부한다. `API Key`와 `API Secret`은 암호화하고 화면·로그·분석 도구에 노출하지 않으며, 연결 해제 시 삭제한다. |
| 계획·자금흐름 | 첫 정상 연결의 `totalEquity`에서 기간·주기·목표율이 고정된 새 계획을 시작한다. 확인된 UTA 경계 입출금만 원금을 조정하고, 비-USDT 자금흐름은 이벤트 시점 USD 가치와 추정 상태를 사용한다. 과거 계획 자동 복원은 제공하지 않는다. |
| 지표·신뢰 상태 | UTA 전체의 USD 환산 `totalEquity`를 공식 현재가치로 삼아 현재가치, 오늘 계획금액, 부호 있는 차이, 조정 최종 목표, 남은 필요 등가수익률, 전체 목표 수익 달성도를 표시한다. 신선도, 입력 신뢰도, 계산 성격을 독립적으로 표시한다. |
| 동기화·비상정지 | 대시보드 진입, 탭 재활성화, 명시적 새로고침에서 동기화한다. 사고 시 연결·동기화·계산 표시를 범위별로 중단할 수 있어야 한다. 24시간 백그라운드 수집은 하지 않는다. |

## 공개 베타 성공 기준

서비스 Day 60에 다음 기준으로 계속·중단·재설계를 판단한다.

| 검증 축 | 성공 기준 |
|---|---|
| 표본과 활성화 | 테스트 사용자 12명 이상, 읽기 전용 연결과 계획 생성 완료율 80% 이상 |
| 반복 가치 | 활성화 사용자의 50% 이상이 첫 4주 동안 서로 다른 3주에 각각 한 번 이상 재방문 |
| 연결 품질 | 동기화 성공률 95% 이상 |
| 이해 가능성 | 사용자의 80% 이상이 계획금액·현재 차이·자금흐름 조정·신뢰 상태를 올바르게 해석 |
| 1인 운영성 | 안정화 후 지원·운영 주 2시간 이하, 월 인프라 비용 30,000원 이하 |
| 안전성 | 확인된 중대 보안 사고, 자격 정보 노출, 쓰기 권한 키 수용, 중대 계산 오류 0건 |
| 안전 통제 | 읽기 전용 검증 실행률과 배포별 보안·계산 검증 통과율 100%, 강한 신호 탐지 후 60초 이내 자동 정지, 5분 이내 수동 전역 정지, 베타 전 및 월 1회 비상 정지 훈련 성공률 100% |

안전성은 결과지표 0건과 선행 통제를 함께 평가한다.

## 수익화

공개 베타는 사용자에게 무료로 제공하고 문맥형 광고로 수익화한다. 금융정보를 광고 타기팅에 사용하거나 광고망에 전달하지 않는다. 광고 공급자, 배치, 도입 시점은 개인정보·보안·화면 신뢰를 해치지 않는다는 조건 아래 PRD 작성 및 출시 준비 단계에서 결정한다. 광고 수익과 무관하게 Day 60에 고정 IP 전환 가능 여부를 판단하고, Day 90 이후에는 IP 제한이 없는 키 요청을 중단한다.

## 핵심 위험과 대응 원칙

| 위험 | 조기 신호 | 대응 원칙 |
|---|---|---|
| 수요·온보딩 | 낮은 연결 완료율, 반복 사용 부족, 설정 문의 집중 | 실패 원인을 분류하고 Day 60 기준으로 계속·중단·재설계를 판단한다. |
| 계산 신뢰 | 사건 누락·중복, 미지원 UTA 모드, 비-USDT 가격 결측, 신뢰 상태 불일치 | 불완전한 입력은 공식 계산으로 승격하지 않는다. 입력 문제라면 해당 계획을 격리하고, 공통 문제라면 해당 계산 버전을 격리한다. |
| 보안·1인 운영 | 비정상 복호화, 쓰기 키 저장·사용, 교차 사용자 접근, 경보·훈련 실패 | 최소 수집과 복호화 감사를 적용한다. 쓰기 권한 키가 입력되면 해당 연결 시도만 거부한다. 공통 원인의 실패이거나 영향 범위를 특정할 수 없으면 신규 연결과 동기화를 전역 중단한 뒤 수동으로 복구한다. |
| 외부·법률 | Bybit API·정책 변경, 개인정보·광고 데이터 흐름 변경 | 공개 베타 전 기술 스파이크와 법률·개인정보 검토를 수행하고 운영 중 변경내역을 재검증한다. |

## 다음 단계

이 브리프는 제품 방향과 베타 판단 기준을 고정한다.

- **PRD:** 가입·지원 범위와 입력 범위, 오류 상태와 검토 필요 상태의 UX, 광고 배치, API 공백, 계획 종료 처리를 인수 조건으로 바꾼다.
- **구현·출시 전:** 계산 SPEC과 기술 스파이크를 완료하고 아키텍처·보안·운영·개인정보를 검토한다. 상세 인계사항은 `addendum.md`에 보존한다.
