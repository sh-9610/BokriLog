# BokriLog — Experience Spine

## Foundation

한국어 모바일 우선 반응형 웹이며 데스크톱을 동등 지원한다. 모바일 웹 대시보드가 대표 진입점이다. WCAG 2.2 AA를 최소 기준으로 삼은 커스텀 컴포넌트 시스템을 사용한다. 시각적 정체성과 토큰은 `DESIGN.md`가, 이 문서는 정보 구조·행동·상태·접근성을 소유한다.

서비스는 사용자 계정당 읽기 전용 Bybit UTA 연결 1개와 활성 계획 최대 1개를 다룬다. 거래 실행·투자 추천·상시 폴링은 제공하지 않는다. `DESIGN.md`와 이 문서는 상위 소스 내용을 반복하지 않고 `sources`를 기준으로 해석한다.

공개 베타는 무료·유광고 모델로 출시한다. 광고는 수동 동기화 성공 뒤 중립 전환 표면에서만 시도하며 금융 결과 접근의 대가나 조건이 아니다. 광고 미동의·미채움·차단·오류·접근성 실패는 개별 광고를 건너뛰는 사유일 뿐 저장된 결과를 막지 않는다.

공개 베타의 가입·로그인은 Google·네이버·카카오 3개 소셜 제공자의 OpenID Connect(OIDC) 인가 코드 흐름으로 통일한다. 비밀번호·이메일 링크·SMS 인증은 MVP에서 제공하지 않는다. 제공자는 본인 확인에만 사용하며 Bybit 자격정보, 금융값, 계획, 조정 이력을 제공자에게 전송하지 않는다.

남은 외부 출시 게이트는 PRD §12의 책임자와 차단 조건을 따른다. 아래 항목은 UX 사양을 미완료로 만들지 않지만 해당 기능의 구현·베타 출시 전에 닫아야 한다.

| 결정 항목 | 책임자 | 차단 범위 |
|---|---|---|
| 지원 UTA·사건 허용목록, 비-USDT 가격 출처·추정 조건, 십진수 정밀도·반올림 | 제품·계산 SPEC 책임자 | 계산 SPEC 및 구현 착수 |
| 광고 공급자·동의·데이터 흐름 | 제품·개인정보 책임자 | 공급자 선정은 구현 단계로 이관; 유광고 베타 출시 전 개인정보 검토·실제 접근성 승인 시험 필수 |
| 강한 신호 판정표 | 보안·운영 책임자 | 베타 출시 |
| 계정 삭제 시 최소 법정 기록의 정확한 대상·기간·목적 | 제품·개인정보 책임자 | 출시 전 법률 검토; 백업 최대 파기 기한은 30일로 확정 |

일반 사용자 전역 탐색은 대시보드, 조정 이력, 설정의 3개 목적지로 제한한다. 온보딩·연결·계획 생성은 순차 흐름, 신뢰 상세·종료·광고 전환은 한 단계 오버레이 또는 전용 화면이다. 운영자 표면은 같은 탐색과 DOM에 섞지 않는다.

## Voice and Tone

마이크로카피는 판정 대신 사실, 원인, 기준 시각, 다음 행동을 짧은 완전문으로 말한다. 브랜드 목소리는 `DESIGN.md`의 Brand & Style을 따른다.

| Do | Don't |
|---|---|
| “2026년 8월 23일 07:42에 측정한 마지막 정상값입니다.” | “실시간 자산입니다.” |
| “동기화하지 못했습니다. 기존 정상값은 그대로 유지됩니다.” | “잔액을 불러오지 못해 0원입니다.” |
| “입력 신뢰도: 검토 필요. 비-USDT 사건 시점 가격을 확인할 수 없습니다.” | “데이터 오류.” |
| “남은 필요 등가수익률은 월 주기 계획 비교값이며 투자 추천이 아닙니다.” | “목표 달성을 위해 월 8% 수익을 내세요.” |
| “복리 계획 비교입니다. 투자성과·계좌 수익률·투자 추천이 아닙니다.” | “내 투자 성과.” |
| “계획을 중도 종료하면 입력은 바꿀 수 없고 기록은 보존됩니다.” | “새 목표로 다시 도전해 보세요!” |
| “광고를 건너뛰어도 최신 결과를 확인할 수 있습니다.” | “광고를 시청하면 결과가 열립니다.” |
| “Google·네이버·카카오는 본인 확인에만 사용합니다. Bybit와 금융 데이터는 공유하지 않습니다.” | “안전한 간편 로그인입니다.” |
| “처음 가입할 때 사용한 방식으로 로그인해 주세요.” | “계정을 찾을 수 없습니다.” |

상태명은 소스 용어를 그대로 쓴다: 신선도 `최신`·`동기화 중`·`최신 아님`, 입력 신뢰도 `확인됨`·`검토 필요`·`사용 불가`, 계산 성격 `공식`·`추정`·`계산 불가`. “정확”, “안전 보장”, “성공/실패 투자”처럼 소스가 보장하지 않는 단어는 쓰지 않는다.

## Component Patterns

시각 사양은 `DESIGN.md` Components와 같은 이름을 사용한다.

| Component | Use | Behavioral rules |
|---|---|---|
| `app-shell` | 모든 일반 사용자 표면 | 모바일 하단/데스크톱 측면 탐색을 제공한다. 라우트 변화 뒤 제목으로 포커스를 옮긴다. 금융 응답을 지속 브라우저 캐시에 저장하지 않으며 로그아웃·세션 만료·계정 삭제 시 민감 화면과 뒤로 가기 복원을 차단한다. |
| `trust-status-panel` | 대시보드, 신뢰 상세, 완료 결과 | 세 축을 결합하지 않는다. 각 축 선택 시 원인·마지막 정상 시각·영향 지표·다음 행동을 펼친다. 동적 공지는 화면의 단일 상태 리전이 소유한다. |
| `metric-card` | 대시보드, 완료 결과 | 여섯 지표와 기준 주기·시각·계산 성격을 연결한다. 각 카드는 적용된 계산 성격과 원인 요약을 직접 포함하거나 신뢰 상세를 `aria-describedby`로 참조한다. `계산 불가`면 0을 표시하지 않고 이유로 이동한다. 동일 스냅샷 묶음만 렌더링한다. |
| `sync-control` | 대시보드, 완료 결과 | 요청 후 1초 안에 진행을 보이고 중복 입력은 같은 실행에 합친다. 진행 중 이전 값은 유지하며, 성공한 새 묶음만 한 번에 교체한다. 자동 진입/탭 재활성화 동기화는 광고를 열지 않는다. |
| `social-sign-in` | 인증, 민감 작업 재인증, 로그인 수단 연결 | `Google로 계속하기`, `네이버로 계속하기`, `카카오로 계속하기`를 고정 순서와 동등한 위계로 제공한다. 선택 즉시 해당 제공자의 도메인으로 이동함을 알리고, 돌아오면 원래 목적지를 복원한다. 취소·거부·제공자 장애는 BokriLog 오류 화면으로 수렴시키며 다른 제공자를 자동 선택하거나 로그인 요청을 반복하지 않는다. 마지막 사용 제공자를 공유 기기에 남기거나 계정 존재 여부를 암시하지 않는다. |
| `secure-input-form` | Bybit 연결 검증, 계획 생성 | 필드별 영구 라벨과 인라인 오류를 제공한다. 실패하면 API Secret만 지우고 나머지 유효 입력을 보존하며 비밀 필드로 포커스를 보내 재입력 이유를 알린다. 붙여넣기를 막지 않는다. 성공하면 비밀 원문과 마스킹 값을 모두 재표시하지 않는다. 검증 단계별 성공/실패를 구분하고 실패한 연결은 저장하지 않는다. |
| `confirmation-dialog` | 계획 생성 확정, 계획 종료, 연결 해제, 계정 삭제, 운영 정지/복구 | 대상·비가역 결과·삭제/보존 데이터를 먼저 말한다. 기본 포커스는 취소다. 계획 종료/연결 해제는 명시 확인, 계정 삭제와 전역 운영 정지는 대상명 재입력을 요구한다. |
| `history-row` | 조정 이력 | 사건 상세를 펼칠 수 있다. 데스크톱은 caption과 `th scope`가 있는 실제 표, 모바일은 사건별 heading/group과 연결된 반복 라벨을 쓴다. 펼치기는 사건명이 포함된 이름과 `aria-expanded`·`aria-controls`를 가진다. 재계산은 원 사건을 덮지 않고 원인, 발견·반영 시각, 영향 시작점·지표, 이전값→새값, 가격 출처·추정 상태를 새 버전에 기록한다. |
| `neutral-ad-transition` | 수동 동기화 성공 후 | 대시보드 상태를 서버에 이미 보존한 다음 별도 중립 라우트에서만 광고를 요청한다. iframe 밖의 네이티브 `광고 닫기`가 DOM의 첫 조작이며 최초 포커스를 받는다. 키보드 트랩·레이블 누락·로드 시간초과·보조기술 실패가 감지되면 광고를 건너뛰고 결과로 이동한다. 닫기·미채움·차단·오류·동의 거부는 모두 같은 최신 결과 라우트로 진행하며 재진입 시 광고를 다시 요구하지 않는다. |
| `service-notice` | 서비스 제한 상태 및 관련 표면 | 정지 범위·시작 시각·영향·가능한 행동을 제시한다. 마지막 정상값 조회는 허용 가능한 범위에서 유지한다. 웹 문의 폼 또는 지원 이메일을 연결하고 `영업일 기준 3일 이내 답변`을 인접 표시한다. 장애·복구 상태는 서비스 내부 공지에서 같은 사건의 시작·변경·복구 시각으로 이어서 제공한다. |
| `operator-control` | 운영자 제어·감사 | 연결·동기화·계산 표시·광고를 독립 선택한다. 실행 전 영향 범위를 미리 보여주고 사유를 필수 입력한다. 복구는 자동이 아니며 검증 증거·복구 조건 확인 뒤에만 가능하고 수행자·시각을 기록한다. |

## State Patterns

### 소셜 인증·계정 연결 계약

- Google·네이버·카카오 모두 OIDC Discovery와 Authorization Code 흐름을 사용한다. 웹 클라이언트는 PKCE(S256), 서버가 발급한 일회성 `state`와 `nonce`, 사전 등록된 정확한 redirect URI를 사용한다. 콜백은 서명과 `iss`·`aud`·`exp`·`nonce`를 검증한 뒤에만 BokriLog 세션을 만든다.
- BokriLog의 불투명 내부 `user_id`가 사용자 데이터 경계를 소유하고, 외부 로그인 식별자 `(issuer, subject)`는 별도 레코드로 `user_id`에 연결한다. 한 `user_id`에는 제공자별 식별자 1~3개가 연결될 수 있지만 같은 `(issuer, subject)`는 둘 이상의 `user_id`에 연결할 수 없다. 이메일이나 표시명은 키가 아니며 이메일이 같다는 이유로 계정을 자동 생성·병합·전환하지 않는다. 로그인 제공자에서 받은 액세스·ID·리프레시 토큰은 광고, 분석, URL, 브라우저 저장소, 클라이언트 로그에 넣지 않는다.
- 일반 로그인 콜백은 기존 `(issuer, subject)` 연결을 찾아 해당 `user_id`의 세션을 만든다. 연결되지 않은 식별자는 신규 가입으로만 처리한다. 로그인된 설정에서 시작한 명시적 연결 트랜잭션일 때만 검증된 새 `(issuer, subject)`를 현재 `user_id`에 추가하며, 이미 다른 사용자에 연결된 식별자는 어느 계정인지 밝히지 않고 연결을 거부한다.
- 기본 동의 범위는 로그인에 필요한 `openid`와 제공자별 최소 식별 정보뿐이다. 이메일·프로필이 제품 기능에 필요해질 때만 목적을 먼저 설명하고 별도 최소 동의를 요청한다. 마케팅·연락처·친구·게시 권한은 로그인과 묶지 않는다.
- 한 BokriLog 계정에 여러 로그인 수단을 연결하려면 로그인된 설정 화면에서 현재 수단으로 재인증한 뒤 새 제공자 인증까지 연속으로 성공해야 한다. 연결된 마지막 수단은 해제할 수 없다. 제공자 이메일 일치만으로 연결하지 않고, 지원 담당자도 이메일 확인만으로 병합·우회 복구하지 않는다.
- 새 제공자로 별도 계정을 만든 뒤 같은 Bybit UID 연결을 시도하면 제공자명이나 다른 계정 정보를 드러내지 않고 “이미 다른 BokriLog 계정에 연결된 Bybit 계정입니다. 처음 사용한 로그인 방식으로 로그인해 주세요”라고 안내한다.
- BokriLog 세션은 제공자 토큰과 분리된 `Secure`·`HttpOnly`·적절한 `SameSite` 쿠키로 유지한다. 로그인·재인증 성공 시 세션 식별자를 회전하며 로그아웃, 계정 삭제, 의심 세션 감지 시 서버 세션과 연결된 제공자 토큰을 폐기한다.
- Bybit 연결 생성·교체·해제, 로그인 수단 연결·해제, 계정 삭제, 의심 세션 이후에는 최근 인증을 요구한다. 사용자가 원래 로그인한 제공자로 재인증하는 것이 기본이며, 이미 안전하게 연결된 다른 제공자도 선택할 수 있다.
- 제공자 장애 또는 계정 접근 상실 시 연결된 다른 제공자가 있으면 그 방법을 선택할 수 있다. 하나만 연결된 경우 해당 제공자의 공식 계정 복구로 안내하며 BokriLog가 이메일만으로 인증을 우회하지 않는다. 복구 중 금융 화면과 존재 여부는 노출하지 않는다.

### 입력·수치 유효성 계약

- 시작금액과 시작 시각은 첫 정상 스냅샷에서 자동 고정해 읽기 전용으로 보여준다. 후속 계획은 생성 직전 새 정상 동기화를 요구한다.
- 종료 시각은 시작 뒤이며 기간은 1일 이상 1년 이하, 목표 주기율은 유한한 0 이상 십진수, 복리 주기는 일·주·월만 허용한다. 계획 경계와 화면의 `오늘`은 `Asia/Seoul` 기준임을 날짜 입력 가까이에 밝힌다.
- 금액·비율은 최종 표시에서만 소수 둘째 자리로 반올림한다. 음수와 100% 초과를 보존하며 `-0.00`은 `0.00`으로 표시한다.
- 현재가치가 0 이하인 정상 응답은 원 값을 보존하되 새 계획과 정의되지 않은 필요 등가수익률을 제한한다. 조정 최종 목표가 0 이하이면 목표 기반 비율을 `계산 불가`로 두고 이유를 연결한다.

### 광고 동의·제3자 데이터 계약

- 광고 동의 화면은 제3자와 공유될 수 있는 범주를 설명하고 개인 맞춤형·행태 기반이 아닌 비개인화 문맥형 광고만 사용한다고 밝힌다. 거부해도 동기화와 결과 조회는 동일하게 동작한다.
- 동의 전에는 광고 SDK를 초기화하거나 제3자 네트워크 요청을 보내지 않는다. 철회는 다음 광고 요청부터 적용하며 철회 뒤 핵심 기능을 제한하지 않는다.
- 광고 요청은 수동 동기화 성공 뒤에만 가능하며 계정 기준 최대 30분에 1회, `Asia/Seoul` 하루 최대 3회다. 자동 동기화, 실패한 동기화, 같은 성공 결과 재진입, 새로고침은 횟수를 소비하거나 광고를 다시 요청하지 않는다.
- 중립 광고 라우트의 DOM·URL·페이지 제목·슬롯명에는 API 자격정보, 사용자 식별자, 금융값, 계획값, 수익률, 자금흐름, 신뢰 상태를 넣지 않는다. 대시보드 DOM 문맥을 수집해야 하는 공급자는 승인하지 않는다.
- 구현 단계에서 공급자·공식 트리거·동의 문구·제3자 데이터 흐름을 확정하고 실제 광고 소재로 키보드·스크린리더 승인 시험을 통과해야 한다. 미확정 또는 시험 실패 상태에서는 유광고 베타 출시를 진행하지 않는다.
- 승인 시험은 키보드만으로 닫기 가능, 논리적이고 가시적인 포커스 순서, 광고 영역 밖으로의 키보드 포커스 이동, 스크린리더가 읽을 수 있는 광고·닫기 이름, 자동재생 음성과 과도한 깜빡임 방지, 확대·리플로 지원, 시간초과·차단·공급자 장애 시 결과 화면으로의 fail-open을 포함한다. 광고 소재나 SDK 버전이 접근성에 영향을 주는 방식으로 바뀌면 다시 시험한다.

### 계정 삭제·법정 보존 계약

- 계정 삭제가 확정되면 소셜 로그인 연결과 제공자 토큰, Bybit 자격정보, 계획, 스냅샷, 외부 자금흐름, 계산 결과·버전, 광고 동의를 삭제하고 모든 BokriLog 세션을 종료한다. 사용자 금융·계획 데이터를 분쟁 대비나 분석 목적으로 임의 보존하지 않는다.
- 다른 법령이 요구하는 최소 보안·관리자 접속기록만 대상, 법적 근거, 목적, 보존기간을 확정해 사용자 데이터와 분리 보관한다. 해당 기록에 Bybit 자격정보와 금융 상세값을 넣지 않으며 정해진 기간이 끝나면 복구 불가능하게 파기한다.
- 백업은 삭제된 계정을 서비스 복구에 사용할 수 없게 격리하고 계정 삭제 후 최대 30일 이내 제거한다. 운영 데이터 삭제 시점과 백업 파기 예정일을 계정 삭제 화면과 개인정보 처리방침에서 구분해 알린다.
- 무료 베타 기준의 정확한 법정 보존 대상·기간과 BokriLog의 금융·신용정보 관련 법적 지위는 출시 전 개인정보·핀테크 법률 검토로 확정한다. 이후 유료 결제를 도입하면 계약·결제·분쟁 기록의 별도 보존 의무를 다시 평가한다.

### 계산 근거·지표 전파 계약

`계산 근거 보기`는 스냅샷 ID, 공통 기준시점 `tc`, 현재가치 측정 시각, 계산 버전, 반영된 조정 이력 버전과 사건 링크를 한 묶음으로 제공한다. ID는 사용자·계정을 드러내지 않는 불투명 값이며 복사할 수 있다. 이전 버전은 덮어쓰지 않고 읽기 전용으로 남긴다.

| Condition | 현재가치 | 현재 시점 계획금액·계획 대비 차이·조정 최종 목표·남은 필요 등가수익률·목표 수익 달성도 |
|---|---|---|
| 정상 공식 입력 | 새 스냅샷의 `공식` 값 | 같은 스냅샷·버전의 `공식` 값 |
| 추정 환산가 포함 | 새 스냅샷의 `공식` 값 | 같은 스냅샷의 `추정` 값과 추정 근거 |
| 미분류·이력 공백·페이지 미완료·중복 의심·사건시점 가격 결측 | 마지막 정상값과 측정 시각 유지 | 마지막 정상 묶음을 유지하고 공식 갱신 보류; `검토 필요` 원인 표시 |
| 현재가치 0 | 원 값 `0.00`을 `공식`으로 표시 | 정의되는 금액만 표시하고 정의되지 않는 비율은 이유와 함께 `계산 불가` |
| 현재가치 음수 | 원 음수 값을 `공식`으로 표시 | 계획 대비 금액은 표시하되 남은 필요 등가수익률은 이유와 함께 `계산 불가` |
| 조정 최종 목표 0 이하 | 현재가치 성격 유지 | 목표 기반 지표를 이유와 함께 `계산 불가`, 계획은 `검토 필요` |
| 계산 버전 격리 | 영향받지 않은 현재가치와 측정 시각만 표시 | 해당 버전의 파생값을 가리고 격리 원인·마지막 검증 버전을 표시 |

서로 다른 측정 시각이나 계산 버전의 값을 하나의 최신 카드 묶음처럼 섞지 않는다. 지표 묶음 제목은 항상 `복리 계획 비교`이며, 첫 화면·결과·완료 결과에 “투자성과·계좌 수익률·투자 추천이 아닙니다”를 인접 배치한다.

### 네트워크 단절 계약

MVP는 오프라인 금융값 표시를 제공하지 않는다. 인증된 온라인 응답으로 받은 마지막 정상값만 화면에 유지할 수 있으며 이를 브라우저의 지속 캐시·서비스 워커·공유 로컬 저장소에 보관하지 않는다. 네트워크 연결이 필요한 변경 작업은 오프라인 상태에서 실행 전에 차단하고 입력을 보존하며 자동 재시도하지 않는다. 온라인 복귀 뒤 사용자가 다시 실행한다.

### 신뢰 상태 계약

| Axis | States | Always shown | Behavior |
|---|---|---|---|
| 신선도 | `최신`, `동기화 중`, `최신 아님` | 상태명, 현재 시도 상태, 마지막 정상 측정 시각 | 실패 시 `최신 아님`으로 바꾸되 마지막 정상값을 유지한다. |
| 입력 신뢰도 | `확인됨`, `검토 필요`, `사용 불가` | 상태명, 원인, 영향 구간/사건, 다음 행동 | 미분류·공백·페이지 미완료·중복 의심·가격 결측은 공식 갱신을 보류한다. 해결 불가능한 사유에는 지원/공지 경로가 확정된 경우만 연결한다. |
| 계산 성격 | `공식`, `추정`, `계산 불가` | 상태명, 계산 버전, 영향 지표, 이유 | 현재가치 자체와 자금흐름 의존 지표의 성격을 분리한다. 추정 흐름은 의존 지표 전체에 `추정`을 전파한다. 정의 불가 값은 0으로 치환하지 않는다. |

세 축은 언제나 독립적으로 읽혀야 한다. 예: `최신 + 검토 필요 + 계산 불가`가 가능하다. 상태 항목을 열면 “무슨 상태인가 → 왜 그런가 → 어떤 값이 유지/보류되는가 → 사용자가 무엇을 할 수 있는가” 순으로 설명한다.

### 원자적 갱신 계약

1. 동기화 시작 시 기존 스냅샷의 모든 값과 버전을 그대로 둔 채 신선도만 `동기화 중`으로 표시한다.
2. 진행 중 카드별 임시 값, 일부 페이지 결과, 0 대체값을 노출하지 않는다.
3. 성공하면 현재가치·외부 자금흐름·여섯 지표·세 신뢰 축·측정 시각·계산 버전을 같은 렌더 커밋에서 교체한다.
4. 수동 성공은 서버에 새 스냅샷을 먼저 확정한 뒤 `neutral-ad-transition`을 거친다. 광고 결과는 저장된 스냅샷을 변경하지 않는다.
5. 실패하면 이전 묶음을 유지하고 `최신 아님`, 실패 원인, 마지막 정상 시각, 재시도 가능 여부를 표시한다.

## Interaction Primitives

- 기본은 탭/클릭과 키보드다. 모든 핵심 조작은 `Tab`으로 도달하고 `Enter`/`Space`로 실행한다. `Esc`는 열린 비파괴 오버레이를 닫되 진행 중인 서버 작업을 취소했다고 오해시키지 않는다.
- 모든 조작은 `{colors.focus-ring}`과 `{spacing.focus-width}`·`{spacing.focus-offset}`을 사용하는 전역 `focus-visible` 표시를 상속한다. 포커스된 요소는 고정 탐색, 오버레이, 화면 키보드에 완전히 가려지지 않는다.
- 링크는 이동, 버튼은 상태 변경에만 쓴다. 행 전체 클릭 영역은 내부 링크와 충돌하지 않게 한다.
- 소셜 로그인 버튼은 각각 제공자명과 “계속하기”를 접근 가능한 이름으로 가진다. 새 창을 기본으로 열지 않으며, 제공자 왕복 뒤 포커스를 페이지 제목 또는 오류 요약으로 보낸다. 팝업을 쓰게 되면 차단·닫힘을 감지해 같은 탭 대체 경로를 제공한다.
- 동기화는 명시적 한 번의 요청이며 반복 클릭, 새로고침, 탭 재활성화가 중복 실행을 만들지 않는다. 자동 진입/탭 재활성화 동기화에는 광고가 없다.
- 파괴적 조작은 숨은 제스처로 제공하지 않는다. 계획 종료·연결 해제·계정 삭제·운영 정지/복구는 `confirmation-dialog`를 거친다. 확인 문구는 결과와 복구 가능성을 구체적으로 말한다.
- 광고 닫기는 iframe 밖의 첫 네이티브 조작이며 즉시 키보드·스크린리더로 식별 가능해야 한다. 전체 화면 라우트는 일반 탭 순서를 사용하고 모달일 때만 상위 문서 범위에서 포커스를 순환시킨다. 닫힌 뒤 갱신된 대시보드 제목으로 포커스를 돌린다.
- 금지: 당겨서 새로고침으로 광고 유도, 자동 재시도 루프, 보상형 동기화, 카운트다운 닫기, 무한 스크롤, 호버 전용 조작, 스트릭·축하 폭죽·손실 경고 진동.

## Accessibility Floor

- 모든 표면은 WCAG 2.2 AA를 충족한다. 시각 대비는 `DESIGN.md` Colors의 목표를 따른다.
- 포인터 목표는 최소 `{spacing.target-min}` × `{spacing.target-min}`이며 인접 목표 사이에 충분한 간격을 둔다. 1280 CSS px 기준 400% 브라우저 확대와 320 CSS px viewport에서 양방향 스크롤 없이 핵심 과업을 수행한다.
- 상태는 색만으로 표현하지 않고 상태명, 아이콘의 대체 이름, 원인을 함께 제공한다. 세 신뢰 축은 각각 의미 있는 그룹과 제목을 가진다.
- 화면당 하나의 `role="status"` polite live region만 동적 공지를 소유한다. 갱신 중 결과 컨테이너에 `aria-busy="true"`를 두고, 완료·실패·검토 필요·서비스 정지는 우선순위에 따라 한 문장으로 한 번만 알린다. 세 신뢰 축과 카드에는 별도 live region을 두지 않는다.
- 비동기 제출 중 포커스는 호출 버튼에 유지하고 `aria-disabled="true"`와 중복 실행 차단을 함께 사용한다. 검증 단계는 이름 있는 순서 목록과 `aria-current="step"`으로 표현한다. 실패 시 오류 요약으로 포커스를 보내고 각 요약 링크가 정확한 필드 또는 해결 안내로 이동한다. 비밀 입력의 보이기/숨기기는 상태와 목적을 낭독한다.
- 대화상자는 제목을 읽고 내부에 포커스를 가두며 닫힐 때 호출점으로 돌아간다. 파괴 확인의 기본 포커스는 취소다.
- 모션 감소 설정에서는 회전 스피너를 포함한 전환 애니메이션을 제거하고 정적 진행 표지와 텍스트를 사용한다. 자동재생 영상·시차 효과는 없다.
- 조정 이력 표는 caption·열/행 머리글을 프로그램적으로 연결하고 모바일 카드도 사건별 heading/group과 반복 라벨 관계를 유지한다. 정렬 결과는 한 번만 짧게 공지한다.
- 표와 긴 숫자는 의미 단위로 낭독되며 통화·백분율·부호를 생략하지 않는다. `-0.00`은 `0.00`으로 읽고, 음수·100% 초과 값을 잘라내지 않는다. 시각 축약이 필요하면 전체값을 열고 복사할 수 있으며 보조기술에는 전체값을 제공한다.
- 고정 탐색과 대화상자는 safe-area, `scroll-padding`, 제한 높이와 내부 스크롤을 사용해 확대·화면 키보드 환경에서도 포커스를 가리지 않는다.

MVP는 설치형 앱, 오프라인 금융값 표시, 오프라인 쓰기, 푸시 알림을 약속하지 않는다. 네트워크 단절 시 새 공식 계산이나 상태 변경을 만들지 않는다. 출시 계약은 라이트 모드만 포함하고 다크 모드는 후속 대비 검증 뒤 결정한다.

| NFR-9 | 내부 `user_id` 사용자 경계와 `(issuer, subject)` 로그인 매핑, 서버 소유권 검증; 이메일 기반 자동 병합 금지 |
| NFR-10 | 계정 삭제 표면, 계정 삭제·법정 보존 계약과 Flow 7; 백업은 최대 30일 내 파기, 최소 법정 기록의 정확한 대상·기간 미확정은 출시 차단 |

## Inspiration & Anti-patterns

- 기준은 특정 금융 앱의 외형이 아니라 “검증 가능한 장부”다. 마지막 정상값, 측정 시각, 원 사건, 계산 버전이 서로 이어지는 추적성을 채택한다.
- 거래 터미널의 네온, 깜박이는 시세, 과도한 그래프를 거부한다. BokriLog는 준실시간 시장 화면이 아니다.
- 수익 축하·손실 공포·스트릭·배지·푸시 압박을 거부한다. 지속 이용은 짧은 확인, 이력 보존, 장애 후 복귀 가능성에서 나온다.
- 광고를 보상이나 결과 접근 조건으로 만드는 패턴을 거부한다. 중립 전환에서만 시도하고 모든 광고 실패 경로는 같은 저장된 결과로 수렴한다.

## Key Flows

### PRD 사용자 여정

### UJ-1. 민준이 출근 전 계획 진행 상황을 확인한다.

1. 민준은 출근 전 모바일 웹 대시보드를 연다.
2. 화면은 마지막 정상 현재가치와 측정 시각, 신선도·입력 신뢰도·계산 성격을 여섯 지표보다 먼저 보여준다.
3. 민준이 `수동 동기화`를 누르면 1초 안에 진행 상태가 나타나고 기존 정상 스냅샷은 유지된다.
4. 모든 구간과 페이지가 검증되면 새 스냅샷 묶음이 서버에 원자적으로 확정된다.
5. 동의·채움·접근성 조건을 충족하고 최근 30분·당일 3회 제한에 걸리지 않으면 별도 중립 전환 화면이 닫기 가능한 전면광고를 시도한다. 조건을 충족하지 않거나 민준이 광고를 닫으면 저장된 결과로 이동한다.
6. **핵심 결과:** 현재가치, 현재 시점 계획금액, 계획 대비 차이, 조정 최종 목표, 남은 필요 등가수익률, 목표 수익 달성도가 같은 측정 시각·계산 버전으로 한 번에 바뀐다. 민준은 계획보다 앞섰는지와 남은 주기율을 빠르게 파악한다.
7. 민준은 거래 권고나 추가 계산 없이 화면을 닫고, 계획과 조정 이력은 유지된다.

실패 경로: 동기화가 실패하면 광고를 열지 않고 마지막 정상 묶음과 시각을 유지한 채 `최신 아님`과 원인을 표시한다. 광고가 미채움·차단·오류·동의 거부여도 저장된 최신 결과로 즉시 이동한다.

### UJ-2. 민준이 처음으로 읽기 전용 연결과 계획을 만든다.

1. 민준은 온보딩에서 BokriLog가 거래하지 않으며 읽기 전용 키만 받는다는 설명과 준비사항을 확인한다.
2. API Key와 API Secret을 입력하고 검증을 시작한다.
3. 화면은 읽기 전용 권한, 지원 UTA, UID·IP 상태, 실제 지갑 조회를 순서대로 확인한다.
4. 검증 성공 뒤 비밀 원문은 사라지고, 첫 정상 `totalEquity`와 측정 시각이 수정 불가능한 시작금액·시작 시각으로 표시된다.
5. 민준은 종료 시각, 일/주/월 복리 주기, 0 이상 목표 주기율을 입력하고 불변 조건을 확인한다.
6. **핵심 결과:** 활성 계획이 생성되고 대시보드가 첫 정상값·세 신뢰 축·계획 지표를 같은 근거 묶음으로 보여 주어 민준은 연결과 기준선이 확정됐음을 확인한다.

실패 경로: 쓰기 권한, 형식 오류, 만료·폐기, UID/IP 불일치, 미지원 UTA, 조회 실패는 각각 원인과 다음 행동을 보여주고 연결을 저장하지 않는다. 입력 신뢰도 미확인, 정상 동기화 없음, 현재가치 0 이하, 기간/율 오류면 계획 생성만 차단하고 유효 입력은 보존한다.

### UJ-3. 민준이 신뢰할 수 없는 자금흐름 때문에 계산이 보류된 이유를 이해한다.

1. 민준은 대시보드에서 마지막 정상값은 남아 있지만 입력 신뢰도가 `검토 필요`이고 일부 지표가 갱신되지 않은 것을 본다.
2. `trust-status-panel`에서 입력 신뢰도를 선택해 신뢰 상세로 이동한다.
3. 화면은 미분류 사건 또는 비-USDT 사건 시점 환산가 결측의 원인, 영향 구간, 마지막 정상 시각, 보류된 지표를 설명한다.
4. 민준은 조정 이력에서 공식 반영된 사건과 보류된 원인을 섞지 않고 확인한다.
5. **핵심 결과:** 민준은 최신값처럼 보이는 임시 숫자 대신 마지막 정상값이 유지된 이유와 완전한 동기화 성공 전에는 공식 계산이 바뀌지 않는다는 사실을 이해한다.
6. 원인이 해소된 뒤 다음 완전 동기화가 성공하면 새 계산 버전과 변경 근거가 표시되고 의존 지표가 함께 갱신된다.

실패 경로: 사용자가 직접 해소할 수 없는 원인이면 무의미한 재시도를 반복시키지 않고 서비스 공지 또는 확정된 지원 경로를 제시한다. 원인이 남아 있으면 `검토 필요`를 유지하며 공식값으로 승격하지 않는다.

### UX 보완 흐름

### Flow 4 — 민준이 계획을 끝내고 완료 결과를 확인한다.

1. 민준은 계획 메뉴에서 `계획 종료`를 선택한다.
2. 확인 화면은 예정 종료 전이면 `중도 종료`가 되며, 성공/실패 판정 없이 마지막 정상 스냅샷과 실제 종료 시각을 보존한다고 설명한다.
3. 민준이 명시적으로 확인하면 계획은 종료되고 핵심 입력과 조정 이력은 읽기 전용으로 남는다.
4. 자연 만료된 계획의 완료 결과는 종료 후 첫 정상 동기화를 기다리며, 그 관측값의 실제 시각과 지연을 표시한다.
5. **핵심 결과:** 민준은 종료 당시 기록, 완료 비교, 종료 뒤 현재가치를 서로 분리된 구획에서 보고 과거 결과가 이후 동기화로 바뀌지 않음을 확인한다.
6. 새 계획을 만들면 생성 직전 새 정상 스냅샷이 새 시작값이 되고 과거 조정 이력은 이전되지 않는다.

실패 경로: 종료 저장이 실패하면 활성 계획을 유지한다. 종료 후 정상 관측값이 없으면 추정하지 않고 동기화를 요청한다. 관측 지연이 24시간을 넘거나 종료~관측 사이 자금흐름이 있으면 완료 비교는 이유와 함께 `계산 불가`로 둔다.

### Flow 5 — 운영자 지은이 문제 범위를 정지하고 검증 후 복구한다.

1. 운영자 지은은 강한 신호 경보와 자동 정지 범위를 운영자 제어·감사에서 확인한다.
2. 영향이 개별 계획인지 계산 버전인지 공통 연결/동기화 문제인지 근거를 검토한다.
3. 필요한 범위만 선택하고 사유를 입력한 뒤 정지를 확인한다. 사용자 표면에는 같은 범위의 `service-notice`가 나타난다.
4. 지은은 검증 증거와 복구 조건을 기록하며, 시스템은 자동 복구하지 않는다.
5. **핵심 결과:** 수동 복구 확인 뒤 선택한 범위만 재개되고 수행자·원인·시작·종료 시각·영향 범위가 감사 기록에 남아 사용자에게는 검증 완료 상태가 일관되게 반영된다.

실패 경로: 범위를 확정할 수 없으면 신규 연결과 동기화를 전역 정지한다. 권한 부족, 기록 저장 실패, 복구 조건 미충족이면 정지 상태를 유지하고 재시도를 감사한다.

### Flow 6 — 민준이 Bybit 연결을 해제하고 기록을 보존한다.

1. 민준은 연결·개인정보 설정에서 현재 연결 상태와 원문 자격정보가 다시 표시되지 않는 것을 확인한다.
2. `연결 해제`를 선택하면 확인 화면이 “자격정보는 즉시 삭제되고 이후 동기화는 중단되지만 계획·조정 이력·완료 결과는 계정 삭제 전까지 읽기 전용으로 남는다”고 설명한다.
3. 민준이 명시적으로 확인한다.
4. **핵심 결과:** 연결 상태는 `해제됨`으로 바뀌고 동기화 조작은 사라지며, 과거 계획과 근거는 읽기 전용으로 계속 열려 데이터 경계와 보존 범위를 확인할 수 있다.

실패 경로: 해제 요청이 실패하면 기존 연결 상태를 바꾸지 않고 실패를 알린다. 계정 삭제를 원하면 별도 더 강한 확인과 법률상 보존 범위 고지를 거친다.

### Flow 7 — 민준이 계정과 개인정보를 삭제한다.

1. 민준은 연결·개인정보 설정에서 `계정 삭제`를 선택한다.
2. 계정 삭제 화면은 자격정보, 계획, 외부 자금흐름, 스냅샷, 계산 버전 등 삭제 대상을 열거하고, 법률상 남는 감사 기록이 있다면 범위·기간·목적을 별도로 보여준다.
3. 민준은 대상명을 재입력하고 삭제를 명시적으로 확인한다.
4. 진행 중에는 중복 요청과 민감 표면 접근을 막고, 삭제 상태를 사실대로 표시한다.
5. **핵심 결과:** 삭제가 완료되면 세션이 종료되고 완료 확인만 표시되며 이전 URL·뒤로 가기·다른 계정 로그인으로 삭제된 금융 화면을 다시 열 수 없다.

실패 경로: 일부 삭제가 실패하면 완료로 표시하지 않는다. 삭제되지 않은 범위와 재시도 경로를 알리고 자동 재시도하지 않는다. 최소 법정 기록의 정확한 대상·기간·목적이 출시 전 확정되지 않았으면 삭제 실행을 열지 않고 정책 확정을 출시 차단 상태로 유지한다. 백업은 계정 삭제 후 최대 30일 내 파기한다.

### Flow 8 — 민준이 바뀐 계산값의 근거를 확인한다.

1. 민준은 대시보드에서 이전 방문과 값이 달라진 것을 보고 `계산 근거 보기`를 선택한다.
2. 계산 근거 화면은 현재 카드 묶음의 스냅샷 ID, 공통 기준시점, 측정 시각, 계산 버전과 조정 이력 버전을 보여준다.
3. 민준은 변경된 버전을 열어 원인 사건, 발견·반영 시각, 영향 시작점과 지표, 이전값→새값, 가격 출처·추정 상태를 확인한다.
4. **핵심 결과:** 민준은 과거 값이 조용히 덮인 것이 아니라 보존된 원 사건과 새 계산 버전 때문에 결정적으로 바뀌었음을 확인한다.

실패 경로: 근거 조회에 실패하면 대시보드 값을 바꾸지 않고 현재 스냅샷 ID와 계산 버전을 유지한다. 격리된 버전은 숨기지 않고 읽기 전용 사유와 함께 표시한다.

### Flow 9 — 민준이 네이버로 가입하고 Google을 복구 수단으로 연결한다.

1. 민준은 첫 방문 인증 화면에서 세 제공자와 “본인 확인에만 사용하며 Bybit·금융·계획 데이터는 공유하지 않습니다”라는 경계 설명을 확인한다.
2. `네이버로 계속하기`를 선택해 네이버 동의 화면으로 이동하고 최소 로그인 정보 제공에 동의한다.
3. BokriLog는 검증된 콜백 뒤 새 세션을 만들고 첫 가입임을 판정해 온보딩으로 이동한다. 비밀번호를 만들거나 같은 정보를 다시 입력하게 하지 않는다.
4. 연결과 계획 생성 후 민준은 설정의 `로그인 수단`에서 네이버가 연결됨을 확인하고 `다른 로그인 수단 연결`을 선택한다.
5. 민준은 네이버로 최근 인증을 증명한 뒤 Google 인증을 완료한다. 두 제공자 인증이 모두 확인되기 전에는 계정 연결 상태를 바꾸지 않는다.
6. **핵심 결과:** 로그인 수단 목록에 네이버와 Google이 같은 BokriLog 계정의 독립 복구 수단으로 표시되고, 어떤 제공자에도 Bybit·금융·계획 데이터가 전달되지 않았다는 설명을 함께 확인한다.
7. 다음 방문에는 민준이 연결된 두 방법 중 하나로 같은 계획과 이력에 진입한다. Kakao도 동일한 규칙으로 연결할 수 있으며 마지막 로그인 수단은 해제할 수 없다.

실패 경로: 제공자에서 취소하거나 콜백 검증이 실패하면 계정·연결 상태를 바꾸지 않고 인증 화면으로 돌아온다. 새 제공자로 별도 계정을 만든 뒤 이미 연결된 Bybit UID를 입력하면 다른 계정이나 제공자명을 밝히지 않고 처음 사용한 방식으로 다시 로그인하도록 안내한다. 제공자 장애 시 연결된 다른 수단은 사용자가 직접 선택하며 자동 전환하지 않는다.
