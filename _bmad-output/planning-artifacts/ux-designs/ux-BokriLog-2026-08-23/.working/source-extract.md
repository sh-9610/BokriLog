# BokriLog UX source extraction

이 문서는 확정된 PRD와 addendum에서 UX 설계에 필요한 사실과 제약을 추출한 작업 자료다. `근거 기반 해석`으로 표시한 항목은 소스에서 도출한 UX 함의이며, 제품 결정 자체가 아니다.

## 1. 제품 계약과 범위

- 제품: 복리 목표를 세우고 Bybit Unified Trading Account(UTA)를 운용하는 개인 투자자를 위한 **읽기 전용 한국어 반응형 웹 서비스**.
- 핵심 가치: 최초 복리 계획과 외부 자금흐름 조정 이력을 보존하고, Bybit UTA 공식 USD 환산 계정가치 `totalEquity`를 계획선과 비교한다.
- MVP 단위: 사용자 계정 1개당 읽기 전용 Bybit UTA 연결 최대 1개, 활성 계획 최대 1개.
- 핵심 결과: 현재가치, 현재 시점 계획금액, 계획 대비 차이, 조정 최종 목표, 남은 필요 등가수익률, 목표 수익 달성도.
- 신뢰 계약: 신선도, 입력 신뢰도, 계산 성격을 서로 독립적으로 보여준다. 불완전한 입력이나 부분 동기화는 공식 결과로 승격하지 않는다.
- 수익화: 무료 공개 베타. 수동 동기화 성공 시 사용자가 닫을 수 있는 문맥형 전면광고 노출을 시도하며, 광고 실패·미채움·차단·동의 거부는 결과 조회를 막지 않는다.
- 비목표: 거래 실행·주문·출금·이체·자동매매·투자 추천, 다중 거래소/UTA/활성 계획, 범용 포트폴리오 및 종목·전략별 공식 성과 분석, 세금·위험·벤치마크·자산배분 분석, 정확한 TWR/TTWROR/MWR/XIRR/연환산 투자성과, 24시간 백그라운드 수집·상시 알림, 광고 시청 강제 또는 보상.
- Later 후보는 MVP 요구사항이 아니다: 대시보드가 열린 동안의 준실시간 추정값, 옵트인 중립 보조 통계, 공식 투자성과 지표, 다중 거래소 및 분석 확장.

## 2. 명명된 사용자·행위자

- **민준**: Bybit UTA에서 현물과 USDT 무기한 계약을 운용하는 직장인 투자자. 매일 거래하기보다 복리 계획이 흐트러지지 않았는지 짧게 확인한다. PRD의 세 핵심 여정 모두의 주인공.
- **인증된 사용자**: 자신의 사용자 계정에 속한 연결·계획·외부 자금흐름·스냅샷·계산 결과만 조회·변경하는 행위자.
- **운영자**: 문제의 영향 범위에 따라 계획·계산 버전·연결·동기화를 격리하고, 신규 연결·동기화·계산 표시를 정지·수동 복구하는 행위자.
- **제품·보안·계산 SPEC·개인정보·운영 책임자**: PRD §12 미결정 사항의 책임자로만 명명되며 일반 사용자용 화면 행위자로 정의되지는 않는다.
- MVP 대상: 복리 목표를 직접 설정하고 Bybit UTA에서 현물 또는 USDT 무기한 계약 등을 운용하는 개인 투자자; 현재 잔액보다 최초 계획과 자금흐름 조정 이력을 기준으로 진행 상황을 보려는 사람; 읽기 전용 API 키 연결과 수학적 계획 비교를 이해하거나 안내를 통해 수행할 수 있는 사람.
- MVP 비사용자: 다중 거래소·다중 포트폴리오 분석 수요자, 코인·상품·전략별 공식 성과/세금/위험지표/벤치마크 분석 수요자, 거래·출금·이체·자동매매·투자 추천 수요자.

## 3. 명명된 사용자 여정 — 원문

### UJ-1. 민준이 출근 전 계획 진행 상황을 확인한다.

- **사용자와 상황:** 민준은 Bybit UTA에서 현물과 USDT 무기한 계약을 운용하는 직장인 투자자다. 매일 거래하기보다 복리 계획이 흐트러지지 않았는지 짧게 확인하려 한다.
- **진입 상태:** 민준은 이미 사용자 계정에 로그인했고, 읽기 전용 Bybit UTA 연결과 활성 계획이 있다. 모바일 웹 대시보드를 연다.
- **경로:** 대시보드는 마지막 정상 현재가치와 측정 시각, 신선도·입력 신뢰도·계산 성격을 먼저 보여준다. 민준은 최신 값을 확인하려고 `수동 동기화`를 누른다. 동기화가 정상 완료되면 닫기 가능한 전면광고가 노출되고, 민준은 광고를 닫는다. 대시보드는 동일한 최신 스냅샷을 기준으로 현재가치, 현재 시점 계획금액, 계획 대비 차이, 조정 최종 목표, 남은 필요 등가수익률, 목표 수익 달성도를 갱신한다.
- **가치 실현:** 민준은 계획보다 앞섰는지 또는 뒤졌는지와 남은 기간에 필요한 주기별 등가수익률을 한 화면에서 파악한다. 제품은 매수·매도 행동을 권하지 않는다.
- **종료 상태:** 민준은 추가 계산이나 엑셀 수정 없이 화면을 닫는다. 최초 계획과 조정 이력은 그대로 보존된다.
- **예외:** 동기화에 실패하면 광고가 결과 조회를 막지 않는다. 마지막 정상값과 실패 상태, 마지막 정상 측정 시각을 보여주며 새 값을 공식 계산으로 승격하지 않는다.

### UJ-2. 민준이 처음으로 읽기 전용 연결과 계획을 만든다.

민준은 읽기 전용 Bybit API 자격정보를 입력한다. 시스템이 권한·UTA·UID·IP 상태와 실제 조회 성공을 검증한 후 첫 정상 `totalEquity`를 시작금액으로 고정한다. 민준은 기간·복리 주기·주기별 목표율을 입력하고 활성 계획을 생성한다. 쓰기 권한 키라면 저장 전에 해당 연결 시도만 거부된다.

### UJ-3. 민준이 신뢰할 수 없는 자금흐름 때문에 계산이 보류된 이유를 이해한다.

동기화 중 미분류 사건이나 비-USDT 환산가 결측이 발견되면 시스템은 공식 계산을 갱신하지 않는다. 민준은 마지막 정상값과 `검토 필요` 상태, 보류 이유를 확인한다. 원인이 해소되고 완전한 동기화가 성공한 뒤에만 이후 계획선과 파생지표가 재계산된다.

## 5. 기능 요구사항 — 명칭과 본문 원문

아래 FR 제목과 요구 문장은 PRD 원문이다. 상세 검증 결과까지 UX에 직접 영향을 주는 조건은 이어지는 §6~§9에 보존했다.

### FR-1: 사용자 데이터 경계

인증된 사용자는 자신의 사용자 계정에 속한 Bybit 연결, 계획, 외부 자금흐름, 스냅샷과 계산 결과만 조회·변경할 수 있다.

### FR-2: 읽기 전용 연결 검증

사용자는 API Key와 API Secret을 제출해 Bybit 연결을 만들 수 있다. 시스템은 저장 전에 `readOnly=1`, 지원 UTA, UID·IP 상태와 실제 지갑 조회 성공을 검증한다. UJ-2를 실현한다.

### FR-3: 자격정보 보호와 연결 해제

시스템은 Bybit 자격정보를 전송·저장 과정에서 보호하고 화면·로그·분석·광고 도구에 노출하지 않는다.

### FR-4: 최초 계획 생성

정상 Bybit 연결을 완료한 사용자는 첫 정상 현재가치를 시작금액으로 사용해 종료 시각, 복리 주기, 목표 주기율을 입력하고 계획을 생성할 수 있다. UJ-2를 실현한다.

### FR-5: 계획 불변성과 교체

시스템은 활성 계획의 시작금액·시작 시각·종료 시각·복리 주기·목표 주기율과 이후 조정 이력을 보존한다.

### FR-6: 사용자 시점 동기화

시스템은 대시보드 진입, 탭 재활성화, 사용자의 수동 동기화에서 Bybit 데이터를 동기화한다. UJ-1을 실현한다.

### FR-7: 원자적 스냅샷과 실패 저하

시스템은 필요한 API 구간과 페이지가 모두 검증된 경우에만 새 스냅샷과 공식 계산을 원자적으로 확정한다.

### FR-8: UTA 경계 외부 자금흐름 판정

시스템은 UTA 경계를 실제로 넘은 것으로 확인된 사건만 외부 자금흐름으로 분류한다.

### FR-9: 멱등한 조정 이력과 재계산

시스템은 확인된 외부 자금흐름의 원 사건과 USD 가치, 분류 근거, 반영 시각을 보존하고 계획 계산에 한 번만 반영한다.

### FR-10: 비-USDT 자금흐름 환산

시스템은 비-USDT 외부 자금흐름을 사건 시점의 USD 가치로 환산하고 환산 근거와 추정 여부를 보존한다.

### FR-11: 핵심 계획 지표 표시

사용자는 하나의 대시보드에서 현재가치, 현재 시점 계획금액, 계획 대비 차이, 조정 최종 목표, 남은 필요 등가수익률, 목표 수익 달성도를 확인할 수 있다. UJ-1을 실현한다.

### FR-12: 독립적인 신뢰 상태

사용자는 각 표시 결과가 어떤 근거를 갖는지 판단할 수 있도록 신선도·입력 신뢰도·계산 성격을 독립적으로 확인할 수 있다. UJ-3을 실현한다.

### FR-13: 계획 완료 결과

사용자는 계획 종료 이후 완료 결과와 종료 후 현재가치를 구분해 볼 수 있다.

### FR-14: 수동 동기화 광고 노출 시도

사용자가 수동 동기화로 최신 현재가치를 조회할 때 시스템은 동기화 성공 후 전면광고 노출을 시도하고, 사용자가 광고를 닫은 뒤 갱신된 결과를 표시한다. UJ-1을 실현한다.

### FR-15: 광고 실패와 개인정보 경계

광고 상태는 동기화와 결과 조회의 성공 조건이 아니다.

### FR-16: 범위별 격리

운영자는 입력 문제·계산 문제·공통 장애의 영향 범위에 따라 계획, 계산 버전, 연결 또는 동기화를 격리할 수 있다.

### FR-17: 자동·수동 정지와 복구

시스템과 운영자는 중대 신호 발생 시 연결, 동기화, 계산 표시를 독립적으로 중단하고 수동 검증 뒤 복구할 수 있다.

### FR 검증 가능한 결과 — 원문

**FR-1**

- 모든 서버 요청에서 사용자 소유권을 검증한다.
- 다른 사용자 식별자를 조작한 요청은 데이터 존재 여부를 노출하지 않고 거부한다.
- 사용자 계정당 Bybit 연결은 최대 1개다.

**FR-2**

- 쓰기 권한 키는 저장하지 않고 해당 연결 시도만 거부한다.
- 형식 오류, 만료·폐기, UID 불일치, IP 제한 불일치, 미지원 UTA와 조회 실패를 구분 가능한 오류로 표시한다.
- 연결 성공은 모든 검증 조건을 충족한 경우에만 기록한다.

**FR-3**

- API Key와 API Secret은 저장 시 암호화하고 화면에는 원문을 다시 표시하지 않는다.
- 연결 해제 즉시 저장된 자격정보를 삭제하고 이후 동기화를 차단한다.
- 연결 해제 후 계획·외부 자금흐름·완료 결과는 사용자 계정 삭제 전까지 읽기 전용으로 보존한다.

**FR-4**

- 최초 계획의 시작금액과 시작 시각은 첫 정상 연결 스냅샷에서 자동 확정되며 사용자가 덮어쓰지 못한다.
- 후속 계획은 생성 직전 새 정상 동기화를 요구하며, 해당 최신 스냅샷의 현재가치와 측정 시각을 새 `P0`, `t0`로 고정한다.
- 입력 신뢰도가 `확인됨`이 아니거나 최신 정상 동기화가 없거나 현재가치가 0 이하이면 새 계획 생성을 차단한다.
- 종료 시각은 시작 시각보다 뒤여야 하고 목표 주기율은 유한한 0 이상의 십진수여야 한다.
- 계획 기간은 1일 이상 1년 이하로 제한한다.
- 사용자 계정당 활성 계획은 최대 1개다.

**FR-5**

- 활성 계획의 핵심 입력은 수정할 수 없다.
- 사용자가 조건을 바꾸려면 기존 계획을 명시적으로 종료하고 새 계획을 생성한다.
- 사용자가 종료 시각 전에 계획을 끝내면 `중도 종료`로 기록하고, 종료 당시 마지막 정상 스냅샷과 실제 종료 시각을 보존한다.
- `중도 종료 결과`는 예정 종료 시각에 도달한 `완료 결과`와 구분하며 계획 성공·실패로 자동 판정하지 않는다.
- 기존 계획에서 새 계획으로 과거 조정 이력을 자동 복원하거나 이전하지 않는다.

**FR-6**

- 24시간 백그라운드 수집이나 상시 폴링을 수행하지 않는다.
- 동시에 발생한 중복 동기화는 하나의 실행으로 합치거나 멱등하게 처리한다.
- 동기화 시작·진행·성공·실패 상태와 마지막 정상 측정 시각을 보여준다.

**FR-7**

- 일부 API 요청이나 페이지 처리만 성공하면 부분 결과를 공식 상태로 승격하지 않는다.
- 현재가치와 외부 자금흐름 이력에는 공통 기준시점 `tc`를 적용한다. 사건 이력은 `tc`까지 모든 페이지와 구간이 완전해야 한다. 또한 사건 이력의 기준시점과 현재가치 측정 시각 사이에 미분류 사건이 없는지 중첩 재조회로 검증한다.
- Bybit API가 공통 기준시점과 이력 완전성을 입증하지 못하면 스냅샷을 공식 상태로 승격하지 않고 입력 신뢰도를 `검토 필요`로 둔다.
- 실패 시 마지막 정상 스냅샷을 유지하고 신선도를 `최신 아님`으로 표시한다.
- 키 오류나 API 실패를 현재가치 `0`으로 기록하지 않는다.
- 동일 스냅샷의 모든 대시보드 지표는 같은 입력·측정 시각·계산 버전을 사용한다.

**FR-8**

- Bybit 응답의 `cashFlow` 값이 0이 아니라는 이유만으로 외부 자금흐름으로 분류하지 않는다.
- 지원하는 명시적 사건 유형과 경계 판정 규칙만 허용한다.
- 계정 내부 손익, 가격변화, 미실현손익, 펀딩비, 수수료, 이자, 리베이트는 외부 자금흐름에서 제외한다.
- 미인식 유형, 이력 구간 공백, 페이지 미완료 또는 중복 의심은 입력 신뢰도를 `검토 필요`로 전환하고 공식 계산 갱신을 보류한다.

**FR-9**

- 동일한 거래소 사건 ID는 재조회나 페이지 중첩에도 한 번만 반영한다.
- 늦게 발견된 과거 사건은 사건 시점 이후의 계획선과 모든 파생지표를 결정적으로 재계산한다.
- 출금 때문에 조정 최종 목표가 0 이하가 되면 계획을 `검토 필요`로 전환한다.
- 원 사건을 삭제하거나 덮어써서 과거 계산 근거를 소실하지 않는다.

**FR-10**

- 원자산 코드·수량·사건 시각·USD 환산가·가격 출처·추정 여부를 함께 기록한다.
- MVP는 Bybit가 공식 API로 사건시각 USD 가격을 검증 가능하게 제공하는 자산만 자동 환산한다. 제3자 가격 공급자, 수동 가격 입력과 무제한 자산 가격 통합은 포함하지 않는다.
- 사건 시점 가격이 없으면 현재 가격으로 확정하지 않고 공식 계산 갱신을 보류한다.
- 추정 환산가가 사용된 계산은 계산 성격을 `추정`으로 표시한다.
- 더 나은 환산가가 확보되면 계산 버전과 변경 이력을 남기고 이후 값을 재계산한다.

**FR-11**

- 모든 지표는 §4의 정의와 동일한 스냅샷·계산 버전으로 산출한다.
- 각 비율에는 지표명, 대상 복리 주기와 기준 시각을 표시한다.
- 음수와 100% 초과 결과를 임의로 제한하지 않는다.
- 계산 불가 값을 `0` 또는 `0%`로 표시하지 않고 이유를 함께 보여준다.
- 투자 행동을 추천하거나 특정 수익률 달성을 유도하는 문구를 사용하지 않는다.

**FR-12**

- 신선도는 최소 `최신`, `동기화 중`, `최신 아님`을 구분한다.
- 입력 신뢰도는 최소 `확인됨`, `검토 필요`, `사용 불가`를 구분한다.
- 계산 성격은 최소 `공식`, `추정`, `계산 불가`를 구분한다.
- 추정 외부 자금흐름이 포함되면 현재가치 자체는 `공식`을 유지하되, 해당 흐름에 의존하는 현재 시점 계획금액·계획 대비 차이·조정 최종 목표·남은 필요 등가수익률·목표 수익 달성도는 모두 `추정`으로 전파한다.
- 하나의 상태가 다른 상태를 암묵적으로 덮어쓰지 않는다.
- 상태마다 원인, 마지막 정상 시각과 사용자가 취할 수 있는 다음 행동을 설명한다.

**FR-13**

- 종료 시점 이후 최초 정상 스냅샷을 첫 종료 후 관측값으로 확정하고 실제 측정 시각과 지연을 표시한다.
- 종료 시점 이후 정상 스냅샷이 없으면 완료 결과를 추정하지 않고 동기화 필요 상태를 표시한다.
- 첫 종료 후 관측값이 종료 시점으로부터 24시간을 초과하면 완료 비교를 계산 불가로 표시한다.
- 종료 시점과 첫 종료 후 관측값 사이 외부 자금흐름이 있으면 완료 비교를 계산 불가로 표시한다.
- 완료 뒤 동기화한 현재가치는 완료 결과를 변경하지 않는다.
- 사용자가 예정 종료 전에 끝낸 계획은 `중도 종료`로 표시하고 자연 만료된 계획의 완료 결과와 섞지 않는다.

**FR-14**

- 전면광고는 사용자가 별도 보상 조건 없이 닫을 수 있다.
- 매 수동 동기화 성공 시 광고 노출을 요청하되 실제 노출은 광고 공급자의 채움·동의·빈도 제한을 따른다.
- 광고는 공급자가 공식 지원하는 사용자 행동 또는 결과 화면 전환 트리거로만 요청한다. 수동 동기화 버튼을 지원하지 않는 공급자에서 임의 팝업·페이지 새로고침으로 트리거를 모방하지 않는다.
- 전면광고는 금융값·계획값·신뢰 상태를 DOM, URL, 페이지 제목에 포함하지 않는 중립적인 결과 전환 화면에서 요청한다. 광고가 종료되면 별도 결과 화면에 최신 스냅샷을 표시한다.
- 대시보드 자동 진입 동기화와 탭 재활성화 동기화는 전면광고를 유발하지 않는다.
- 광고를 계산 카드, 신뢰 상태 또는 동기화 조작으로 오인하게 만들지 않는다.

**FR-15**

- 광고 미채움, 차단, 로드 오류, 사용자 동의 거부 또는 광고 공급자 장애 시 광고 없이 갱신 결과를 표시한다.
- 광고 대기·닫기·실패 때문에 정상 동기화 결과가 유실되거나 다시 계산되지 않는다.
- API 자격정보, UTA 현재가치, 계획값, 수익률, 외부 자금흐름과 신뢰 상태를 광고 타기팅 또는 광고망 요청에 포함하지 않는다.
- MVP 광고는 화면·페이지의 일반 문맥만 사용하는 문맥형 광고로 한정하고, 개인 맞춤형·행태 기반 광고를 사용하지 않는다.
- 광고망에 전달되는 IP, 사용자 에이전트, 쿠키·로컬 저장소, URL, 페이지 제목, 동의 상태와 공급자 식별자를 데이터 흐름표로 관리한다. URL·페이지 제목·광고 슬롯명에는 금융값이나 사용자 식별자를 포함하지 않는다.
- 제3자 광고 요청 전 필요한 동의를 받고 비개인화 모드를 적용한다. 출시 전 실제 네트워크 요청을 검사해 허용된 필드 이외의 금융·계획·사용자 데이터가 전달되지 않는지 검증한다.
- 광고 공급자가 대시보드 본문 또는 DOM을 문맥 분석해야만 동작한다면 해당 공급자를 사용하지 않는다.
- 광고 기능을 전역 비활성화해도 핵심 제품 기능이 정상 동작한다.

**FR-16**

- 개별 입력 문제는 해당 계획만 공식 갱신에서 제외한다.
- 공통 계산 문제는 해당 계산 버전의 결과 표시를 중단한다.
- 공통 원인이거나 영향 범위를 특정할 수 없으면 신규 연결과 동기화를 전역 중단한다.
- 쓰기 권한 키 입력은 전역 중단이 아니라 해당 연결 시도만 거부한다.

**FR-17**

- 정의된 강한 신호를 탐지한 후 60초 이내 자동 정지한다.
- 운영자는 5분 이내 신규 연결과 동기화를 전역 정지할 수 있다.
- 정지 원인, 시작·종료 시각, 영향 범위, 수행자를 감사 기록으로 남긴다.
- 자동 복구하지 않고 검증된 복구 조건을 충족한 뒤 수동으로 재개한다.

## 6. 비기능 요구사항 — 원문

### 계산 정확성과 재현성

- **NFR-1:** 동일한 원 입력·스냅샷·계산 버전은 언제나 동일한 결과를 생성해야 한다.
- **NFR-2:** 모든 공식 지표는 스냅샷 ID, 계산 버전, 기준 시각과 외부 자금흐름 이력으로 재현 가능해야 한다.
- **NFR-3:** 정상, 0·음수, 소액·대규모, 동일 시각 다중 사건, 지연 사건, 중복 사건, 비-USDT 결측, 계획 종료를 포함한 고정 계산 예제의 배포 전 회귀 통과율은 100%여야 한다.
- **NFR-4:** 금액과 비율은 정확한 십진수로 계산하고 표시 단계에서 한 번만 반올림해야 한다.
- **NFR-5:** 중대 계산 오류는 공개 베타 기간 0건이어야 한다.

### 보안과 개인정보

- **NFR-6:** 읽기 전용 검증은 모든 연결 시도에서 실행되어야 하며 실행률은 100%여야 한다.
- **NFR-7:** 자격정보는 전송 중 보호하고 저장 시 암호화하며 암호화 키와 데이터 접근 권한을 분리해야 한다.
- **NFR-8:** 자격정보·세션 비밀·금융 상세값은 화면, 로그, 오류 추적, 분석과 광고 도구에 기록하지 않아야 한다.
- **NFR-9:** 모든 데이터 요청은 서버에서 사용자 소유권을 검증하며 교차 사용자 접근 허용은 0건이어야 한다.
- **NFR-10:** 계정 삭제 시 사용자 데이터와 자격정보를 삭제할 수 있어야 한다. 법률상 보존이 필요한 감사 기록이 있다면 범위와 기간을 별도로 고지해야 한다.
- **NFR-11:** 공개 베타 전 법률·개인정보 검토를 완료하고, 광고 또는 데이터 흐름이 바뀌면 재검토해야 한다.

### 신뢰성·성능·사용성

- **NFR-12:** 동기화 성공률은 전체 유효 동기화 시도 중 95% 이상이어야 한다. 성공은 필수 API 구간·페이지 검증과 원자적 스냅샷 확정을 모두 완료한 경우다. 사용자 취소와 중복 억제 요청은 분모에서 제외하고 Bybit 오류는 포함한다.
- **NFR-13:** 동기화 요청 후 1초 이내 진행 상태를 표시하고, 실패 또는 성공 시 기존 화면이 서로 다른 스냅샷의 값을 섞어 보여주지 않아야 한다.
- **NFR-14:** 일반 모바일·데스크톱 환경에서 핵심 화면은 75백분위 기준 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하를 목표로 한다. 외부 광고가 이 기준을 깨뜨리면 광고를 비활성화할 수 있어야 한다.
- **NFR-15:** 핵심 계산값·상태·동기화 조작은 키보드로 접근 가능하고 색상만으로 상태를 구분하지 않아야 한다.
- **NFR-16:** 광고의 닫기 조작은 명확하고 즉시 사용 가능해야 하며 동기화 조작과 충분히 분리돼야 한다.

### 운영성과 복구

- **NFR-17:** 신규 연결·동기화·계산 표시·광고를 독립적으로 정지할 수 있어야 한다.
- **NFR-18:** 베타 전 1회 이상 백업 복원 시험을 완료하고, 사용자 계정·계획·외부 자금흐름·스냅샷·계산 버전을 복원할 수 있어야 한다.
- **NFR-19:** 베타 전과 이후 월 1회 비상정지 훈련을 수행하며 성공률은 100%여야 한다.
- **NFR-20:** 안정화 후 운영 시간은 최근 4주 평균 주 2시간 이하여야 한다. 운영 시간에는 지원, 경보 확인, 정기 API·광고·개인정보 점검, 백업·정지 훈련, 예정 유지보수를 포함한다. 월 인프라 비용은 30,000원 이하여야 한다. 신규 기능 개발 시간과 실제 중대 사고 대응 시간은 별도로 기록한다.
- **NFR-21:** Bybit API 변경내역과 지원 사건 유형을 정기 재검증하며 미인식 유형은 기본 거부해야 한다.

## 7. 데이터·개인정보·금융 위험 제약

### 데이터와 계산 무결성

- 현재가치는 Bybit UTA `totalEquity`이며 다른 잔액 필드와 혼용하지 않는다.
- 모든 대시보드 지표는 하나의 원자적 스냅샷, 동일 입력·측정 시각·계산 버전을 사용해야 한다. 일부 구간/페이지 성공이나 공통 기준시점·이력 완전성 미입증은 공식 상태로 승격하지 않는다.
- API 실패·키 오류를 현재가치 `0`으로 기록하지 않는다. 마지막 정상 스냅샷을 유지하고 신선도를 `최신 아님`으로 둔다.
- `cashFlow != 0`만으로 외부 자금흐름을 분류하지 않는다. 검증된 사건 유형 허용목록과 실제 UTA 경계 판정을 모두 요구한다.
- 거래소 사건 ID를 멱등 키로 사용하고, 지연 사건은 사건 시점 이후 계획선·파생지표를 재계산하며 버전·근거를 보존한다.
- 비-USDT 흐름은 사건 시점 공식 USD 환산가를 요구한다. 결측 시 현재가로 대체하지 않고 공식 계산을 보류한다. 추정 사용 시 의존 지표 전체에 `추정` 성격이 전파된다.
- 금액·비율·API 십진수 문자열은 이진 부동소수점이 아닌 정확한 십진수로 계산하며 화면 표시에서만 둘째 자리 반올림하고 `-0.00`은 `0.00`으로 표시한다.
- 남은 필요 등가수익률은 투자 추천이나 투자성과 수익률이 아니며, 음수 또는 100% 초과 값을 임의 제한하지 않는다. 정의되지 않은 값은 `0`으로 대체하지 않고 이유와 함께 `계산 불가`로 표시한다.
- 종료 결과는 종료 후 최초 정상 관측값의 실제 측정 시각과 지연을 표시한다. 24시간 초과 또는 종료~관측 사이 외부 자금흐름 존재 시 완료 비교는 계산 불가다. 완료 뒤 현재가치는 완료 결과와 분리한다.

### 자격정보와 사용자 경계

- 모든 서버 요청에서 사용자 소유권을 검증하고 타 사용자의 데이터 존재 여부도 노출하지 않는다.
- API Key/Secret은 저장 전 읽기 전용, 지원 UTA, UID·IP 상태, 실제 지갑 조회 성공을 검증한다. 쓰기 권한 키는 저장하지 않고 해당 시도만 거부한다.
- 자격정보는 전송 중 보호·저장 시 암호화하고 원문을 다시 표시하지 않는다. 화면·로그·분석·오류 추적·광고 도구에 노출하지 않는다.
- 연결 해제 즉시 자격정보를 삭제하고 동기화를 차단한다. 계획·외부 자금흐름·완료 결과는 계정 삭제 전까지 읽기 전용으로 보존한다.
- 계정 삭제 시 사용자 데이터와 자격정보를 삭제할 수 있어야 하며 법률상 보존 감사기록의 범위·기간은 별도 고지한다.

### 광고·제3자 데이터 경계

- 광고는 금융값·계획값·수익률·자금흐름·신뢰 상태를 DOM, URL, 페이지 제목, 슬롯명 또는 타기팅/네트워크 요청에 포함하지 않는 중립 결과 전환 화면에서만 요청한다.
- 개인 맞춤형·행태 기반 광고가 아닌 일반 화면 문맥만 쓰는 문맥형 광고이며, 제3자 요청 전에 필요한 동의와 비개인화 모드를 적용한다.
- IP, 사용자 에이전트, 쿠키·로컬 저장소, URL, 페이지 제목, 동의 상태, 공급자 식별자를 데이터 흐름표로 관리하고 실제 요청을 검사한다.
- 공급자가 대시보드 본문/DOM을 문맥 분석해야만 동작하면 사용하지 않는다. 광고 기능을 전역 비활성화해도 핵심 기능은 정상 동작해야 한다.

### 운영 위험

- 개별 입력 문제는 해당 계획, 공통 계산 문제는 해당 계산 버전, 공통 원인/불명 범위는 신규 연결·동기화를 격리한다.
- 강한 신호 탐지 후 60초 이내 자동 정지, 운영자는 5분 이내 전역 정지 가능. 자동 복구 없이 수동 검증 후 재개하며 원인·시각·범위·수행자를 감사 기록으로 남긴다.
- 읽기 전용 검증과 배포별 보안·계산 회귀는 100%, 베타 중 중대 보안 사고·자격정보 노출·쓰기 권한 키 수용·교차 접근·중대 계산 오류는 각 0건 목표다.

## 8. 플랫폼·폼팩터·UI 시스템 단서

- 명시된 표면은 **한국어 반응형 웹**이며 일반 모바일·데스크톱 환경을 모두 지원한다. UJ-1의 대표 진입은 **모바일 웹 대시보드**다.
- 핵심 화면 성능 목표: p75 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하. 광고가 목표를 깨면 비활성화 가능해야 한다.
- 키보드 접근을 지원하고 색상만으로 상태를 구분하면 안 된다.
- 동기화 요청 후 1초 이내 진행 상태를 표시한다.
- 명시된 UI 프레임워크/디자인 시스템/컴포넌트 라이브러리는 없다.
- 네이티브 앱, 오프라인 모드, 다크 모드, 푸시 알림, 멀티 디바이스 연속성에 대한 결정은 없다.

## 9. 기존 UX·시각 결정

### UX 결정

- 대시보드는 마지막 정상 현재가치와 측정 시각, 신선도·입력 신뢰도·계산 성격을 **먼저** 보여준다.
- 여섯 핵심 지표는 하나의 대시보드에서 확인하며, 비율에는 지표명·대상 복리 주기·기준 시각을 표시한다.
- 세 신뢰 축은 서로 덮어쓰지 않고 독립적으로 표시하며 각 상태에 원인, 마지막 정상 시각, 다음 행동을 설명한다.
- 동기화 시작·진행·성공·실패와 마지막 정상 측정 시각을 보여준다. 동시 중복 동기화는 합치거나 멱등하게 처리한다.
- 광고는 수동 동기화 성공 뒤, 결과 화면 전환 전에만 시도한다. 자동 진입/탭 재활성화 동기화는 광고를 유발하지 않는다. 닫기는 명확하고 즉시 사용 가능하며 동기화 조작과 충분히 분리한다.
- 계획 핵심 입력은 불변이며 조건 변경은 기존 계획의 명시적 종료와 새 계획 생성으로 처리한다. 중도 종료는 자연 만료 완료와 구분하고 성공·실패로 자동 판정하지 않는다.
- 오류 유형은 형식, 만료·폐기, UID, IP, 미지원 UTA, 조회 실패 등 구분 가능해야 한다.

### 시각 결정

- PRD는 색상, 서체, 라운딩, 간격, 아이콘, 로고, 이미지 스타일을 정하지 않았다.
- 상태를 색상만으로 구분하지 않는다는 접근성 제약만 명시한다.
- 광고는 계산 카드·신뢰 상태·동기화 조작으로 오인되지 않아야 한다.

## 11. 신뢰와 지속 이용 함의 — 근거 기반 해석

### 신뢰 형성

- **정확함보다 근거를 먼저 보이는 구조:** PRD가 세 신뢰 축과 마지막 정상 시각을 지표보다 먼저 요구하므로, 핵심 신뢰 신호는 장식이 아니라 정보 위계의 최상단이어야 한다.
- **오류 시 데이터 보존:** 실패를 0으로 바꾸지 않고 마지막 정상값을 유지하는 것은 사용자가 일시 장애와 자산 손실을 혼동하지 않게 하는 핵심 신뢰 장치다.
- **독립 상태 언어:** `최신`이 곧 `공식` 또는 `확인됨`을 뜻하지 않는다. 세 축을 합친 하나의 녹색/빨간 상태로 축약하면 FR-12를 훼손하고 오해율 역지표를 악화시킬 수 있다.
- **계산 근거 추적:** 스냅샷, 계산 버전, 기준 시각, 조정 이력으로 재현 가능하다는 요구는 결과 근거와 변화 사유로 내려갈 수 있는 UX를 시사한다.
- **비권고 언어:** 목표율·필요 등가수익률을 행동 촉구처럼 표현하면 제품 경계를 위반한다. 수치의 성격과 기준 주기를 인접하게 설명해야 한다.
- **보안 가시성:** 읽기 전용 검증, 비밀 원문 비재표시, 연결 해제 시 삭제를 사용자가 확인할 수 있어야 하지만 보안 구현 세부를 과장된 보증 문구로 바꾸면 안 된다.
- **광고와 금융 정보의 시각적·기술적 분리:** 광고가 상태/계산/동기화 조작처럼 보이지 않아야 하며, 금융 데이터가 없는 중립 전환 화면이어야 한다.

### 지속 이용

- **짧은 재방문 가치:** UJ-1은 출근 전 짧은 확인과 추가 계산 없이 종료를 핵심으로 한다. 재방문의 중심은 새로운 분석 기능이 아니라 빠른 상태 파악이다.
- **계획과 이력의 영속성:** 최초 계획과 조정 근거가 수정·유실되지 않는다는 확신이 장기 이용의 핵심이다. 계획 교체·중도 종료·연결 해제에서도 무엇이 유지되는지 명시해야 한다.
- **장애 후 복귀 가능성:** 보류 원인과 다음 행동을 제시하고 정상 동기화 성공 때만 공식 상태로 돌아가는 흐름은 막힌 경험을 회복 가능한 경험으로 만든다.
- **광고 피로 방어:** 광고는 자동 동기화에는 나타나지 않고, 수동 성공 뒤에도 실패/거부/미채움 시 결과를 막지 않는다. 광고 후 조회 포기율 15% 초과 시 재설계라는 역지표가 지속 이용의 명시적 가드레일이다.
- **과도한 활동 유도 금지:** 자동 새로고침, 강제 재시도, 보상형 동기화로 광고 노출을 늘리지 않는다는 SM-C3는 차분하고 통제감 있는 재방문 경험을 요구한다.

## 12. 계산·표시 경계 중 UX가 보존해야 할 사항

- 복리 주기는 일·주·월이며 `Asia/Seoul`의 시작 시각 고정 경계를 따른다. 화면의 `오늘`도 `Asia/Seoul` 기준이다.
- 시작금액/시각은 첫 정상 스냅샷에서 자동 확정되어 수정할 수 없다. 새 계획은 생성 직전 새 정상 동기화를 요구한다.
- 계획 기간은 1일 이상 1년 이하, 종료는 시작보다 뒤, 목표 주기율은 유한한 0 이상 십진수다.
- 현재가치가 0 이하이면 원 금액과 경고를 표시하되 계획 생성과 정의되지 않은 필요 수익률 계산을 제한한다.
- 목표 수익 달성도는 음수와 100% 초과를 허용하고, 목표 수익이 0 이하라면 이유와 함께 계산 불가다.
- 출금으로 조정 최종 목표가 0 이하이면 계획은 `검토 필요`가 되며 목표 기반 파생비율을 계산하지 않는다.
- 미래 자금흐름은 예측하지 않는다. 계획 종료 뒤 자금흐름은 완료 지표에 포함하지 않는다.

## 14. UX 명세에서 추가로 열어 둘 질문

아래는 PRD가 답하지 않은 항목이며 새 결정으로 간주하면 안 된다.

- 브랜드 성격과 시각 언어(색상, 서체, 형태, 일러스트레이션/데이터 시각화 방향)는 무엇인가?
- 사용자 계정 가입·로그인·비밀번호 회복·세션 만료 흐름은 무엇인가?
- Bybit API Key/Secret을 생성하는 외부 절차를 제품 안에서 어느 수준까지 안내하는가? IP 제한 설정과 Day 90 정책을 언제, 어떻게 설명하는가?
- 대시보드에서 상태 상세와 자금흐름 조정 이력을 인라인, 드릴다운, 별도 화면 중 어떻게 배치하는가?
- 여섯 핵심 지표의 우선순위와 모바일 한 화면에서의 접힘/스크롤 구조는 무엇인가?
- 공식/추정/계산 불가, 확인됨/검토 필요/사용 불가의 최종 한국어 마이크로카피와 아이콘·보조 설명은 무엇인가?
- 사용자가 직접 해결할 수 없는 `검토 필요` 사유의 지원·공지 경로는 무엇인가?
- 계획 종료 확인, 새 계획 생성, 연결 해제, 계정 삭제에서 필요한 재확인 강도와 복구 가능성은 무엇인가?
- 광고 동의 UI, 공급자, 빈도 제한, 공식 트리거, 중립 전환 화면의 내용과 광고 미노출 시 전환 속도는 무엇인가?
- 사용자-facing 상태와 운영자-facing 격리/정지 제어를 같은 앱에서 제공하는지 별도 운영 표면으로 두는가?
- 접근성 목표 수준(WCAG 버전/등급), 스크린리더 공지 방식, 포커스 이동, 동적 동기화 상태의 라이브 리전 정책은 무엇인가?
- 다크 모드, 오프라인/불안정 네트워크, 국제화, 모션 감소 설정의 MVP 범위는 무엇인가?

## 15. 성공·검증 관점에서의 UX 기준

- 활성화: 온보딩 시작자의 80% 이상이 읽기 전용 연결과 계획 생성을 완료해야 한다(SM-2).
- 반복 가치: 활성화 사용자의 50% 이상이 첫 28일 중 서로 다른 3개 주에 공식 또는 마지막 정상 스냅샷과 신뢰 상태가 보이는 정상 조회를 1회 이상 완료해야 한다(SM-3).
- 이해 가능성: 과업 평가 참가자의 80% 이상이 현재 시점 계획금액, 계획 대비 차이, 외부 자금흐름 조정, 세 신뢰 상태를 모두 올바르게 해석해야 한다(SM-5).
- 광고 후 조회 포기율이 15%를 넘으면 광고 빈도·시점을 재설계한다(SM-C1).
- `검토 필요` 또는 `계산 불가`를 공식 최신값으로 오해하는 비율이 20%를 넘으면 상태 표현을 재설계한다(SM-C2).
- 출시 전 오류·검토 필요·계산 불가 상태에 대한 사용자 이해 과업을 수행해야 한다.
