# BokriLog UX source reconciliation — PRD

이 문서는 확정 PRD와 addendum이 `DESIGN.md`와 `EXPERIENCE.md`에 어떻게 보존됐는지 기록한다. 제품 요구사항과 계산·구현 세부는 PRD/addendum을 따르고, UX 세부는 두 spine을 따른다. 시각 결과물·목업과 spine이 충돌하면 spine이 우선한다.

## UX spine에 의도적으로 중복하지 않은 제품 내용

다음 내용은 누락이 아니라 상위 문서 소유권을 유지한 것이다.

- 복리 공식, `periods(a,b)`의 달력·월말·윤년·부분 주기 규칙, 정확한 십진수 처리, 반올림 시점과 저장 정밀도는 계산 SPEC/PRD가 소유한다. UX는 부호·기준 주기·계산 버전·계산 불가 표현만 규정한다.
- Bybit 필드 매핑, `totalEquity`, `cashFlow` 오해 방지, 사건 유형 허용목록, 페이지 중첩·멱등 키·재조회 방식은 addendum과 후속 계산·아키텍처가 소유한다. UX는 검증 진행, 보류 원인, 이력 근거를 보여주는 책임만 갖는다.
- NFR의 백업 복원, 회귀 예제, 자동 정지 60초, 수동 정지 5분, 운영시간·인프라 비용과 Day 60 성공 지표는 운영·품질 계약이다. 사용자에게 보이는 제한·복구 상태와 이해도에 직접 필요한 부분만 UX로 투영했다.
- 광고 공급자 선정, 공식 트리거 지원 여부, 실제 네트워크 요청 데이터 흐름표와 법률·개인정보 검토는 제품·개인정보·구현 책임이다. UX는 무료·유광고 베타 결정에 따라 중립 전환, 비차단, 비개인화 경계, 닫기 행동과 실제 보조기술 승인 게이트를 규정한다.
- MVP 제외·Later 항목은 새 화면이나 숨은 준비 요구로 확장하지 않았다. 따라서 다중 거래소, 다중 계획, TWR/MWR/XIRR, 전략·위험·세금 분석, 준실시간 추정, 푸시 알림은 IA에 없다.
- PRD의 조사 링크와 외부 표준 원문은 UX spine에 복제하지 않았다. 필요 시 `sources`를 통해 원문을 추적한다.

## 정성적 아이디어 보존 및 제외

사용자가 제시한 “신용할 수 있고 지속적으로 이용할 수 있는 느낌”은 다음과 같이 보존됐다.

- 신뢰: 최신처럼 보이는 숫자보다 마지막 정상 측정 시각과 세 신뢰 축을 먼저 보여주고, 실패·추정·계산 불가를 숨기지 않는다.
- 지속 이용: 스트릭이나 알림 압박 대신 짧은 재방문, 변하지 않는 계획 기준선, 조정·계산 버전 이력, 장애 뒤 마지막 정상 상태로 복귀하는 경험을 사용한다.
- 정서: 수익을 과장하거나 손실을 겁주는 시각 언어를 피하고, 장시간 읽기 좋은 차분한 장부형 도구로 정의한다.

별도의 사용자 제공 시각 자료·브랜드 방향·경쟁 제품 영감은 없었으므로 조정 과정에서 버려진 정성 아이디어는 없다. MVP 시각 방향은 차분한 장부형 라이트 모드와 커스텀 토큰 시스템으로 확정됐고, 다크 모드는 후속 대비 검증 범위다.

## 충돌, 가정, 미결정 사항

초기 PRD 초안의 “광고 없이 출시” 기본값은 이후 결정으로 폐기됐다. 현재 PRD와 두 UX spine은 무료·유광고 베타로 일치하며, 광고 공급자·개인정보 흐름·실제 접근성 시험 미확정 시 출시를 차단한다. 그 밖에는 다음 상위 결정 또는 검증이 필요하다.

- 가입·인증·세션 회복은 Google·네이버·카카오 OIDC와 명시적 다중 로그인 수단 연결로 확정됐다.
- 지원 UTA 모드와 외부 자금흐름 사건 허용목록, 비-USDT 가격 출처·추정 조건, 십진수 저장 정밀도·반올림 모드는 계산 SPEC 전 확정이 필요하다.
- 광고 공급자, 공식 트리거, 동의 방식과 데이터 흐름은 구현 단계에서 확정하고 실제 광고 소재로 키보드·스크린리더 시험을 통과해야 한다. 빈도는 사용자당 30분 최대 1회, `Asia/Seoul` 하루 최대 3회로 확정됐다.
- 계정 삭제는 사용자·금융·계획 데이터를 삭제하고 최소 법정 보안·관리자 접속기록만 분리 보존하는 원칙과 백업 최대 30일 파기로 확정됐다. 정확한 법정 대상·근거·목적·기간은 출시 전 법률 검토로 확정해야 한다.
- 지원은 웹 문의 폼 또는 공개 이메일, 영업일 기준 3일 이내 답변 목표, 서비스 내부 장애·복구 공지로 확정됐다. 강한 신호 판정표와 중대 사고의 수동 운영 대응 시간대·당직 범위는 베타 전 운영·보안 검토가 필요하다.
- Day 90 시점에 남아 있는 IP 제한 없는 연결의 유지·유예·중단 정책은 미결정이다. 정책 확정 시 온보딩, 연결 검증, 설정, 서비스 공지의 카피와 상태를 갱신해야 한다.
- 커스텀 토큰 시스템, 라이트 모드, 차분한 기록 도구의 시각 언어가 MVP 계약이다. 후속 브랜드 시스템 또는 다크 모드를 추가하면 WCAG 대비와 상태 의미를 다시 검증해야 한다.
- `EXPERIENCE.md`의 온보딩 단계 저장과 계정 삭제 시 대상명 재입력은 안전한 UX 상세화지만 PRD의 필수 구현 문구는 아니다. 기술·보안 정책과 충돌하면 상위 정책에 맞춰 조정한다. MVP는 오프라인 금융값 표시와 지속 캐시를 제공하지 않는다.

## 결론

두 UX spine은 FR-1~FR-20과 UJ-1~UJ-3의 사용자 가시적 책임을 모두 표면·상태·흐름으로 연결했다. 계산·API·운영 구현 내용은 상위 소스에 남겨 중복과 불일치를 피했고, 신뢰와 지속 이용이라는 정성 목표도 구체적인 정보 위계·복구 행동·이력 보존·비게임화 원칙으로 보존됐다. 무료·유광고 베타, 세 소셜 로그인, 계정 삭제 원칙, 지원 채널과 라이트 모드는 확정됐으며, 남은 항목은 공급자 통합 승인, 정확한 법정 보존 범위, 계산·운영 정책이다.
