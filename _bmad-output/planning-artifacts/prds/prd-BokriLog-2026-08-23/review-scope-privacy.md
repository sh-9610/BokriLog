# BokriLog MVP PRD 검토 — 범위·광고·개인정보·운영 경계

## 검토 범위

- 대상: `prd.md`, `addendum.md`, `reconcile-brief.md`
- 관점: MVP/Later 경계, 숨은 범위 확대, 무료 베타와 문맥형 전면광고, 수동 동기화별 광고 요청, 광고 데이터 경계, Day 60/90 IP 제한, 1인 운영성과 비상정지
- 정책 확인 기준일: 2026-08-23
- 정책 근거: Google의 공식 AdSense/Publisher Tag 문서만 사용했다.

## 종합 판정

**조건부 불합격.** 무료 공개 베타, 문맥형 광고 한정, 금융정보의 광고망 전달 금지, Day 60/90 IP 제한 일정, 1인 운영비·시간, 비상정지 기준은 문서에 명시되어 있고 MVP/Later의 기능 경계도 대체로 선명하다. 그러나 출시 전 확정해야 할 높은 중요도 문제 3건이 남아 있다. 특히 현재 정의한 `수동 동기화 성공 후 매번 전면광고 요청`은 Google AdSense 비네트/GPT 관리형 웹 인터스티셜의 공식 트리거 모델과 그대로 맞지 않으며, `문맥형`이라는 표현만으로 광고망에 전달되는 개인정보·기술 데이터의 경계를 보장할 수 없다. 비-USDT 전 종목 환산도 지원 자산 경계가 없어 MVP 범위를 사실상 무제한으로 만들 수 있다.

## 높은 중요도

### H-1 — 수동 동기화 버튼을 광고 트리거로 삼는 요구가 후보 광고 제품과 호환된다는 근거가 없다

**근거**

- FR-14는 수동 동기화가 성공할 때마다 전면광고 노출을 요청하고, 닫은 뒤 결과를 표시하도록 요구한다.
- AdSense 비네트 광고는 공식적으로 페이지 로드 사이에서 나타나며 기본 트리거는 사이트 링크 클릭이다. 추가 트리거 목록에도 임의 버튼 클릭이나 비동기 작업 완료 콜백은 없다.
- Google Publisher Tag 관리형 웹 인터스티셜의 지원 사용자 행동은 앵커 클릭, 글 끝 도달, 비활성 후 상호작용, 브라우저 탐색바 클릭, 탭 복귀, GPT가 만든 계속 보기 버튼으로 한정된다. 공식 문서는 향후 동작이 추가될 수 있다고 명시하므로, 일반 `수동 동기화` 버튼 완료 이벤트를 지원한다고 가정할 수 없다.
- GPT 관리형 웹 인터스티셜은 기본 10분, 허용 최소 1분의 사용자별 빈도 제한을 가진다. 따라서 제품은 매 성공마다 요청을 시도할 수 있더라도 실제 노출을 매번 만들 수 없다.

**영향**

- 선정한 공급자가 이 트리거를 지원하지 않으면 FR-14를 만족시키기 위해 동기화를 링크 이동처럼 위장하거나 자체 팝업 광고를 조립하는 잘못된 구현으로 흐를 수 있다.
- 출시 직전 광고 공급자를 바꾸거나, 동기화·결과 공개 흐름을 다시 설계하거나, 수익화 요구를 축소해야 할 수 있다.

**권고**

- FR-14를 유지하려면 출시 게이트에 `동기화 완료라는 제품 이벤트를 정책상 허용된 트리거로 지원하는 공급자·상품의 서면/공식 문서 확인`을 통과 조건으로 둔다.
- 지원되지 않으면 광고 트리거를 공급자가 허용하는 페이지 전환으로 재정의하거나, MVP에서는 일반 비네트의 공급자 관리 트리거만 허용한다. 동기화 버튼을 앵커로 가장하는 식의 우회는 허용하지 않는다고 명시한다.
- 광고 요청과 실제 노출의 공급자 빈도 제한을 FR-14 인수조건과 테스트 예제로 고정한다.

공식 근거: [AdSense 비네트 광고](https://support.google.com/adsense/answer/16531962?hl=en), [Google Publisher Tag 웹 인터스티셜](https://developers.google.com/publisher-tag/samples/display-web-interstitial-ad)

### H-2 — `문맥형`·`금융정보 미전달`만으로 실제 광고 데이터 경계가 검증되지 않는다

**근거**

- FR-15는 개인 맞춤형·행태 기반 광고를 금지하고 일반 문맥만 사용하도록 하지만, 광고 공급자가 받는 IP 주소, 사용자 에이전트, 쿠키·로컬 스토리지 식별자, 전체 URL·리퍼러, 광고 측정 이벤트의 허용 여부와 보존 범위를 정의하지 않는다.
- Google 광고 요청은 기본적으로 개인 맞춤형이다. 비개인화 요청은 별도 설정이 필요하고, 비개인화 광고도 빈도 제한과 집계 보고를 위해 쿠키를 사용한다. 적용 지역에서는 그 목적에도 동의가 필요할 수 있다.
- Google의 문맥 타기팅은 페이지 내용을 분석한다. 대시보드에 광고 태그를 로드하면 제품이 요청 파라미터에 계정가치나 수익률을 직접 넣지 않더라도, 금융 화면의 URL·표시 문맥·DOM 접근을 통해 `금융정보를 광고망에 전달하지 않는다`는 요구와 충돌할 여지가 있다.

**영향**

- 제품 문구는 강한 프라이버시 약속을 하지만 구현·법률 검토자가 이를 객관적으로 시험할 기준이 없다.
- 단순히 `개인 맞춤 광고 끄기`만으로 PRD 준수를 선언하거나, 광고 SDK·측정 태그가 식별자와 금융 페이지 문맥을 보내는 상태로 출시할 수 있다.

**권고**

- 출시 게이트에서 공급자별 데이터 흐름표를 승인하도록 한다: 전송 필드, URL/리퍼러, 쿠키·로컬 스토리지, IP·기기 정보, 광고/분석 이벤트, 제3자 수신자, 보존 기간, 동의 거부 시 동작.
- 모든 지역에서 개인화를 명시적으로 비활성화하고 그 신호를 네트워크 수준 테스트로 검증한다. 동의가 필요한 저장·측정은 동의 전 요청하지 않으며, 거부 시 FR-15대로 광고 요청 자체를 생략한다.
- 광고 태그가 금융값·계획·수익률·신뢰 상태가 있는 화면 내용을 읽거나 URL로 추론할 수 없는지를 확인하고, 보장할 수 없으면 광고 요청을 금융 데이터가 없는 중립 표면으로 격리하거나 광고를 비활성화한다.
- `금융 상세값`뿐 아니라 사용자 계정 식별자와 이를 파생할 수 있는 내부 ID도 광고·분석 도구 금지 목록에 추가한다.

공식 근거: [광고 개인화 설정](https://support.google.com/adsense/answer/7670312?hl=en), [AdSense 광고 타기팅 방식](https://support.google.com/adsense/answer/9713?hl=en), [Google 동의 관리 요구사항](https://support.google.com/adsense/answer/13554116?hl=en)

### H-3 — 비-USDT 외부 자금흐름 환산의 지원 자산·가격 출처 경계가 없어 MVP가 무제한 데이터 통합으로 커질 수 있다

**근거**

- FR-10은 비-USDT 자금흐름을 사건 시각 USD 가치로 환산하고 더 나은 가격이 생기면 버전과 이력을 남겨 재계산하도록 한다.
- §12는 가격 출처와 추정 조건만 구현 전 결정 대상으로 두며, 지원 자산·시장·가격 조회 기간·가격 부재 시 영구 처리의 상한을 정하지 않는다.
- `모든 비-USDT 자산`을 암묵적으로 지원하면 장기 과거가격, 스테이블코인 디페그, 상장폐지·심볼 변경, 유동성 부족, 제3자 가격 API 비용·장애까지 MVP 의무가 된다. 이는 NFR-20의 월 30,000원·주 2시간 운영 목표와 직접 충돌할 수 있다.

**영향**

- 지원 자산 하나가 추가될 때마다 데이터 공급자·정합성·회귀 예제가 늘고, 미지원 사건 하나가 전체 공식 계산을 장기간 보류할 수 있다.
- 범위와 성공 기준을 바꾸지 않는 단순 구현 결정으로 보기 어렵다.

**권고**

- MVP 지원 자산 허용목록, 최대 과거 조회기간, 공식 가격 출처, 가격 선택 규칙과 `지원 불가` 종결 상태를 출시 전에 고정한다.
- 허용목록 밖 자산은 추정을 끝없이 시도하지 말고 연결/계획 생성 전에 지원 범위를 알리거나 해당 계획을 명확한 `지원 불가` 상태로 둔다.
- 자산·가격 출처 확대는 Later 또는 별도 범위 변경으로 분리한다.

## 중간 중요도

### M-1 — Day 60/90 IP 제한 일정은 복원됐지만 의사결정 결과와 기존 연결 처리가 빠져 있다

**근거**

- §10은 Day 60에 고정 IP 전환 가능 여부를 판단하고 Day 90 이후 IP 제한 없는 키의 신규 연결을 받지 않는다고 명시한다. §11도 제품 통제 준비를 요구한다.
- 그러나 Day 60 판단의 책임자·판단 기준·기록할 산출물, `전환 불가` 판정 시 베타의 계속/중단, Day 90 당시 이미 연결된 무제한 키의 유예·차단·재연결 정책은 없다.

**영향**

- 신규 연결만 차단한 채 기존 무제한 키가 무기한 남아 보안 목표가 절반만 달성될 수 있다.
- Day 60 판단이 실행되지 않아도 핵심 성공 기준 전체가 통과한 것으로 보고될 수 있다.

**권고**

- 이를 일정 문구가 아니라 운영 게이트로 만든다: 책임자, 판단 입력(호스팅 고정 egress IP 가능성·비용·Bybit 호환성), 승인 기록, 실패 시 기본 조치.
- Day 90 기존 연결에 대해 재발급 안내, 유예 기간, 동기화 중단 여부를 명시한다.

### M-2 — 1인 운영 성공 기준과 비상정지·재검증 의무의 측정 경계가 맞물리지 않는다

**근거**

- SM-6/NFR-20은 안정화 후 지원·운영 주 2시간 이하와 월 30,000원 이하를 요구한다.
- 동시에 월 1회 비상정지 훈련, 정기 API·사건 유형 재검증, 백업 복원, 광고/개인정보 재검토, 사고 대응을 요구하지만 운영 시간·비용에 포함되는 활동과 측정 방식이 정의되지 않는다.
- FR-17은 운영자가 5분 내 전역 정지를 수행하도록 하지만, 1인 운영자가 부재·취침 중일 때의 적용 시간대나 가용성 전제를 명시하지 않는다.

**영향**

- 핵심 운영 의무를 비용·시간 계산에서 제외해 SM-6을 형식적으로 통과하거나, 반대로 24시간 대응을 암묵적으로 요구해 개인 프로젝트로는 달성 불가능해질 수 있다.

**권고**

- 운영 시간에는 훈련, 재검증, 지원, 장애 처리, 개인정보·광고 점검을 포함한다고 정의하고 월 단위 실측을 주 평균으로 환산한다. 외부 서비스와 광고 비용의 포함 범위도 고정한다.
- `5분 내 수동 정지`가 경보 인지 후인지 24시간 절대시간인지 명시하고, 무인 시간에는 60초 자동 정지가 보호 경계임을 확정한다.

## 낮은 중요도

### L-1 — 광고 남용·중복 요청에 대한 사용자 측 쿨다운이 명시되지 않았다

- FR-6은 중복 동기화를 합치거나 멱등 처리하지만, 연속 수동 성공 요청의 최소 간격과 광고 요청 중복 억제는 없다.
- 공급자 빈도 제한으로 실제 노출은 줄어도 Bybit 호출·광고 요청·측정 이벤트는 늘 수 있다.
- 제품이 허위 활동을 유도하지 않는다는 SM-C3에 더해, 진행 중 버튼 잠금과 짧은 서버 측 쿨다운, 동일 스냅샷에 광고 요청 1회라는 인수조건을 권한다.

## 확인된 강점

- 무료 공개 베타가 §8.1에 명시되어 결제·구독 기능의 숨은 범위가 없다.
- MVP 광고는 보상형이 아니며, 실제 노출은 채움·동의·빈도 제한을 따른다고 구분했다.
- 광고 미채움·차단·동의 거부·장애가 동기화 결과를 파기하지 않고, 광고를 전역 비활성화할 수 있다.
- TWR/MWR/XIRR, 다중 거래소, 자산·전략별 성과, 자동매매, 백그라운드 수집은 Later/비목표로 명확히 분리되어 있다.
- 광고 후 조회 포기율을 역지표로 두고 15% 초과 시 재설계한다는 안전장치가 있다.
- 비상정지는 계획/계산 버전/연결/동기화/광고 단위로 분리되어 공통 장애의 확산 방지 구조가 좋다.

## 최소 통과 조건

1. 광고 공급자·상품이 `동기화 성공 후` 트리거를 정책상 지원함을 출시 전 검증하거나, FR-14 트리거를 지원 가능한 흐름으로 재정의한다.
2. 공급자별 광고 데이터 흐름과 동의 전/거부 시 동작을 요구사항·출시 게이트로 만들고, 금융 화면 문맥 유출 가능성을 해소한다.
3. 비-USDT 환산의 MVP 자산 허용목록과 가격 조회 경계를 고정한다.
4. Day 90 기존 무제한 키 처리와 1인 운영 시간/응답시간의 측정 경계를 명료화한다.

### 재검토 판정

**조건부 통과.** 기존 5건 중 3건은 해결됐고 2건은 부분 해결됐다. 새로 발견된 치명·높음 문제는 없다. 다만 H-2의 금융 페이지 본문/DOM 문맥 유출 가능성은 출시 전 광고 데이터 흐름 검토에서 반드시 닫아야 하며, 해결할 수 없으면 §12.3에 따라 광고 없이 출시해야 한다. M-2는 운영 현실성 명료화 항목으로 남는다.

### Final recheck

- **H-2 — Resolved.** FR-14는 금융값·계획값·신뢰 상태가 DOM·URL·제목에 없는 중립 결과 전환 화면에서만 광고를 요청하고, 광고 종료 뒤 별도 결과 화면이 최신 스냅샷을 표시하도록 한다. FR-15는 대시보드 본문/DOM 문맥 분석을 요구하는 공급자를 사용하지 않도록 명시한다. 기존의 네트워크 요청 검사·비개인화·사전 동의 조건과 합쳐 금융 화면 문맥 유출 경계가 검증 가능하게 닫혔다.
- **M-2 — Resolved.** SM-9는 5분 수동 정지 SLA를 공지된 베타 운영 대응 시간대 또는 훈련 중으로 제한하고, 24시간 수동 대응을 약속하지 않으며 시간대 밖에는 60초 자동 정지를 일차 통제로 삼는다. NFR-20의 운영 시간 포함 범위와 함께 1인 운영 현실성 및 측정 경계가 명확해졌다.

**최종 판정: 통과.** 기존 상위 발견 5건이 모두 해결됐다. 이 재검토 범위에서 남은 치명·높음 문제는 없다.
