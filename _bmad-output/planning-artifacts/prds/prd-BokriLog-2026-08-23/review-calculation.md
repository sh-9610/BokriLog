# BokriLog MVP PRD — 계산·데이터 무결성 검토

## 판정

**수정 후 통과 (현재 상태: 출시·계산 SPEC 인계 차단).** 계산 방향과 실패 시 마지막 정상값을 보존하는 원칙은 적절하지만, 외부 자금흐름의 시간 범위와 계획 종료 후 완료 결과의 기준 시점에 직접적인 오계산 가능성이 있다. 또한 서로 다른 Bybit 응답을 하나의 공식 스냅샷으로 승격하는 일관성 계약이 없어, 정상 응답만으로도 잘못된 공식 결과가 만들어질 수 있다.

## Critical

### C-1. 외부 자금흐름 합산 범위에 계획 시작 하한이 없어 시작금액을 이중 계산할 수 있다

- **근거:** §4.2와 §4.3은 각각 `Σ[ti ≤ t]`만 정의한다. `t0 < ti` 또는 시작 스냅샷에 포함되었는지를 가르는 하한이 없다. §4.1의 `Fi` 정의도 계획 시작 이후 사건으로 제한하지 않는다. FR-9는 늦게 발견된 과거 사건을 사건 시점부터 재계산한다고만 한다.
- **위험:** 동기화가 계획 시작 전의 입출금을 뒤늦게 반환하면, 그 사건은 이미 `P0 = E(t0)`에 반영되어 있는데 계획선과 목표에 다시 더해지거나 빠진다. 시작 시각과 동일한 밀리초의 사건도 시작 스냅샷 포함 여부에 따라 결과가 달라진다.
- **필요한 계약 보완:** 계획 조정에 포함되는 사건의 시작 경계와 `ti = t0` 처리 규칙을 명시하고, 시작 스냅샷의 포함 컷오프와 일치시켜야 한다. 시작 전 사건과 경계 시각 사건을 NFR-3 고정 예제에 포함해야 한다.

### C-2. 종료 후 최초 스냅샷은 종료 시점의 계정가치가 아니므로 완료 결과를 잘못 확정할 수 있다

- **근거:** §4.7과 FR-13은 `T` 이후 최초 정상 스냅샷으로 완료 결과를 확정한다고 한다. 그러나 §4는 완료 결과가 어떤 기준 시각과 공식으로 산출되는지 정의하지 않는다. `Target(t)`는 `ti ≤ t`인 사건을 포함하므로 `t > T`에서 발견한 종료 후 자금흐름까지 `periods(ti,T)`의 음수 지수로 목표에 반영할 수 있다.
- **위험:** 최초 정상 동기화가 `T`보다 수시간 또는 수일 늦으면 `E(snapshot_time)`에는 종료 후 시장손익·수수료·펀딩·입출금이 섞인다. 이를 `T`의 목표와 비교하면 계획 종료 성과처럼 보이는 값이 실제로는 종료 후 변동을 포함한다. 특히 종료 후 입출금은 목표식에 역복리로 들어가거나 완료 결과의 현재가치만 바꾸는 등 구현별 결과가 갈린다.
- **필요한 계약 보완:** 완료 결과가 “종료 시각 값”인지 “종료 후 최초 관측값”인지 명시하고, 후자라면 이를 근사치가 아닌 공식 완료값으로 부를 수 있는 허용 지연·표시·계산 규칙을 정해야 한다. 완료 계산에 포함되는 외부 자금흐름의 종료 상한, 완료 스냅샷 측정 시각, `T` 이후 변동의 처리, 지연 한계를 고정 예제로 검증해야 한다.

## High

### H-1. 지갑 가치와 사건 이력이 동일 기준시점이라는 보장이 없어 일시적 불일치를 공식값으로 승격할 수 있다

- **근거:** FR-7은 “필요한 API 구간과 페이지가 모두 검증”되면 원자적으로 확정한다고 하지만, Bybit의 현재 지갑값과 페이지형 거래 이력은 서로 다른 요청이다. PRD에는 공통 기준시점, 포함 컷오프, 지연 사건 안정화 조건이 없다. FR-9의 사후 재계산은 이미 잘못 승격된 값을 허용한다.
- **위험:** 입금 직후 지갑 `totalEquity`에는 금액이 반영됐지만 사건 이력에는 아직 없거나, 반대 순서로 보일 수 있다. 모든 호출과 페이지가 성공해도 계획 대비 차이와 달성도가 입출금을 투자성과로 잠시 오인하며 `공식`으로 표시될 수 있다.
- **필요한 계약 보완:** 공식 승격에 필요한 공통 as-of 경계 또는 동등한 일관성 조건을 제품 계약으로 정의해야 한다. 경계 직전·직후 사건, API 지연, 페이지 이동 중 신규 사건을 NFR-3 회귀 예제에 포함해야 한다.

### H-2. 일·주·월의 부분 주기 함수가 단일한 결과를 보장하지 않는다

- **근거:** §4.1은 “계획 시작 시각에 고정된 복리 주기 경계”와 “각 달력 주기의 실제 길이 대비 경과시간 비율”을 함께 사용하지만, 월말 시작일(29·30·31일), 경계가 없는 달, 윤년, 종료일 산정, 여러 부분 구간을 합산하는 규칙을 정의하지 않는다. `periods(a,b)`의 가법성도 명시하지 않는다.
- **위험:** 1월 31일에 시작한 월 복리 계획의 2월·3월 경계를 구현마다 다르게 잡을 수 있다. `periods(t0,t)`와 `periods(t0,ti)+periods(ti,t)`가 달라지면 동일 자금흐름도 계산 경로에 따라 다른 계획선이 된다.
- **필요한 계약 보완:** 각 주기의 경계 생성 규칙과 부분 구간 합산 규칙을 계산 SPEC의 선행 결정으로 승격하고, 월말·윤일·자정·주기 경계 정확히 일치·1일 계획을 필수 고정 예제로 지정해야 한다.

### H-3. 추정 환산가가 어떤 지표를 `추정`으로 전파하는지 불명확하다

- **근거:** FR-10은 추정 환산가를 사용한 “계산”을 추정으로 표시한다고 하지만, FR-12는 계산 성격을 독립 상태로 보여준다고만 한다. 현재가치 `E(t)`는 공식일 수 있는 반면, 같은 화면의 `Plan`, `Target`, `Difference`, `RequiredRate`, `GoalProgress`는 추정 외부 자금흐름에 의존한다. 지표별 상태인지 화면 전체 상태인지 정의되지 않았다.
- **위험:** 전역 상태를 `공식`으로 두면 파생값이 과장되고, `추정`으로 두면 Bybit 공식 `totalEquity`까지 추정처럼 보인다. 서로 다른 계산 버전 또는 근거 상태가 한 화면에서 섞여도 FR-11/FR-12 테스트가 통과할 수 있다.
- **필요한 계약 보완:** 추정 입력의 의존 지표 전파 범위와 지표별 계산 성격 표시 단위를 정의해야 한다. 추정값이 더 나은 가격으로 교체될 때 영향을 받는 지표와 버전 변경도 검증해야 한다.

## Medium

### M-1. 목표율 상한과 수치 표현 한계가 없어 “유한한 입력”도 계산 불가능해질 수 있다

- **근거:** FR-4는 목표 주기율을 유한한 0 이상 십진수로만 제한한다. 기간은 최대 1년이나 일 복리와 매우 큰 `r`, 큰 금액·자금흐름 조합이면 거듭제곱 결과가 저장 정밀도나 화면 표현 범위를 넘을 수 있다. 정확한 저장 정밀도는 §12의 구현 전 미결정이다.
- **위험:** 입력 검증을 통과한 계획이 생성 직후 오버플로·과도한 자릿수·응답 실패를 일으킬 수 있으며, 구현별 상한에 따라 동일 계획의 허용 여부가 달라진다.
- **필요한 계약 보완:** 제품이 지원하는 금액·목표율·계산 결과 범위와 범위 초과 동작을 정하고 NFR-3의 “대규모” 예제를 수치로 고정해야 한다.

### M-2. 조기 종료 값은 실제 종료 시각과 다른 스냅샷일 수 있으나 신선도 계약이 없다

- **근거:** FR-5는 중도 종료 당시 “마지막 정상 스냅샷”과 실제 종료 시각을 보존한다. 두 시각이 다를 수 있지만 최대 허용 차이, 표시 방식, 결과의 계산 성격이 없다.
- **위험:** 오래된 값을 실제 중도 종료 결과로 오해할 수 있고, 같은 상황에서 어떤 구현은 종료를 허용하고 어떤 구현은 동기화를 강제할 수 있다.
- **필요한 계약 보완:** 중도 종료 결과의 기준 시각과 스냅샷 신선도 표시, 정상 스냅샷이 없는 경우의 동작을 정의해야 한다.

### M-3. 중복 판정 키가 실제 사건 공간에서 유일하다는 계약이 부족하다

- **근거:** FR-9와 addendum은 거래소 사건 ID 하나를 멱등 키로 사용한다고 단정한다. 지원 사건 유형은 아직 미정이며, 유형·엔드포인트별 ID 존재성과 전역 유일성은 출시 전 게이트로도 명시되지 않았다.
- **위험:** 서로 다른 사건 유형의 같은 ID가 하나로 합쳐지거나, ID가 없는 사건이 중복 반영될 수 있다. 미인식·중복 의심 시 보류 원칙은 있지만 무엇을 “의심”으로 판정하는지 검증할 수 없다.
- **필요한 계약 보완:** 지원 사건 유형별 고유성 근거와 ID 누락·충돌 시 공식 승격 금지를 출시 전 검증 항목 및 고정 예제로 포함해야 한다.

## Low

### L-1. 계산 무결성 성공 기준 일부가 판정 가능하도록 정의되지 않았다

- **근거:** NFR-5와 SM-7은 “중대 계산 오류 0건”을 요구하지만 중대 계산 오류 판정표는 §12의 구현 전 미결정이다. NFR-3의 고정 예제도 기대값·허용오차·계산 버전이 문서에 연결되지 않았다.
- **위험:** Day 60에 알려진 신고만 0건인지 실제 오류가 0건인지, 어떤 오차가 중대인지 합의할 수 없다.
- **필요한 계약 보완:** 공개 베타 전 중대도 정의와 고정 예제 식별자·기대 결과·허용오차를 승인된 계산 SPEC에 연결하고, SM-7의 측정 대상을 “탐지된 건수” 등 관찰 가능한 형태로 명시해야 한다.

## 긍정적 확인

- `Plan`, `Target`, `Difference`, `RequiredRate`, `GoalProgress`를 서로 구분하고 TWR·MWR/XIRR을 MVP에서 배제한 것은 지표 오인 위험을 줄인다.
- 현재가치 또는 목표가 0 이하일 때 비율을 `0%`로 대체하지 않는 규칙은 안전하다.
- 지연 사건의 결정적 재계산, 원 사건 보존, 표시값의 후속 계산 금지, 십진수 계산과 원자적 화면 버전 요구는 올바른 무결성 방향이다.
- 광고 실패가 계산 성공 상태와 분리되어 있어 계산 결과 보존 계약과 충돌하지 않는다.

## Recheck

수정된 PRD에서 기존 Critical/High 5건만 재검토했다.

| Finding | 판정 | 재검토 근거 |
|---|---|---|
| C-1 시작 전 자금흐름 이중 계산 | **Resolved** | `Fi`를 `t0 < ti ≤ T`로 제한하고, `Plan`, `Target`, `AdjustedPrincipal`의 합산 범위도 `t0 < ti ≤ u(t)`로 통일했다. `ti = t0`는 시작 스냅샷에 포함된 것으로 취급되어 중복 합산되지 않는다. |
| C-2 종료 후 최초 스냅샷의 완료값 오인 | **Partially resolved** | `u(t)=min(t,T)`와 사건 상한으로 T 이후 자금흐름의 음수 지수 반영은 제거됐다. 최초 값을 `첫 종료 후 관측값`으로 명명하고 실제 측정 시각·지연을 표시하며, T 이후 외부 자금흐름이 있으면 비교 불가로 처리한다. 다만 지연 허용 상한이 없어 T 이후 시장손익·수수료·펀딩 등이 수일 이상 누적된 관측값도 여전히 “완료 비교”로 남을 수 있다. 정확한 T 평가액이 아니라는 고지는 있으므로 직접 오계산은 막았지만, 완료 비교의 유효성 경계는 아직 미정이다. |
| H-1 지갑값·사건 이력 기준시점 불일치 | **Resolved** | 공통 기준시점 `tc`, 사건 이력의 구간·페이지 완전성, 불확실 구간 중첩 재조회, 입증 실패 시 공식 승격 금지가 FR-7에 추가됐다. 실제 Bybit API로 충족 가능한지는 출시 전 기술 검증 대상이지만 무결성 계약 자체는 명확하다. |
| H-2 부분 주기와 월말 경계 불명확 | **Resolved** | 일·주·월 경계, 월말 대체 후 원래 기준일 복귀, 실제 구간 길이에 따른 부분 주기 합산, 가법성, 윤년·시간대 오프셋 처리가 §4.1에 명시됐다. |
| H-3 추정 환산가 상태 전파 불명확 | **Resolved** | FR-12가 공식 현재가치와 추정 흐름에 의존하는 다섯 파생지표를 구분하고, 후자 전체에 `추정`을 전파하도록 명시했다. |

**새로운 Critical/High:** 없음.

**재검토 판정:** Critical은 해소되었고 기존 High 3건도 해소됐다. C-2의 남은 문제는 정확성 오류보다는 완료 비교의 유효성·제품 표현 경계이므로 **Medium으로 하향**할 수 있다. 계산 SPEC 인계를 차단할 Critical/High는 더 이상 없다.

**C-2 최종 판정 — Resolved:** 첫 종료 후 관측값을 정확한 `T` 평가액으로 표현하지 않고, `T`로부터 24시간 이내에만 참고 비교를 허용하며 이후에는 `계산 불가`로 처리하도록 §4.7과 FR-13이 일치해 기존의 무제한 지연 위험이 해소됐다.
