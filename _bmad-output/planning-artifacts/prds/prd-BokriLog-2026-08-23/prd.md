# PRD: BokriLog MVP

## 0. 문서 목적

이 문서는 BokriLog 공개 베타 MVP의 제품 계약이다. 사용자 경험 설계, 아키텍처, 계산 SPEC, 에픽·스토리 작성자는 이 문서의 용어와 요구사항 ID를 기준으로 작업한다. 기능은 전역 ID `FR-N`, 사용자 여정은 `UJ-N`, 성공 기준은 `SM-N`으로 식별한다. 구현 전 미결정 사항은 §12의 책임자·기한·차단 조건을 따른다.

기준 입력은 `brief-BokriLog-2026-08-16/brief.md`다. 계산 구현, Bybit API 매핑, 광고 공급자 선정처럼 제품 요구사항보다 하위 수준인 내용은 `addendum.md`에 분리한다.

### MVP 계약 요약

- **핵심 가치:** 최초 복리 계획과 외부 자금흐름 조정 이력을 보존하고 Bybit UTA `totalEquity`를 계획선과 비교한다.
- **MVP 경계:** 읽기 전용 Bybit UTA 1개, 활성 계획 1개, 계획 비교 대시보드와 신뢰 상태에 집중한다. 거래 실행·추천·다중 거래소·공식 투자성과 분석은 제외한다.
- **수익화:** 무료 공개 베타에서 수동 동기화 성공 시 닫기 가능한 문맥형 전면광고 노출을 시도한다. 광고 실패는 결과 조회를 막지 않는다.
- **성공 판정:** 공개 베타 Day 60에 반복 사용, 이해도, 동기화 품질, 안전성, 1인 운영성과 비용을 기준으로 계속·중단·재설계를 결정한다.
- **출시 차단:** 소셜 인증 보안, 읽기 전용 검증, 계산 회귀, 개인정보·광고 데이터 흐름과 실제 소재 접근성, 계정 삭제 법률 검토, 백업 복원과 비상정지 검증을 통과하지 못하면 관련 기능 또는 베타 출시를 차단한다.

## 1. 비전과 제품 원칙

BokriLog는 복리 목표를 세우고 Bybit Unified Trading Account(UTA)를 운용하는 개인 투자자를 위한 읽기 전용 반응형 웹 서비스다. 사용자가 최초 계획과 외부 자금흐름 조정 이력을 잃지 않은 채, Bybit가 제공하는 UTA 공식 USD 환산 계정가치 `totalEquity`를 계획선과 비교하도록 돕는다.

제품의 핵심 가치는 더 많은 투자 분석이 아니라 기준선 보존이다. 사용자는 대시보드 한 화면에서 현재가치, 현재 시점 계획금액, 계획 대비 차이, 조정 최종 목표, 남은 필요 등가수익률, 목표 수익 달성도를 확인한다. 입출금은 성과가 아니며, UTA 내부에서 발생한 손익·가격변화·미실현손익·펀딩비·수수료·이자·리베이트는 외부 자금흐름이 아닌 계정가치 변동으로 취급한다.

MVP는 거래 실행이나 투자 행동을 추천하지 않는다. 숫자를 최신·정확한 값처럼 과장하지 않으며, 신선도·입력 신뢰도·계산 성격을 분리해 보여준다. 불완전한 입력은 공식 계산으로 승격하지 않는다.

## 2. 대상 사용자와 사용자 여정

### 2.1 대상 사용자

- 복리 목표를 직접 설정하고 Bybit UTA에서 현물 또는 USDT 무기한 계약 등을 운용하는 개인 투자자
- 현재 잔액이 아니라 최초 계획과 자금흐름 조정 이력을 기준으로 진행 상황을 보고 싶은 사용자
- 읽기 전용 API 키 연결과 수학적 계획 비교를 이해하거나 안내를 통해 수행할 수 있는 사용자

### 2.2 MVP 비사용자

- 다중 거래소 또는 다중 포트폴리오를 한 화면에서 분석하려는 사용자
- 코인·상품·전략별 공식 성과, 세금, 위험지표 또는 벤치마크 분석이 필요한 사용자
- 주문·출금·이체·자동매매·투자 추천을 원하는 사용자

### 2.3 핵심 사용자 여정

- **UJ-1. 민준이 출근 전 계획 진행 상황을 확인한다.**
  - **사용자와 상황:** 민준은 Bybit UTA에서 현물과 USDT 무기한 계약을 운용하는 직장인 투자자다. 매일 거래하기보다 복리 계획이 흐트러지지 않았는지 짧게 확인하려 한다.
  - **진입 상태:** 민준은 이미 사용자 계정에 로그인했고, 읽기 전용 Bybit UTA 연결과 활성 계획이 있다. 모바일 웹 대시보드를 연다.
  - **경로:** 대시보드는 마지막 정상 현재가치와 측정 시각, 신선도·입력 신뢰도·계산 성격을 먼저 보여준다. 민준은 최신 값을 확인하려고 `수동 동기화`를 누른다. 동기화가 정상 완료되고 동의·채움·접근성·빈도 조건을 충족하면 닫기 가능한 전면광고 노출을 시도한다. 최근 30분 안에 광고를 시도했거나 `Asia/Seoul` 당일 시도 횟수가 3회에 도달했다면 광고를 요청하지 않는다. 어느 경우든 대시보드는 저장된 동일 최신 스냅샷을 기준으로 여섯 지표를 갱신한다.
  - **가치 실현:** 민준은 계획보다 앞섰는지 또는 뒤졌는지와 남은 기간에 필요한 주기별 등가수익률을 한 화면에서 파악한다. 제품은 매수·매도 행동을 권하지 않는다.
  - **종료 상태:** 민준은 추가 계산이나 엑셀 수정 없이 화면을 닫는다. 최초 계획과 조정 이력은 그대로 보존된다.
  - **예외:** 동기화에 실패하면 광고가 결과 조회를 막지 않는다. 마지막 정상값과 실패 상태, 마지막 정상 측정 시각을 보여주며 새 값을 공식 계산으로 승격하지 않는다.

- **UJ-2. 민준이 처음으로 읽기 전용 연결과 계획을 만든다.** 민준은 Google·네이버·카카오 중 하나로 가입한다. 소셜 제공자는 본인 확인에만 사용되며 금융·계획·Bybit 데이터는 공유되지 않는다. 로그인 성공 뒤 읽기 전용 Bybit API 자격정보를 입력한다. 시스템이 권한·UTA·UID·IP 상태와 실제 조회 성공을 검증한 후 첫 정상 `totalEquity`를 시작금액으로 고정한다. 민준은 기간·복리 주기·주기별 목표율을 입력하고 활성 계획을 생성한다. 쓰기 권한 키라면 저장 전에 해당 연결 시도만 거부된다. 로그인된 설정에서는 현재 수단으로 재인증한 뒤 다른 소셜 제공자를 같은 계정에 명시적으로 연결할 수 있다.

- **UJ-3. 민준이 신뢰할 수 없는 자금흐름 때문에 계산이 보류된 이유를 이해한다.** 동기화 중 미분류 사건이나 비-USDT 환산가 결측이 발견되면 시스템은 공식 계산을 갱신하지 않는다. 민준은 마지막 정상값과 `검토 필요` 상태, 보류 이유를 확인한다. 원인이 해소되고 완전한 동기화가 성공한 뒤에만 이후 계획선과 파생지표가 재계산된다.

## 3. 용어집

- **사용자 계정** — BokriLog 내부 `user_id`가 소유하는 인증·데이터 경계. MVP에서 제공자별 로그인 수단 1~3개, Bybit 연결 1개와 활성 계획 최대 1개를 가진다.
- **로그인 수단** — Google·네이버·카카오가 발급한 고유 외부 식별자 `(issuer, subject)`와 한 BokriLog `user_id`의 연결. 이메일·표시명은 식별키나 자동 병합 근거가 아니다.
- **Bybit 연결** — 사용자 계정과 읽기 전용 Bybit UTA를 연결하는 자격정보 및 검증 상태.
- **UTA** — BokriLog가 지원하는 Bybit Unified Trading Account의 단일 계정 경계.
- **현재가치** — 정상 동기화로 확인된 Bybit UTA 전체의 공식 USD 환산 `totalEquity`.
- **스냅샷** — 하나의 정상 동기화에서 원자적으로 확정한 현재가치, 측정 시각, 관련 입력 상태의 묶음.
- **계획** — 시작 시각, 종료 시각, 시작금액, 복리 주기, 목표 주기율을 고정한 복리 목표.
- **시작금액** — 첫 정상 연결 시점의 현재가치.
- **목표 주기율** — 사용자가 선택한 복리 주기마다 계획에 적용되는 고정 비율 `r`.
- **외부 자금흐름** — UTA 경계를 넘어 유입되거나 유출된 것으로 확인된 사용자 자본. 입금은 양수, 출금은 음수다.
- **조정 원금** — 시작금액과 현재까지 확인된 외부 자금흐름의 대수합.
- **현재 시점 계획금액** — 시작금액과 각 외부 자금흐름을 해당 시점부터 목표 주기율로 복리 반영한 현재 기준 계획값.
- **조정 최종 목표** — 시작금액과 현재까지 확인된 외부 자금흐름을 각각 계획 종료 시점까지 목표 주기율로 복리 반영한 합계.
- **계획 대비 차이** — 현재가치에서 현재 시점 계획금액을 뺀 부호 있는 금액.
- **남은 필요 등가수익률** — 현재가치가 남은 기간 동안 조정 최종 목표에 도달하기 위해 필요한, 복리 주기당 부호 있는 등가수익률.
- **목표 수익 달성도** — 현재가치에서 조정 원금을 뺀 금액을 조정 최종 목표에서 조정 원금을 뺀 금액과 비교한 비율.
- **신선도** — 스냅샷 측정 시각과 최근 동기화 결과가 얼마나 최신인지 나타내는 상태.
- **입력 신뢰도** — 외부 자금흐름·환산가·API 구간의 완전성과 분류 확실성을 나타내는 상태.
- **계산 성격** — 표시값이 공식 계산, 추정 계산 또는 계산 불가 중 어디에 해당하는지 나타내는 상태.
- **전면광고** — 수동 동기화 후 화면을 덮어 노출을 시도하며 사용자가 닫을 수 있는 인터스티셜·비네트형 광고.
- **격리** — 문제가 있는 계획, 계산 버전 또는 동기화 범위가 공식 결과를 갱신하지 못하도록 중단한 상태.

## 4. 수익률 및 계획 계산 정의

### 4.1 공통 변수와 시간 규칙

- `t0`: 첫 정상 연결 및 계획 시작 시각
- `T`: 계획 종료 시각, `T > t0`
- `E(t)`: 시각 `t`의 정상 스냅샷 현재가치
- `P0`: 시작금액, `P0 = E(t0)`
- `r`: 목표 주기율, `r >= 0`
- `u(t)`: 계획 계산 상한 시각, `u(t) = min(t,T)`
- `periods(a,b)`: `Asia/Seoul`에서 계획 시작 시각에 고정된 복리 주기 경계를 기준으로 `a`부터 `b`까지의 주기 수
- `Fi`: `t0 < ti ≤ T`인 시각 `ti`에 발생한 확인된 외부 자금흐름의 이벤트 시점 USD 가치. 입금은 양수, 출금은 음수
- `tc`: 한 공식 스냅샷에서 현재가치와 외부 자금흐름 완전성을 함께 판정하는 동기화 기준시점

복리 주기는 일·주·월 중 하나다. 기준 경계는 `t0`의 `Asia/Seoul` 현지 날짜와 시각에 고정한다. 일 주기는 다음 현지 달력일의 같은 시각, 주 주기는 7개 현지 달력일 뒤 같은 시각, 월 주기는 다음 달의 같은 일·시각을 경계로 한다. 월에 기준 일이 없으면 그 달의 마지막 날을 사용하되, 다음 달에는 원래 기준 일로 복귀한다. 예를 들어 1월 31일 시작의 월 경계는 2월 말일, 3월 31일이다.

`periods(a,b)`는 `a`부터 `b`까지 걸친 각 기준 구간의 `실제 경과시간 ÷ 해당 구간의 실제 길이`를 합산한다. 따라서 부분 주기를 포함해 `periods(a,c) = periods(a,b) + periods(b,c)`를 만족해야 한다. 윤년과 시간대 오프셋 변화는 해당 구간의 실제 길이에 반영한다. 모든 사건 원본 시각은 UTC 밀리초로 보존하고 계획 경계와 화면의 `오늘`만 `Asia/Seoul`로 평가한다.

금액과 비율은 정확한 십진수로 계산한다. 표시값으로 후속 계산하지 않으며 최종 화면 표시 단계에서만 금액은 소수 둘째 자리, 비율은 소수 둘째 자리로 반올림한다. 반올림 결과 `-0.00`은 `0.00`으로 표시한다.

### 4.2 현재 시점 계획금액

```text
Plan(t) = P0 × (1 + r)^periods(t0,u(t))
        + Σ[t0 < ti ≤ u(t)] Fi × (1 + r)^periods(ti,u(t))
```

입출금은 사건 시점부터 계획선에 반영된다. 최초 계획 입력과 시작금액은 변경하지 않으며, 외부 자금흐름마다 별도 조정 성분과 이력을 보존한다.

### 4.3 조정 최종 목표

```text
Target(t) = P0 × (1 + r)^periods(t0,T)
          + Σ[t0 < ti ≤ u(t)] Fi × (1 + r)^periods(ti,T)
```

미래 외부 자금흐름은 예측하지 않는다. 새로 확인된 과거 외부 자금흐름은 사건 시점부터 이후 계획선과 모든 파생지표를 다시 계산한다.

### 4.4 계획 대비 차이

```text
Difference(t) = E(t) - Plan(t)
```

- 양수: 현재가치가 현재 시점 계획금액보다 큼
- 0: 현재가치와 현재 시점 계획금액이 같음
- 음수: 현재가치가 현재 시점 계획금액보다 작음

### 4.5 남은 필요 등가수익률

`t < T`, `E(t) > 0`, `Target(t) > 0`, `periods(t,T) > 0`일 때:

```text
RequiredRate(t) = (Target(t) / E(t))^(1 / periods(t,T)) - 1
```

결과는 사용자가 선택한 복리 주기당 부호 있는 등가수익률이다. 현재가치가 조정 최종 목표보다 크면 음수가 될 수 있으며 0으로 보정하지 않는다. 이 값은 투자 추천이나 투자성과 수익률이 아니다.

### 4.6 목표 수익 달성도

```text
AdjustedPrincipal(t) = P0 + Σ[t0 < ti ≤ u(t)] Fi
GoalProfit(t)         = Target(t) - AdjustedPrincipal(t)
AchievedProfit(t)     = E(t) - AdjustedPrincipal(t)
GoalProgress(t)       = AchievedProfit(t) / GoalProfit(t)
```

`GoalProfit(t) > 0`일 때만 계산한다. 결과는 음수와 100% 초과를 허용하고 범위를 강제로 제한하지 않는다. `GoalProfit(t) <= 0`이면 계산 불가와 이유를 표시한다.

### 4.7 계산 불가와 계획 종료

- 분모가 0이거나 실수 범위에서 정의되지 않은 비율은 `0%`로 대체하지 않는다.
- 현재가치가 0 이하이면 원 금액과 경고는 표시하되 남은 필요 등가수익률은 계산하지 않는다.
- 조정 최종 목표가 0 이하이면 계획을 `검토 필요`로 전환하고 목표 기반 파생비율을 계산하지 않는다.
- 종료 시점 이후 최초의 정상 스냅샷을 `첫 종료 후 관측값`으로 확정하고 실제 측정 시각과 `측정 시각 - T` 지연을 표시한다. 이를 종료 시각의 정확한 평가액으로 표현하지 않는다.
- 첫 종료 후 관측값이 `T`로부터 24시간 이내일 때만 완료 목표와의 참고 비교를 제공한다. 24시간을 초과하면 완료 비교는 `계산 불가`로 두고 관측 현재가치만 별도 표시한다.
- `T` 이후에 발생한 외부 자금흐름은 완료 목표·조정 원금·완료 달성도에 포함하지 않는다. `T`와 첫 종료 후 관측값 사이 외부 자금흐름이 있으면 완료 비교를 `계산 불가`로 표시한다.
- 완료 뒤 현재가치는 계속 동기화할 수 있지만 완료 결과와 분리해 표시한다.
- 정확한 TWR·MWR·XIRR·단순 투자수익률·연환산 투자수익률은 MVP에서 계산하거나 암시하지 않는다.

## 5. 기능 요구사항

### 5.1 사용자 계정과 읽기 전용 Bybit 연결

#### FR-1: 사용자 데이터 경계

인증된 사용자는 자신의 사용자 계정에 속한 Bybit 연결, 계획, 외부 자금흐름, 스냅샷과 계산 결과만 조회·변경할 수 있다.

**검증 가능한 결과:**
- 모든 서버 요청에서 사용자 소유권을 검증한다.
- 다른 사용자 식별자를 조작한 요청은 데이터 존재 여부를 노출하지 않고 거부한다.
- 모든 사용자 데이터는 외부 제공자 식별자가 아니라 BokriLog 내부 `user_id`에 귀속한다.
- 동일한 `(issuer, subject)`는 둘 이상의 `user_id`에 연결할 수 없다.
- 이메일 주소가 같다는 이유로 계정을 자동 병합·전환하거나 기존 계정 존재 여부를 노출하지 않는다.
- 사용자 계정당 Bybit 연결은 최대 1개다.

#### FR-2: 읽기 전용 연결 검증

사용자는 API Key와 API Secret을 제출해 Bybit 연결을 만들 수 있다. 시스템은 저장 전에 `readOnly=1`, 지원 UTA, UID·IP 상태와 실제 지갑 조회 성공을 검증한다. UJ-2를 실현한다.

**검증 가능한 결과:**
- 쓰기 권한 키는 저장하지 않고 해당 연결 시도만 거부한다.
- 형식 오류, 만료·폐기, UID 불일치, IP 제한 불일치, 미지원 UTA와 조회 실패를 구분 가능한 오류로 표시한다.
- 연결 성공은 모든 검증 조건을 충족한 경우에만 기록한다.

#### FR-3: 자격정보 보호와 연결 해제

시스템은 Bybit 자격정보를 전송·저장 과정에서 보호하고 화면·로그·분석·광고 도구에 노출하지 않는다.

**검증 가능한 결과:**
- API Key와 API Secret은 저장 시 암호화하고 화면에는 원문을 다시 표시하지 않는다.
- 연결 해제 즉시 저장된 자격정보를 삭제하고 이후 동기화를 차단한다.
- 연결 해제 후 계획·외부 자금흐름·완료 결과는 사용자 계정 삭제 전까지 읽기 전용으로 보존한다.

### 5.2 계획 생성과 보존

#### FR-4: 최초 계획 생성

정상 Bybit 연결을 완료한 사용자는 첫 정상 현재가치를 시작금액으로 사용해 종료 시각, 복리 주기, 목표 주기율을 입력하고 계획을 생성할 수 있다. UJ-2를 실현한다.

**검증 가능한 결과:**
- 최초 계획의 시작금액과 시작 시각은 첫 정상 연결 스냅샷에서 자동 확정되며 사용자가 덮어쓰지 못한다.
- 후속 계획은 생성 직전 새 정상 동기화를 요구하며, 해당 최신 스냅샷의 현재가치와 측정 시각을 새 `P0`, `t0`로 고정한다.
- 입력 신뢰도가 `확인됨`이 아니거나 최신 정상 동기화가 없거나 현재가치가 0 이하이면 새 계획 생성을 차단한다.
- 종료 시각은 시작 시각보다 뒤여야 하고 목표 주기율은 유한한 0 이상의 십진수여야 한다.
- 계획 기간은 1일 이상 1년 이하로 제한한다.
- 사용자 계정당 활성 계획은 최대 1개다.

#### FR-5: 계획 불변성과 교체

시스템은 활성 계획의 시작금액·시작 시각·종료 시각·복리 주기·목표 주기율과 이후 조정 이력을 보존한다.

**검증 가능한 결과:**
- 활성 계획의 핵심 입력은 수정할 수 없다.
- 사용자가 조건을 바꾸려면 기존 계획을 명시적으로 종료하고 새 계획을 생성한다.
- 사용자가 종료 시각 전에 계획을 끝내면 `중도 종료`로 기록하고, 종료 당시 마지막 정상 스냅샷과 실제 종료 시각을 보존한다.
- `중도 종료 결과`는 예정 종료 시각에 도달한 `완료 결과`와 구분하며 계획 성공·실패로 자동 판정하지 않는다.
- 기존 계획에서 새 계획으로 과거 조정 이력을 자동 복원하거나 이전하지 않는다.

### 5.3 동기화와 현재가치

#### FR-6: 사용자 시점 동기화

시스템은 대시보드 진입, 탭 재활성화, 사용자의 수동 동기화에서 Bybit 데이터를 동기화한다. UJ-1을 실현한다.

**검증 가능한 결과:**
- 24시간 백그라운드 수집이나 상시 폴링을 수행하지 않는다.
- 동시에 발생한 중복 동기화는 하나의 실행으로 합치거나 멱등하게 처리한다.
- 동기화 시작·진행·성공·실패 상태와 마지막 정상 측정 시각을 보여준다.

#### FR-7: 원자적 스냅샷과 실패 저하

시스템은 필요한 API 구간과 페이지가 모두 검증된 경우에만 새 스냅샷과 공식 계산을 원자적으로 확정한다.

**검증 가능한 결과:**
- 일부 API 요청이나 페이지 처리만 성공하면 부분 결과를 공식 상태로 승격하지 않는다.
- 현재가치는 Bybit 응답의 측정 시각 `tc`를 기록한다. 일상 동기화의 사건 이력은 마지막 확인 지점 이전의 안전 중첩 구간부터 `tc`까지 증분 조회하며, 필요한 모든 구간과 페이지가 완전해야 한다. 매 동기화마다 계획 전체 이력이나 같은 경계 구간을 반복 조회하지 않는다.
- 화면과 계산 근거에는 현재가치 측정 시각과 자금흐름 확인 완료 시각을 구분해 표시한다. 최근 입출금이 아직 거래 로그에 반영되지 않았을 수 있음을 안내하고 사용자가 다시 동기화할 수 있게 한다.
- 계획 종료, 미인식 사건·중복·구간 공백 의심, 장기 미동기화, 사용자의 정밀 검증 요청 또는 운영 조사에서는 계획 관련 전체 이력을 다시 검증한다.
- 필수 증분 구간이나 페이지가 불완전하거나 명시적 이상이 발견되면 스냅샷을 공식 상태로 승격하지 않고 입력 신뢰도를 `검토 필요`로 둔다.
- 실패 시 마지막 정상 스냅샷을 유지하고 신선도를 `최신 아님`으로 표시한다.
- 키 오류나 API 실패를 현재가치 `0`으로 기록하지 않는다.
- 동일 스냅샷의 모든 대시보드 지표는 같은 입력·측정 시각·계산 버전을 사용한다.

### 5.4 외부 자금흐름 분류와 계획 조정

#### FR-8: UTA 경계 외부 자금흐름 판정

시스템은 UTA 경계를 실제로 넘은 것으로 확인된 사건만 외부 자금흐름으로 분류한다.

**검증 가능한 결과:**
- Bybit 응답의 `cashFlow` 값이 0이 아니라는 이유만으로 외부 자금흐름으로 분류하지 않는다.
- 지원하는 명시적 사건 유형과 경계 판정 규칙만 허용한다.
- 계정 내부 손익, 가격변화, 미실현손익, 펀딩비, 수수료, 이자, 리베이트는 외부 자금흐름에서 제외한다.
- 미인식 유형, 이력 구간 공백, 페이지 미완료 또는 중복 의심은 입력 신뢰도를 `검토 필요`로 전환하고 공식 계산 갱신을 보류한다.

#### FR-9: 멱등한 조정 이력과 재계산

시스템은 확인된 외부 자금흐름의 원 사건과 USD 가치, 분류 근거, 반영 시각을 보존하고 계획 계산에 한 번만 반영한다.

**검증 가능한 결과:**
- 동일한 거래소 사건 ID는 재조회나 페이지 중첩에도 한 번만 반영한다.
- 늦게 발견된 과거 사건은 사건 시점 이후의 계획선과 모든 파생지표를 결정적으로 재계산한다.
- 출금 때문에 조정 최종 목표가 0 이하가 되면 계획을 `검토 필요`로 전환한다.
- 원 사건을 삭제하거나 덮어써서 과거 계산 근거를 소실하지 않는다.

#### FR-10: 비-USDT 자금흐름 환산

시스템은 비-USDT 외부 자금흐름을 사건 시점의 USD 가치로 환산하고 환산 근거와 추정 여부를 보존한다.

**검증 가능한 결과:**
- 원자산 코드·수량·사건 시각·USD 환산가·가격 출처·추정 여부를 함께 기록한다.
- MVP는 Bybit가 공식 API로 사건시각 USD 가격을 검증 가능하게 제공하는 자산만 자동 환산한다. 제3자 가격 공급자, 수동 가격 입력과 무제한 자산 가격 통합은 포함하지 않는다.
- 사건 시점 가격이 없으면 현재 가격으로 확정하지 않고 공식 계산 갱신을 보류한다.
- 추정 환산가가 사용된 계산은 계산 성격을 `추정`으로 표시한다.
- 더 나은 환산가가 확보되면 계산 버전과 변경 이력을 남기고 이후 값을 재계산한다.

### 5.5 계획 비교 대시보드

#### FR-11: 핵심 계획 지표 표시

사용자는 하나의 대시보드에서 현재가치, 현재 시점 계획금액, 계획 대비 차이, 조정 최종 목표, 남은 필요 등가수익률, 목표 수익 달성도를 확인할 수 있다. UJ-1을 실현한다.

**검증 가능한 결과:**
- 모든 지표는 §4의 정의와 동일한 스냅샷·계산 버전으로 산출한다.
- 각 비율에는 지표명, 대상 복리 주기와 기준 시각을 표시한다.
- 음수와 100% 초과 결과를 임의로 제한하지 않는다.
- 계산 불가 값을 `0` 또는 `0%`로 표시하지 않고 이유를 함께 보여준다.
- 투자 행동을 추천하거나 특정 수익률 달성을 유도하는 문구를 사용하지 않는다.

#### FR-12: 독립적인 신뢰 상태

사용자는 각 표시 결과가 어떤 근거를 갖는지 판단할 수 있도록 신선도·입력 신뢰도·계산 성격을 독립적으로 확인할 수 있다. UJ-3을 실현한다.

**검증 가능한 결과:**
- 신선도는 최소 `최신`, `동기화 중`, `최신 아님`을 구분한다.
- 입력 신뢰도는 최소 `확인됨`, `검토 필요`, `사용 불가`를 구분한다.
- 계산 성격은 최소 `공식`, `추정`, `계산 불가`를 구분한다.
- 추정 외부 자금흐름이 포함되면 현재가치 자체는 `공식`을 유지하되, 해당 흐름에 의존하는 현재 시점 계획금액·계획 대비 차이·조정 최종 목표·남은 필요 등가수익률·목표 수익 달성도는 모두 `추정`으로 전파한다.
- 하나의 상태가 다른 상태를 암묵적으로 덮어쓰지 않는다.
- 상태마다 원인, 마지막 정상 시각과 사용자가 취할 수 있는 다음 행동을 설명한다.

#### FR-13: 계획 완료 결과

사용자는 계획 종료 이후 완료 결과와 종료 후 현재가치를 구분해 볼 수 있다.

**검증 가능한 결과:**
- 종료 시점 이후 최초 정상 스냅샷을 첫 종료 후 관측값으로 확정하고 실제 측정 시각과 지연을 표시한다.
- 종료 시점 이후 정상 스냅샷이 없으면 완료 결과를 추정하지 않고 동기화 필요 상태를 표시한다.
- 첫 종료 후 관측값이 종료 시점으로부터 24시간을 초과하면 완료 비교를 계산 불가로 표시한다.
- 종료 시점과 첫 종료 후 관측값 사이 외부 자금흐름이 있으면 완료 비교를 계산 불가로 표시한다.
- 완료 뒤 동기화한 현재가치는 완료 결과를 변경하지 않는다.
- 사용자가 예정 종료 전에 끝낸 계획은 `중도 종료`로 표시하고 자연 만료된 계획의 완료 결과와 섞지 않는다.

### 5.6 수동 동기화 전면광고

#### FR-14: 수동 동기화 광고 노출 시도

사용자가 수동 동기화로 최신 현재가치를 조회할 때 시스템은 동기화 성공 후 전면광고 노출을 시도하고, 사용자가 광고를 닫은 뒤 갱신된 결과를 표시한다. UJ-1을 실현한다.

**검증 가능한 결과:**
- 전면광고는 사용자가 별도 보상 조건 없이 닫을 수 있다.
- 수동 동기화 성공 후 광고 노출 시도는 사용자당 30분에 최대 1회, `Asia/Seoul` 기준 하루 최대 3회로 제한한다. 제한에 걸린 동기화는 광고 요청 없이 같은 저장 결과로 이동한다.
- 광고는 공급자가 공식 지원하는 사용자 행동 또는 결과 화면 전환 트리거로만 요청한다. 수동 동기화 버튼을 지원하지 않는 공급자에서 임의 팝업·페이지 새로고침으로 트리거를 모방하지 않는다.
- 전면광고는 금융값·계획값·신뢰 상태를 DOM, URL, 페이지 제목에 포함하지 않는 중립적인 결과 전환 화면에서 요청한다. 광고가 종료되면 별도 결과 화면에 최신 스냅샷을 표시한다.
- 대시보드 자동 진입 동기화와 탭 재활성화 동기화는 전면광고를 유발하지 않는다.
- 광고를 계산 카드, 신뢰 상태 또는 동기화 조작으로 오인하게 만들지 않는다.

#### FR-15: 광고 실패와 개인정보 경계

광고 상태는 동기화와 결과 조회의 성공 조건이 아니다.

**검증 가능한 결과:**
- 광고 미채움, 차단, 로드 오류, 사용자 동의 거부 또는 광고 공급자 장애 시 광고 없이 갱신 결과를 표시한다.
- 광고 대기·닫기·실패 때문에 정상 동기화 결과가 유실되거나 다시 계산되지 않는다.
- API 자격정보, UTA 현재가치, 계획값, 수익률, 외부 자금흐름과 신뢰 상태를 광고 타기팅 또는 광고망 요청에 포함하지 않는다.
- MVP 광고는 화면·페이지의 일반 문맥만 사용하는 문맥형 광고로 한정하고, 개인 맞춤형·행태 기반 광고를 사용하지 않는다.
- 광고망에 전달되는 IP, 사용자 에이전트, 쿠키·로컬 저장소, URL, 페이지 제목, 동의 상태와 공급자 식별자를 데이터 흐름표로 관리한다. URL·페이지 제목·광고 슬롯명에는 금융값이나 사용자 식별자를 포함하지 않는다.
- 제3자 광고 요청 전 필요한 동의를 받고 비개인화 모드를 적용한다. 출시 전 실제 네트워크 요청을 검사해 허용된 필드 이외의 금융·계획·사용자 데이터가 전달되지 않는지 검증한다.
- 광고 공급자가 대시보드 본문 또는 DOM을 문맥 분석해야만 동작한다면 해당 공급자를 사용하지 않는다.
- 광고 기능을 전역 비활성화해도 핵심 제품 기능이 정상 동작한다.
- 실제 광고가 키보드·스크린리더 접근성 승인 조건을 만족하지 못하거나 광고 영역 밖으로 키보드 포커스를 이동할 수 없으면 광고를 건너뛰고 저장된 최신 결과를 표시한다.
- 광고 동의 철회는 다음 광고 요청부터 적용하며 핵심 기능을 제한하지 않는다.
- 광고가 실패하거나 건너뛰어져도 빈도 제한을 우회하기 위한 자동 재요청을 하지 않는다.

### 5.7 격리와 비상정지

#### FR-16: 범위별 격리

운영자는 입력 문제·계산 문제·공통 장애의 영향 범위에 따라 계획, 계산 버전, 연결 또는 동기화를 격리할 수 있다.

**검증 가능한 결과:**
- 개별 입력 문제는 해당 계획만 공식 갱신에서 제외한다.
- 공통 계산 문제는 해당 계산 버전의 결과 표시를 중단한다.
- 공통 원인이거나 영향 범위를 특정할 수 없으면 신규 연결과 동기화를 전역 중단한다.
- 쓰기 권한 키 입력은 전역 중단이 아니라 해당 연결 시도만 거부한다.

#### FR-17: 자동·수동 정지와 복구

시스템과 운영자는 중대 신호 발생 시 연결, 동기화, 계산 표시를 독립적으로 중단하고 수동 검증 뒤 복구할 수 있다.

**검증 가능한 결과:**
- 정의된 강한 신호를 탐지한 후 60초 이내 자동 정지한다.
- 운영자는 5분 이내 신규 연결과 동기화를 전역 정지할 수 있다.
- 정지 원인, 시작·종료 시각, 영향 범위, 수행자를 감사 기록으로 남긴다.
- 자동 복구하지 않고 검증된 복구 조건을 충족한 뒤 수동으로 재개한다.

### 5.8 인증·계정 삭제·지원

#### FR-18: 소셜 인증과 로그인 수단 관리

사용자는 Google·네이버·카카오의 OpenID Connect(OIDC) 로그인 중 하나로 가입·로그인할 수 있고, 로그인된 설정에서 재인증을 거쳐 다른 제공자를 같은 BokriLog 사용자 계정에 연결하거나 마지막 수단이 아닌 연결을 해제할 수 있다.

**검증 가능한 결과:**
- MVP는 Google·네이버·카카오 3개 제공자를 지원하고 BokriLog 비밀번호·이메일 링크·SMS 로그인은 제공하지 않는다.
- 신규 외부 식별자는 일반 로그인 콜백에서 새 계정으로 처리하며 로그인된 계정에서 시작한 명시적 연결 절차에서만 기존 `user_id`에 추가한다.
- 로그인 수단 추가는 현재 연결 수단 재인증과 새 제공자 인증을 모두 성공한 뒤 원자적으로 완료한다.
- 마지막 로그인 수단은 해제할 수 없다.
- Bybit 연결 생성·교체·해제, 로그인 수단 연결·해제, 계정 삭제와 의심 세션 이후에는 최근 인증을 요구한다.
- 제공자 취소·거부·장애·콜백 검증 실패 시 계정이나 연결 상태를 바꾸지 않으며 다른 제공자를 자동 선택하지 않는다.
- 소셜 제공자에는 인증에 필요한 최소 정보만 요청하고 Bybit 자격정보, 금융값, 계획과 조정 이력을 전달하지 않는다.

#### FR-19: 사용자 계정 삭제

사용자는 최근 인증과 명시적 확인을 거쳐 BokriLog 계정 삭제를 요청할 수 있다. 완료되면 모든 세션을 종료하고 사용자·금융 데이터를 다시 조회할 수 없게 한다.

**검증 가능한 결과:**
- 소셜 로그인 연결·제공자 토큰, Bybit 자격정보, 계획, 외부 자금흐름, 스냅샷, 계산 결과·버전과 광고 동의를 운영 데이터에서 삭제한다.
- 법률상 필요한 최소 보안·관리자 접속기록만 대상·근거·목적·기간을 확정해 사용자 데이터와 분리 보관하고 Bybit 자격정보나 금융 상세값을 포함하지 않는다.
- 삭제된 계정의 백업은 서비스 복구에 사용하지 못하게 격리하고 삭제 요청일부터 최대 30일 안에 파기한다.
- 화면과 개인정보 처리방침은 운영 데이터 삭제 시점, 백업 파기 예정일, 법정 분리 보존 대상·목적·기간을 구분해 알린다.
- 일부 삭제 실패를 완료로 표시하지 않고 중복 요청과 삭제 중 민감 화면 접근을 차단한다.

#### FR-20: 사용자 지원과 장애·복구 공지

사용자는 웹 문의 폼 또는 공개 지원 이메일 중 최소 하나로 문의할 수 있고, 서비스는 접수 사실과 영업일 기준 3일 이내 답변 목표를 안내한다. 전체 또는 범위별 장애·복구 상태는 인증 후 서비스 내부 공지로 확인할 수 있다.

**검증 가능한 결과:**
- 문의 채널, 접수 상태와 예상 답변 기한을 설정 및 오류·서비스 제한 화면에서 제공한다.
- 장애 공지는 시작 시각, 영향 범위, 사용 가능한 기능, 다음 갱신 예정 또는 복구 시각을 포함하며 금융 상세값을 포함하지 않는다.
- 복구 후에는 종료 상태와 종료 시각을 같은 공지 채널에 남긴다.
- `영업일`은 대한민국의 월요일부터 금요일 중 법정 공휴일을 제외한 날이며, 답변 기한은 접수 다음 영업일부터 세어 세 번째 영업일 종료 시각까지다. 자동 접수 응답은 이 기한을 날짜로 계산해 알린다.

## 7. 비기능 요구사항

### 7.1 계산 정확성과 재현성

- **NFR-1:** 동일한 원 입력·스냅샷·계산 버전은 언제나 동일한 결과를 생성해야 한다.
- **NFR-2:** 모든 공식 지표는 스냅샷 ID, 계산 버전, 기준 시각과 외부 자금흐름 이력으로 재현 가능해야 한다.
- **NFR-3:** 정상, 0·음수, 소액·대규모, 동일 시각 다중 사건, 지연 사건, 중복 사건, 비-USDT 결측, 계획 종료를 포함한 고정 계산 예제의 배포 전 회귀 통과율은 100%여야 한다.
- **NFR-4:** 금액과 비율은 정확한 십진수로 계산하고 표시 단계에서 한 번만 반올림해야 한다.
- **NFR-5:** 중대 계산 오류는 공개 베타 기간 0건이어야 한다.

### 7.2 보안과 개인정보

- **NFR-6:** 읽기 전용 검증은 모든 연결 시도에서 실행되어야 하며 실행률은 100%여야 한다.
- **NFR-7:** 자격정보는 전송 중 보호하고 저장 시 암호화하며 암호화 키와 데이터 접근 권한을 분리해야 한다.
- **NFR-8:** Bybit 자격정보, 세션 비밀, 소셜 제공자 액세스·ID·리프레시 토큰과 금융 상세값은 화면, URL, 브라우저 저장소, 로그, 오류 추적, 분석과 광고 도구에 기록하지 않아야 한다.
- **NFR-9:** 모든 데이터 요청은 내부 `user_id` 소유권을 서버에서 검증하며 교차 사용자 접근 허용은 0건이어야 한다. `(issuer, subject)`는 전역 유일해야 하며 이메일 일치 자동 병합은 금지한다.
- **NFR-10:** 계정 삭제 시 소셜 인증 연결·제공자 토큰·Bybit 자격정보와 모든 사용자·금융·계획·계산 데이터를 운영 환경에서 삭제하고 세션을 폐기해야 한다. 법률상 필요한 최소 기록은 대상·법적 근거·목적·기간을 고지해 분리 보관하며, 삭제 계정의 백업은 최대 30일 이내 파기해야 한다.
- **NFR-11:** 공개 베타 전 법률·개인정보 검토를 완료하고, 광고 또는 데이터 흐름이 바뀌면 재검토해야 한다.

### 7.3 신뢰성·성능·사용성

- **NFR-12:** 동기화 성공률은 전체 유효 동기화 시도 중 95% 이상이어야 한다. 성공은 필수 API 구간·페이지 검증과 원자적 스냅샷 확정을 모두 완료한 경우다. 사용자 취소와 중복 억제 요청은 분모에서 제외하고 Bybit 오류는 포함한다.
- **NFR-13:** 동기화 요청 후 1초 이내 진행 상태를 표시하고, 실패 또는 성공 시 기존 화면이 서로 다른 스냅샷의 값을 섞어 보여주지 않아야 한다.
- **NFR-14:** 일반 모바일·데스크톱 환경에서 핵심 화면은 75백분위 기준 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하를 목표로 한다. 외부 광고가 이 기준을 깨뜨리면 광고를 비활성화할 수 있어야 한다.
- **NFR-15:** 핵심 계산값·상태·동기화·광고 닫기·광고 후 결과 이동은 키보드로 접근 가능하고 색상만으로 상태를 구분하지 않아야 한다.
- **NFR-16:** 실제 광고 소재는 iframe 밖에서 즉시 사용할 수 있는 닫기 조작, 논리적이고 가시적인 포커스 순서, 광고 영역 밖으로의 키보드 포커스 이동, 스크린리더가 읽을 수 있는 광고·닫기 이름, 자동재생 음성과 과도한 깜빡임 방지, 확대·리플로 지원, 오류·시간초과 시 결과 화면으로의 fail-open을 검증해야 한다. 광고 닫기는 동기화 조작과 충분히 분리돼야 한다.

### 7.4 운영성과 복구

- **NFR-17:** 신규 연결·동기화·계산 표시·광고를 독립적으로 정지할 수 있어야 한다.
- **NFR-18:** 베타 전 1회 이상 백업 복원 시험을 완료하고, 사용자 계정·계획·외부 자금흐름·스냅샷·계산 버전을 복원할 수 있어야 한다. 이미 삭제된 계정은 복원 후 서비스 활성 데이터로 되살아나지 않아야 하며 삭제 격리 목록과 최대 30일 파기 일정도 유지돼야 한다.
- **NFR-19:** 베타 전과 이후 월 1회 비상정지 훈련을 수행하며 성공률은 100%여야 한다.
- **NFR-20:** 안정화 후 운영 시간은 최근 4주 평균 주 2시간 이하여야 한다. 운영 시간에는 문의 접수·답변, 장애 공지 갱신, 경보 확인, 정기 API·광고·개인정보 점검, 백업·정지 훈련과 예정 유지보수를 포함한다. 영업일 기준 3일 이내 답변 목표 달성률을 측정한다. 월 인프라 비용은 30,000원 이하여야 하며 신규 기능 개발 시간과 실제 중대 사고 대응 시간은 별도로 기록한다.
- **NFR-21:** Bybit API 변경내역과 지원 사건 유형을 정기 재검증하며 미인식 유형은 기본 거부해야 한다.

## 10. 성공 기준

판단 시점은 공개 베타 Day 60이며 결과는 계속, 중단 또는 재설계다. Day 60은 첫 외부 베타 사용자가 가입할 수 있게 된 공개 시점부터 계산한다.

Day 60에는 광고 수익과 별개로 고정 IP 전환 가능 여부를 판단한다. Day 90 이후에는 IP 제한이 없는 Bybit API 키를 사용하는 신규 연결 요청을 받지 않는다.

### 10.1 핵심 성공 지표

- **SM-1 표본:** 유효 테스트 사용자 12명 이상. 유효 사용자는 서로 다른 실제 사람으로, 소셜 로그인으로 사용자 계정을 만들고 온보딩을 시작한 사람이다. FR-1~FR-4와 FR-18을 검증한다.
- **SM-2 활성화:** 온보딩을 시작한 유효 테스트 사용자의 80% 이상이 읽기 전용 연결과 계획 생성을 완료한다. 활성화 완료 시점은 FR-4의 계획 생성 성공 시각이다. FR-2, FR-4를 검증한다.
- **SM-3 반복 가치:** 활성화 사용자의 50% 이상이 활성화 후 첫 28일 동안 서로 다른 3개 주에 각각 한 번 이상 대시보드 정상 조회를 완료한다. 정상 조회는 로그인 후 공식 또는 마지막 정상 스냅샷과 신뢰 상태가 표시된 경우다. FR-6, FR-11, FR-12를 검증한다.
- **SM-4 연결 품질:** 유효 동기화 시도의 95% 이상이 NFR-12의 성공 정의를 충족한다. FR-6, FR-7을 검증한다.
- **SM-5 이해 가능성:** 사용자 과업 평가 참가자의 80% 이상이 현재 시점 계획금액, 계획 대비 차이, 외부 자금흐름 조정, 세 가지 신뢰 상태를 모두 올바르게 해석한다. FR-11, FR-12를 검증한다.
- **SM-6 1인 운영성:** 안정화 시점부터 지원·운영 시간이 주 2시간 이하이고 월 인프라 비용이 30,000원 이하이다. 안정화 시점은 최근 14일 동안 중대 사고가 없고 미해결된 치명적 결함과 높은 심각도의 결함이 모두 0건인 첫날이다. FR-16, FR-17, FR-20을 검증한다.
- **SM-7 안전 결과:** 중대 보안 사고, 소셜·Bybit 자격정보 노출, 쓰기 권한 키 수용, 교차 사용자 접근, 삭제 계정 복원과 중대 계산 오류가 각각 0건이다. FR-1~FR-3, FR-7~FR-12, FR-18~FR-19를 검증한다.
- **SM-8 안전 선행통제:** 읽기 전용 검증 실행률과 배포별 보안·계산 회귀 통과율은 100%다. FR-2와 NFR-3, NFR-6을 검증한다.
- **SM-9 정지 대응:** 강한 신호 탐지 후 자동 정지 60초 이내다. 수동 전역 정지는 공지된 베타 운영 대응 시간대 또는 정지 훈련 중 운영자에게 경보가 전달된 시각부터 정지 상태 확인까지 5분 이내이며, 베타 전·월 1회 훈련 성공률은 100%다. 24시간 수동 대응을 약속하지 않으며 대응 시간대 밖에서는 자동 정지를 일차 통제로 사용한다. FR-16, FR-17을 검증한다.

### 10.2 수익화 관찰 지표

- **SM-10 광고 도달:** 수동 동기화 성공 횟수, 30분·일일 제한으로 건너뛴 횟수, 광고 노출 요청·실제 노출 횟수, 미채움·차단·동의 거부·로드 오류·공급자 장애·접근성 실패 횟수, 광고 뒤 저장 결과 도달 여부와 광고 수익을 분리 측정한다. Day 60의 계속·중단 기준으로 사용할 최소 수익 목표는 두지 않는다. FR-14, FR-15를 검증한다.

### 10.3 역지표

- **SM-C1 광고 후 조회 포기율:** 전면광고가 실제 노출된 수동 동기화 중 사용자가 광고를 닫은 뒤 갱신 결과를 보지 않고 이탈한 비율을 측정한다. 15%를 초과하면 광고 빈도·시점을 재설계한다. SM-10을 견제한다.
- **SM-C2 신뢰 상태 무시율:** `검토 필요` 또는 `계산 불가` 상태를 본 사용자가 이를 공식 최신값으로 오해한 비율을 측정한다. 20%를 초과하면 상태 표현을 재설계한다. SM-5를 견제한다.
- **SM-C3 허위 활동 증가 금지:** 광고 노출만 늘리기 위한 자동 새로고침, 강제 재시도 또는 보상형 동기화를 제품이 유도하지 않는다. SM-10을 견제한다.
