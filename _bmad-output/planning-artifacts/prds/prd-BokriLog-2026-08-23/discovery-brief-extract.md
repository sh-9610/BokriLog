# 제품 브리프 소스 추출

> 유일한 원문: `brief-BokriLog-2026-08-16/brief.md`  
> 목적: MVP PRD 작성을 위한 사실·결정·가정·미정 사항의 추출. 아래 내용은 구현 제안이 아니라 브리프에 명시된 내용과 그 공백만 정리한다.

## 1. 제품 비전과 포지셔닝

- BokriLog는 복리 목표를 설정하고 Bybit에서 현물 또는 USDT 무기한 계약 등을 운용하는 개인 투자자를 위한 **읽기 전용 웹 서비스**다.
- 최초 계획과 입출금 조정 이력을 보존하고, Bybit Unified Trading Account(UTA)의 공식 USD 환산 계정가치인 `totalEquity`를 계획선과 비교한다.
- 사용자가 답을 얻어야 하는 핵심 질문은 다음 세 가지다.
  - 오늘 계정가치가 얼마여야 하는가.
  - 현재 계획보다 얼마나 앞서거나 뒤졌는가.
  - 남은 기간 동안 어떤 등가수익률이 필요한가.
- 핵심 문제는 계산식 자체가 아니라 **기준선의 소실**이다. 현재 잔액으로 계산기를 다시 돌리면 최초 목표와 조정 이력이 사라지고, 거래 뒤 엑셀이나 계산기를 계속 갱신하는 흐름은 지속하기 어렵다.
- 제품은 범용 포트폴리오 분석기가 아니다. **계획 보존과 실제 계정가치 자동 비교**에 집중한다.
- 최초 계획은 움직이지 않으며, UTA 경계를 넘은 사용자 자본만 원금 조정으로 취급한다.
- 투자 행동을 추천하지 않고 수학적 차이를 중립적으로 보여준다.

## 2. 대상 사용자와 검증 목적

- 대상 사용자는 복리 목표를 세우고 Bybit의 현물 또는 USDT 무기한 계약 등을 운용하는 개인 투자자다.
- 계정 기준은 Bybit UTA다.
- 사용자는 목표 기간, 복리 주기, 주기별 목표율을 직접 정한다.
- 계획은 첫 정상 연결 시점부터 시작한다.
- 현재 근거는 창업자의 반복 경험과 Bybit 공식 API·관련 법령 검토다.
- 아직 검증되지 않은 가설:
  - 외부 수요
  - API 키 온보딩 가능성
  - 계산 및 상태 설명의 이해도
  - 시장성
- 공개 베타의 목적은 위 가설을 월 30,000원 이하의 운영비로 검증하는 것이다.
- 운영 성격은 1인 운영을 전제로 한 기준이 명시되어 있다.

## 3. 사용자 문제와 제공 가치

### 문제

- 현재 잔액으로 목표 계산을 다시 하면 최초 계획과 자금흐름 조정 이력이 사라진다.
- 거래 후 엑셀이나 계산기를 계속 갱신하는 수동 흐름은 유지하기 어렵다.
- 입출금과 계정 내 손익을 구분하지 않으면 성과와 원금이 혼동될 수 있다.
- API 입력이나 계산이 불완전한 상태에서 숫자를 공식 값처럼 보여주면 계산 신뢰가 훼손된다.

### 가치

- 최초 계획을 보존한다.
- 확인된 외부 자금흐름만 원금에 반영한다.
- UTA 전체의 공식 USD 환산 계정가치와 계획선을 자동 비교한다.
- 현재 위치, 오늘의 계획금액, 목표까지 필요한 수익률을 한 화면에서 판단하게 한다.
- 데이터 신선도, 입력 신뢰도, 계산 성격을 분리해 숫자의 신뢰 수준을 알린다.
- 읽기 전용 연결과 중립적 표현으로 거래 실행이나 투자 추천과 제품을 분리한다.

## 4. MVP 기능 범위

### 4.1 연결 및 자격정보

- 서버는 API 키의 `readOnly=1` 여부를 확인한다.
- 서버는 UTA·UID·IP 상태를 확인한다.
- 서버는 실제 조회 성공 여부를 검증한다.
- 쓰기 권한 키가 입력되면 저장 전에 **그 연결 시도만** 거부한다.
- `API Key`와 `API Secret`을 암호화한다.
- 자격정보를 화면, 로그, 분석 도구에 노출하지 않는다.
- 연결 해제 시 자격정보를 삭제한다.

### 4.2 계획 생성과 계획 보존

- 첫 정상 연결에서 조회한 `totalEquity`를 계획 시작점으로 사용한다.
- 사용자가 정한 기간, 복리 주기, 주기별 목표율을 고정하여 새 계획을 시작한다.
- 최초 계획을 움직이지 않고 보존한다.
- 과거 계획 자동 복원은 제공하지 않는다.

### 4.3 자금흐름 조정

- 확인된 UTA 경계 입출금만 원금을 조정한다.
- 입금은 수익이 아니다.
- UTA 내부의 다음 항목은 사용자 자본 유입·유출이 아니라 계정 성과로 취급한다.
  - 계정 내부 손익
  - 가격변화
  - 미실현손익
  - 펀딩비
  - 수수료
  - 이자
  - 리베이트
- 비-USDT 자금흐름은 이벤트 시점의 USD 가치와 추정 상태를 사용한다.

### 4.4 지표와 신뢰 상태

- UTA 전체의 USD 환산 `totalEquity`를 공식 현재가치로 사용한다.
- 다음 지표를 표시한다.
  - 현재가치
  - 오늘 계획금액
  - 부호 있는 차이
  - 조정 최종 목표
  - 남은 필요 등가수익률
  - 전체 목표 수익 달성도
- 다음 세 상태를 서로 독립적으로 표시한다.
  - 신선도
  - 입력 신뢰도
  - 계산 성격

### 4.5 동기화

- 다음 시점에 동기화한다.
  - 대시보드 진입
  - 탭 재활성화
  - 사용자의 명시적 새로고침
- 24시간 백그라운드 수집은 하지 않는다.

### 4.6 비상정지와 격리

- 사고 시 연결, 동기화, 계산 표시를 범위별로 중단할 수 있어야 한다.
- 불완전한 입력을 공식 계산으로 승격하지 않는다.
- 입력 문제라면 해당 계획을 격리한다.
- 공통 문제라면 해당 계산 버전을 격리한다.
- 공통 원인의 실패이거나 영향 범위를 특정할 수 없으면 신규 연결과 동기화를 전역 중단한 뒤 수동으로 복구한다.
- 쓰기 권한 키 입력은 해당 연결 시도만 거부한다.

### 4.7 베타 수익화

- 공개 베타는 사용자에게 무료로 제공한다.
- 문맥형 광고로 수익화한다.
- 금융정보를 광고 타기팅에 사용하거나 광고망에 전달하지 않는다.
- 광고 공급자, 배치, 도입 시점은 PRD 작성 및 출시 준비 단계에서 결정한다.
- 광고 결정은 개인정보, 보안, 화면 신뢰를 해치지 않아야 한다.

## 5. 수익률 및 계획 계산의 명시적 정의·가정

### 명시된 기준값과 분류

- **공식 현재가치:** Bybit UTA 전체의 공식 USD 환산 계정가치인 `totalEquity`.
- **초기 기준값:** 첫 정상 연결 시점의 `totalEquity`.
- **계획 입력:** 목표 기간, 복리 주기, 주기별 목표율.
- **계획 시작 시점:** 첫 정상 연결 시점.
- **원금 조정 대상:** 확인된 UTA 경계 입출금만.
- **수익이 아닌 항목:** 입금.
- **계정 성과로 취급할 항목:** 계정 내부 손익, 가격변화, 미실현손익, 펀딩비, 수수료, 이자, 리베이트.
- **비-USDT 자금흐름:** 이벤트 시점 USD 가치로 환산하며 추정 상태를 함께 사용.
- **비교 산출물:** 현재가치, 오늘 계획금액, 부호 있는 차이, 조정 최종 목표, 남은 필요 등가수익률, 전체 목표 수익 달성도.

### 브리프가 정의하지 않은 계산 세부

- 계획금액의 정확한 복리 수식과 기간 경계 처리.
- 복리 주기의 허용 단위와 주기별 목표율의 입력 단위·범위.
- 부분 주기 또는 당일 진행분을 오늘 계획금액에 어떻게 반영하는지.
- 입출금이 발생했을 때 계획선과 조정 최종 목표를 재계산하는 정확한 방식.
- 입출금 발생 시점이 복리 주기 중간인 경우의 시간 가중 방식.
- ‘부호 있는 차이’의 공식과 부호의 의미.
- ‘남은 필요 등가수익률’이 일·주기·전체 잔여 기간 중 어느 단위인지 및 정확한 공식.
- 잔여 기간이 0 이하이거나 현재가치가 0 또는 음수일 때 필요 등가수익률의 정의.
- ‘전체 목표 수익 달성도’의 분모·분자, 0%/100% 기준, 음수 및 100% 초과 표시 방식.
- 비-USDT 이벤트 시점 USD 가치의 가격 출처, 타임스탬프 기준, 환산 방식 및 가격 결측 처리.
- 동일하거나 중복된 입출금 이벤트 판별 기준.
- 출금의 범위와 원금 조정 하한, 출금이 누적 원금을 초과하는 상황의 처리.
- UTA 내부 이체와 UTA 경계를 넘는 입출금을 구분하는 상세 규칙.
- 계획 종료 시점 및 종료 이후 각 지표의 처리.
- 시간대, 날짜 전환, 윤년, 일광절약시간, 소수점 정밀도와 반올림 규칙.
- 계획 입력값의 수정 허용 여부와 수정 시 기존 계획 보존 방식.
- `totalEquity` 조회 실패 또는 부분 데이터일 때 마지막 정상값의 사용 여부.

## 6. 예외 상황과 오류·검토 상태

### 브리프에 명시된 예외 및 대응 원칙

- 쓰기 권한 키 입력: 저장 전에 해당 연결 시도만 거부.
- 불완전한 입력: 공식 계산으로 승격하지 않음.
- 개별 입력 문제: 해당 계획 격리.
- 공통 계산 문제: 해당 계산 버전 격리.
- 공통 원인의 실패 또는 영향 범위 특정 불가: 신규 연결과 동기화를 전역 중단하고 수동 복구.
- 비-USDT 가격 결측: 계산 신뢰 위험의 조기 신호로 명시됨.
- 사건 누락·중복: 계산 신뢰 위험의 조기 신호로 명시됨.
- 미지원 UTA 모드: 계산 신뢰 위험의 조기 신호로 명시됨.
- 신뢰 상태 불일치: 계산 신뢰 위험의 조기 신호로 명시됨.
- 비정상 복호화: 보안·운영 위험 신호.
- 쓰기 키 저장·사용: 보안·운영 위험 신호이며 허용되지 않음.
- 교차 사용자 접근: 보안·운영 위험 신호.
- 경보·훈련 실패: 보안·운영 위험 신호.
- Bybit API·정책 변경: 공개 베타 전 기술 스파이크와 운영 중 변경내역 재검증 대상.
- 개인정보·광고 데이터 흐름 변경: 법률·개인정보 재검토 대상.

### PRD에서 구체화하도록 브리프가 직접 지목한 항목

- 가입 범위와 지원 범위.
- 입력 범위.
- 오류 상태와 검토 필요 상태의 UX 및 인수 조건.
- 광고 배치.
- API 공백.
- 계획 종료 처리.

### 브리프에 상세 처리가 없는 주요 예외

- API 키 형식 오류, 만료, 폐기, 권한 변경, UID 불일치.
- IP 제한 불일치와 고정 IP 미지원 상태의 사용자 처리.
- 네트워크 실패, API 시간초과, 호출 제한, 부분 응답, Bybit 장애.
- 최초 연결 성공 후 첫 `totalEquity`가 0 또는 비정상 값인 경우.
- 동기화 중 이전 정상값과 신규값의 불연속 또는 비정상 급변.
- 여러 입출금이 같은 시점에 발생하거나 늦게 발견되는 경우.
- 과거 이벤트가 뒤늦게 수신되어 기존 계산을 바꾸는 경우.
- 계획 기간·주기·목표율 입력의 누락, 0, 음수, 과도한 값.
- 계획 만료, 조기 목표 달성, 목표 미달 종료.
- 연결 해제 후 계획과 비자격정보 데이터를 보존할지 여부.
- 사용자가 연결을 재생성하거나 다른 UID로 교체하는 경우.
- 광고 차단기, 광고 공급자 장애, 부적절한 광고 노출.

## 7. 비기능 요구사항으로 전환할 근거

### 보안과 개인정보

- 읽기 전용 키만 수용하며 검증 실행률 목표는 100%다.
- API Key와 API Secret은 암호화한다.
- 자격정보는 화면, 로그, 분석 도구에 노출하지 않는다.
- 연결 해제 시 자격정보를 삭제한다.
- 최소 수집과 복호화 감사를 적용한다.
- 교차 사용자 접근을 중대 위험으로 취급한다.
- 금융정보를 광고 타기팅에 사용하거나 광고망에 전달하지 않는다.
- 공개 베타 전 법률·개인정보 검토를 수행하며, 데이터 흐름 변경 시 재검증한다.

### 신뢰성·정확성·감사가능성

- Bybit 공식 `totalEquity`를 공식 현재가치로 삼는다.
- 최초 계획과 입출금 조정 이력을 보존한다.
- 불완전한 입력을 공식 계산으로 승격하지 않는다.
- 신선도, 입력 신뢰도, 계산 성격을 독립적으로 표시한다.
- 배포별 보안·계산 검증 통과율 목표는 100%다.
- 중대 계산 오류 목표는 0건이다.

### 가용성·동기화 품질

- 동기화 성공률 목표는 95% 이상이다.
- 상시 수집은 하지 않고 대시보드 진입, 탭 재활성화, 명시적 새로고침에서 동기화한다.
- 강한 신호 탐지 후 60초 이내 자동 정지해야 한다.
- 5분 이내 수동 전역 정지가 가능해야 한다.

### 운영성·비용

- 안정화 후 지원·운영 시간은 주 2시간 이하여야 한다.
- 월 인프라 비용은 30,000원 이하여야 한다.
- 베타 전 및 월 1회 비상정지 훈련 성공률 목표는 100%다.
- 공통 실패 시 전역 중단 뒤 수동 복구하는 운영 통제가 필요하다.

### 사용성·설명 가능성

- 사용자의 80% 이상이 계획금액, 현재 차이, 자금흐름 조정, 신뢰 상태를 올바르게 해석해야 한다.
- 투자 행동을 추천하지 않고 수학적 차이를 중립적으로 표현해야 한다.
- 광고는 화면 신뢰를 해치지 않아야 한다.

### 외부 의존성과 변경 대응

- Bybit API·정책 변경을 운영 중 재검증한다.
- 공개 베타 전 기술 스파이크를 수행한다.
- 개인정보·광고 데이터 흐름 변경을 재검토한다.

### 계산과 데이터의 모호점

- 수익률 관련 정확한 수식, 주기 경계, 자금흐름 조정 방식이 없다.
- UTA 경계 입출금의 ‘확인됨’ 기준이 없다.
- 비-USDT 이벤트 가치가 ‘추정’일 때 공식 계산에 포함 가능한 조건이 없다.
- 신선도·입력 신뢰도·계산 성격의 상태값과 상태 전이 기준이 없다.
- 지원하는 UTA 모드와 현물·USDT 무기한 계약 ‘등’의 정확한 지원 범위가 없다.
- 과거 계획 자동 복원은 제외되지만 계획 및 조정 이력의 보존 기간과 복구 정책은 없다.
- 연결 해제 시 자격정보 삭제는 명확하지만 계획 및 계산 데이터 처리 방침은 없다.

### 제품·운영의 모호점

- 단일 사용자가 여러 UTA/계획을 가질 수 있는지 없다.
- 사용자 계정 가입·로그인·탈퇴와 데이터 삭제 범위가 없다.
- 동기화 빈도 제한, 중복 요청, 실패 재시도, 사용자에게 보여줄 마지막 정상 시점이 없다.
- ‘강한 신호’의 정의와 자동 정지 범위가 없다.
- 범위별 중단 단위와 수동 복구 승인·절차가 없다.
- 사용자 지원 채널과 사고 공지 방식이 없다.
- 문맥형 광고의 문맥이 금융정보와 분리되는 정확한 기준이 없다.

### 성공 측정의 모호점

- 테스트 사용자 모집 기준과 12명 표본의 유효성 조건이 없다.
- 활성화, 재방문, 동기화 성공, 올바른 해석의 측정 이벤트와 분모가 없다.
- ‘첫 4주’의 시작점이 가입·연결·계획 생성 중 무엇인지 없다.
- 중대 보안 사고와 중대 계산 오류의 등급 기준이 없다.
- ‘안정화 후’의 시작 시점과 운영시간 집계 범위가 없다.
- Day 60의 기산점이 서비스 공개일인지 사용자별 시작일인지 없다.

### 잠재적 긴장 또는 경계 확인 필요

- 제품은 사용자에게 무료이고 광고로 수익화하지만 광고 공급자·도입 시점은 미정이다. 따라서 ‘광고 포함’이 MVP 출시 필수인지 베타 중 도입 가능한지 브리프만으로 확정할 수 없다.
- 불완전한 입력은 공식 계산으로 승격하지 않는 원칙과 비-USDT 자금흐름에 추정값을 사용하는 방침 사이에는, 추정값을 허용할 신뢰 기준이 추가로 필요하다는 긴장이 있다.
- 24시간 수집을 하지 않으면서 입출금 사건 누락·중복을 막고 이벤트 시점 USD 가치를 복원해야 하므로, API가 제공하는 과거 데이터의 범위와 품질이 검증되어야 한다. 브리프는 이를 기술 스파이크/API 공백 항목으로 남긴다.
- 최초 계획은 고정·보존하지만 입출금으로 원금과 최종 목표를 조정한다. ‘고정’의 대상이 원래 계획 입력·원래 계획선인지, 조정 전후 선을 모두 보존한다는 뜻인지 정확한 표현은 없다.
- 대시보드 진입·재활성화·새로고침 동기화와 동기화 성공률 95% 목표가 있으나, 요청 단위와 성공 판정 기준이 정의되지 않았다.
