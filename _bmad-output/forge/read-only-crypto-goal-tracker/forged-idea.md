# BokriLog — Forge 인계 커널

> **HARDENED**는 핵심 사용자·제품 경계·MVP 범위·위험 수용 원칙이 잠겼다는 뜻이다. 아래 `OPEN-*` 계산 예외와 운영 규칙까지 완료됐다는 뜻이 아니며, 시장성·법률 준수·보안·계산 정확성·Bybit API 지속성 또는 투자 성과를 보증하지 않는다.

## 현재 프로젝트 상태

- **존재함:** Forge 결정 원장과 시각 보고서
- **존재하지 않음:** 외부 사용자 검증, Product Brief, PRD, UX 명세, 계산 SPEC, 아키텍처, 코드, 배포, 운영·법률 문서
- **기준 문서:** 이 파일이 정본이다. `forge-report.html`은 같은 결정을 사람이 읽기 쉽게 표현한 파생 보고서다.
- **한 문장 제품:** 사용자가 정한 복리 계획을 보존하고, Bybit 읽기 전용 연동으로 가져온 USD 환산 Unified 계정가치와 비교해 현재 목표 위치를 자동으로 보여주는 웹 서비스

## 계산 커널

`E₀`는 시작 계정가치, `r`은 주기별 목표율, `N`은 전체 주기 수, `p(t)`는 시각 `t`까지 지난 연속 주기 수, `Cᵢ`는 시각 `tᵢ`의 USD 환산 외부 자금흐름(입금 `+`, 출금 `-`)이다.

```text
현재 계획금액 G(t)
= E₀ × (1+r)^p(t)
  + Σ[Cᵢ × (1+r)^(p(t)-p(tᵢ))]

조정 최종 목표 G(T)
= E₀ × (1+r)^N
  + Σ[Cᵢ × (1+r)^(N-p(tᵢ))]

현재 차이 = totalEquity - G(t)

남은 필요 등가율
= (G(T) / totalEquity)^(1 / 남은 주기 수) - 1

누적 계정 성과금액 = totalEquity - E₀ - ΣCᵢ
최종 목표 성장금액 = G(T) - E₀ - ΣCᵢ
전체 목표 수익 달성도 = 누적 계정 성과금액 / 최종 목표 성장금액

현금흐름 구간 Modified Dietz 추정수익률
R_MD = [V₁ - V₀ - ΣCᵢ] / [V₀ + Σ(wᵢ × Cᵢ)]
wᵢ = (t₁ - tᵢ) / (t₁ - t₀)
```

Modified Dietz의 `Cᵢ`는 입금 양수·출금 음수다. 이 계산의 시간대·달력·정밀도·0/음수 분모·잔여 주기 0 같은 산술 경계는 `OPEN-005`에서 명세해야 한다.

## 다음 BMAD 워크플로 인계 규칙

1. 다음 권장 단계는 **`bmad-prd`**다. PRD는 `OPEN-001`~`OPEN-018` 중 MVP·공개 베타 전에 필요한 항목을 결정하고 acceptance criteria로 바꾼다.
2. 계산 구현 전 **계산 SPEC 또는 동등한 명세**에서 `OPEN-004`~`OPEN-007`, `OPEN-015`~`OPEN-017`을 닫아야 한다.
3. 공개 베타 전 아키텍처·보안·개인정보 작업에서 `OPEN-009`, `OPEN-010`, `OPEN-012`, `OPEN-018`을 닫아야 한다.
4. `INV-*`, `DEC-*`는 구체화할 수 있지만 묵시적으로 변경할 수 없다. 변경이 필요하면 영향과 이유를 적은 Forge 변경안부터 만든다.
5. `REJ-*`나 `NG-*`를 단순 백로그로 되살리지 않는다. 재검토 조건이 충족됐는지 먼저 확인한다.
6. API 조사 결과가 상위 불변식과 충돌하면 구현 편의를 위해 산정 의미를 바꾸지 말고 제품 결정을 다시 연다.
7. 아직 구현 허가는 내려지지 않았다. 이 산출물은 요구사항·설계·코드가 아니라 **제품 방향 입력물**이다.
