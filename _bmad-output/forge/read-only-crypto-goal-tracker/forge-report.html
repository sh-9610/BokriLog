01

Forge 판정

제품의 중심과 경계가 서로 충돌하지 않는다.

HARDENED — 최초 계획을 보존하고, UTA 전체 USD 환산 계정가치로 현재 위치를 추적한다.

핵심 사용자, 제품 경계, MVP 범위와 공개 베타 위험 수용 원칙이 결정됐다. 계산 예외·운영 규칙·아키텍처에는 아래 OPEN-* 항목이 남아 있으며 서비스 구현은 시작하지 않았다.

보증하지 않는 것

법률 준수, 보안 무결성, 계산 무오류, API 지속성, 사업성 또는 투자 성과를 인증하지 않는다.

직접 검증할 것

사용자가 목표 차이를 반복 확인하는지, 읽기 전용 키 등록 마찰을 견디는지, 한도 없는 베타를 1인이 운영 가능한지 확인한다.

바꾸면 재검토할 것

다중 거래소, 상품별 분석, 과거 계획 복원, 24시간 수집, 거래 추천은 MVP 확장이 아니라 방향 변경이다.

03

누구의 어떤 문제인가

계산기는 있지만, 보존되는 계획과 실제 비교가 없다.

첫 사용자

  • 월·주 단위 복리 목표를 직접 세우는 Bybit 개인 투자자
  • 현물이나 USDT 무기한을 쓰되 전체 계정 기준으로 성과를 보고 싶은 사람
  • 매 거래 뒤 엑셀이나 계산기를 다시 입력하지 않을 사람

깨지는 순간

사용자가 현재 잔액을 새 원금으로 복리 계산기에 넣을 때마다 최초 목표와 조정 이력이 사라진다. 목표가 현실을 평가하는 기준이 아니라 현실에 맞춰 계속 움직이는 숫자가 된다.

핵심 가치는 복리 계산이 아니라 계획 보존 + 자동 실제값 비교다.

수동 입력은 보조 경로가 아니라 반복 사용을 무너뜨리는 마찰로 판단했다. 거래소 읽기 전용 연동은 편의 기능이 아니라 제품의 중심이다.

05

자금흐름과 성과의 경계

원금을 수익으로 세지 않고, 입금 뒤 가격변화는 성과로 센다.

UTA 경계를 넘은 것으로 확인된 사용자 자본만 원금을 조정한다.

거래손익, 가격변동, 미실현손익, 펀딩비, UTA에서 실제 차감된 수수료, 이자와 리베이트는 계정 성과다. UTA 도달 전 외부에서 차감된 비용과 차입·상환은 원금 조정이 아니다. 보너스·보상은 ‘기타 계정 증감’으로 구분하지만 전체 계정가치에는 포함한다. cashFlow 부호만으로 분류하지 않으며 동일 자금이 입금·이체 기록 양쪽에 있어도 UTA 경계 사건 한 번만 센다.

비-USDT 입금 예시

0.1 BTC가 들어올 때 BTC가 60,000 USD라면 6,000 USD는 새 원금이다. 이후 BTC가 70,000 USD가 되며 생긴 1,000 USD는 계정 성과다.

자산·수량·시각은 거래소 기록, USD 가치는 이벤트 시점에 가장 가까운 Bybit 가격으로 추정한다.

출금과 종료

사용자 자본 출금은 남은 기간 목표에서 대칭적으로 차감한다. UTA에서 실제 차감된 수수료는 성과 비용이다. 확인된 출금 뒤 G(t)≤0이거나 V(t)≤0으로 계정가치가 남지 않으면 마지막 신뢰 동기화 시점에 종료한다. 먼지 잔액 기준은 OPEN-005다.

입력 신뢰도

검증됨필요 사건과 가치가 신뢰 가능한 기록으로 확인됐다.
추정치 포함비-USDT 이벤트 가격 등 일부 입력이 추정됐다.
검토 필요분류가 모호하거나 사건 누락 가능성이 있어 공식 계산을 확정할 수 없다.

신선도 축

최신 또는 stale. 마지막 REST 스냅샷 시각과 함께 표시한다.

계산 성격 축

정확 구간수익률 또는 Modified Dietz 추정. 입력이 검증돼도 계산은 추정일 수 있다.

수익률의 정직한 표시

외부 현금흐름이 없는 구간은 정확 구간수익률을 표시한다. 현금흐름이 있는 구간은 R_MD = [V₁−V₀−ΣCᵢ] / [V₀+Σ(wᵢ×Cᵢ)]인 Modified Dietz 추정 수익률로 표시하며 정확 TWR이라고 부르지 않는다. 분모가 0 이하이거나 사건이 불완전하면 산출하지 않는다.

MVP 경험과 범위

연결은 한 번, 확인은 반복해서.

최초 연결

읽기 전용 키 검증 → 현재 totalEquity 확인 → 목표 기간·주기·수익률 입력 → 최초 스냅샷에서 계획 시작.

자동 갱신

대시보드 진입, 탭 재활성화, ‘지금 새로고침’에서 동기화한다. 화면의 ‘현재’는 마지막 성공한 REST totalEquity 스냅샷이며 시각과 stale 여부를 항상 보인다.

후속 고도화

대시보드가 열린 동안만 준실시간 추정치를 제공하고 REST totalEquity와 대조한다. 24시간 수집은 하지 않는다.

  • 주문·출금·이체 실행
  • 과거 계획 자동 복원

보안 경계와 키 교체

읽기 전용은 자산 이동을 막지만 금융정보 유출까지 막지는 않는다.

연결 허용 조건

  • readOnly=1, UTA, UID, IP 상태, 실제 조회 성공 검증
  • 쓰기 권한 키는 거부
  • 주문·출금·이체 기능과 호출 경로 자체를 두지 않음
  • 허용 목록에 든 조회 API만 사용

자격정보 처리

  • Key·Secret 서버 암호화 저장
  • 로그·분석도구·화면 노출 금지
  • 연결 해제와 교체 완료 시 이전 암호문 삭제
  • 인증된 비공개 요청은 고정 출구 IP를 계속 사용

새 고정-IP 키 사전 검증 후 원자적 교체

1 · Old active기존 비제한 키는 계속 동작
2 · New pending새 고정-IP 읽기 전용 키 등록
3 · Verify권한·IP·UTA·동일 UID·잔액 확인

Bybit에 존재하는 이전 키의 폐기는 사용자가 Bybit에서 수행한다. 동일 UID는 재개의 필요조건일 뿐이며, 키 교체·만료 복구는 계획을 잇지만 사용자가 명시적으로 연결 해제한 뒤에는 동일 UID여도 새 계획이다.

08

공개 베타: 수용한 균열

숫자 한도 없이 운영하되, 시간 경계와 비상 정지는 유지한다.

IP 비제한 활성 연동 수에 한도를 두지 않는다.

실제 운영에서 유입, 장애, 비용과 지원 부하를 직접 경험하고 싶다는 제품 소유자의 명시적 선택이다. 이는 위험이 낮다는 판단이 아니다. 사용자 수와 함께 민감 금융정보의 노출면과 사고 영향범위가 커지는 것을 의식적으로 수용한 베타 운영 위험이다.

서로 다른 두 시계

서비스의 Day 0·60·90은 공개 베타 전체 운영 일정이다. 각 Bybit 키의 deadlineDay·expiredAt은 키 생성·연장 시점에 따른 개별 만료 정보다. 두 시계를 합쳐 해석하지 않는다.

Day 0IP 비제한 읽기 전용 키로 공개 베타
Day 60고정 IP가 준비되면 신규는 고정-IP만; 아니면 신규 연결 중단
Day 60–90준비된 경우 기존 사용자를 사전 검증 키로 이전

비상 정지

09

데이터 최소화와 금융 조언 경계

맞춤화를 위해 먼저 모으지 않는다. 목표의 차이를 행동 추천으로 바꾸지 않는다.

MVP 저장

  • totalEquity 스냅샷과 동기화 시각
  • 정규화 자금흐름·이벤트 ID
  • 목표 생성·조정·종료 이력
  • 계산 버전·신뢰 상태·암호화 자격정보

MVP 미저장

  • 원시 주문·체결·포지션 응답
  • 매매전략 추론 목적의 상세 행동 이력
  • 목적이 정해지지 않은 미래 활용용 데이터
  • 광고 타기팅을 위한 잔액·수익률·보유정보

허용 경계 · 실제 MVP 포함은 OPEN-013

공식 주지표는 목표 진행, 계정가치, 차이와 필요 등가수익률이다. 변동성, 최대 낙폭, 구성 비중은 허용 가능한 중립 통계 후보일 뿐 MVP 포함이 확정되지 않았다.

금지되는 행동 추천

종목, 매수·매도, Long·Short, 레버리지, 비중, 진입·청산 시점, 손실 회복 행동 또는 서비스가 선택한 적정 목표율.

“금융 조언이 아님”이라는 문구보다 실제 기능의 경계가 우선한다.

향후 맞춤 통계는 별도 옵트인과 동의 시점 이후의 최소 데이터로만 만든다. 광고는 금융정보를 사용하거나 광고망에 제공하지 않는 문맥형 배치만 허용한다.
