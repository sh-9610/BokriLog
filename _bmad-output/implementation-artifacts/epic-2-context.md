# Epic 2 Context: Bybit 자산으로 복리 계획을 기록하고 근거와 함께 비교하기

## Goal

읽기 전용 Bybit UTA 자산을 검증된 시작 기준으로 삼아 불변 복리 계획을 만들고, 완전하게 검증된 동기화·외부 자금흐름·계산 근거를 함께 기록해 계획의 진행과 종료 결과를 비교한다. 사용자는 마지막 정상값과 신뢰 상태를 확인하고, 실패 시 부분 데이터가 공식 결과처럼 보이지 않는 핵심 여정을 완료할 수 있다. 실제 계정·법률·개인정보 승인 등 출시 게이트는 구현 완료와 별도로 관리한다.

## Requirements & Constraints

- 모든 사용자 소유 조회·변경·작업·발행은 세션에서 얻은 내부 `user_id`로 범위를 제한한다. identity 삭제 상태와 durable 운영 제한은 연결, 계획 변경, 작업 수락, lease, 발행, 표시 경계에서 fail-closed로 확인한다.
- 연결은 읽기 전용 권한, 지원 UTA, UID, regional reserved IP, 실제 wallet 조회를 검증한 뒤에만 저장한다. 모호하거나 미지원인 권한·응답은 거부한다. 자격정보는 AES-256-GCM으로 암호화하고 비밀 원문을 다시 반환하거나 로그·브라우저 저장소에 남기지 않는다.
- 정상 현재가치는 Bybit `totalEquity` 원문과 제공자 측정 시각을 사용한다. 계획은 사용자 `USD` portfolio에 귀속되고 첫 정상 snapshot의 `P0`·`t0`를 고정한다. 계획 조건 미리보기 intent는 활성 계획이나 공식 계산 결과가 아니다.
- 외부 자금흐름은 허용된 UTA 사건과 방향·부호 규칙으로만 판정한다. 미인식 유형, 충돌, 필수 페이지 누락, 불완전 입력, 환산 결측은 공식 발행과 watermark 전진을 보류한다. 중복은 멱등 처리하고 정정은 새 사실·계산 버전으로 남긴다.
- `USD`·`USDT` 정규화 외 비-USDT 흐름은 지원되는 현물 경로의 사건 시각 기준 종료 candle로 환산한다. 허용 가능한 가격 근거가 없으면 현재가로 대체하지 않는다. 추정 가격을 사용하면 현재가치와 구분하고 의존 지표 전체에 추정 성격을 전파한다.
- 금액·비율·가격은 canonical decimal string 경계와 `BigDecimal`을 사용한다. 계산은 DECIMAL128 34자리 `HALF_EVEN`, 화면에서만 `HALF_UP` 2자리로 반올림한다. UTC instant를 저장하고 계획 경계와 사용자 표시는 `Asia/Seoul`을 따른다. 정의 불가·범위 초과 값은 0으로 치환하지 않는다.
- 원 사건·snapshot·계산 버전은 허용 보존기간에 추가 전용이다. 동일 입력·snapshot·정책 버전은 재현 가능해야 하며 공식 상태는 검증된 포인터로 한 묶음만 발행한다. 실패 시 마지막 정상 묶음과 원인·다음 행동을 보존한다.

## Technical Decisions

- 모듈형 모놀리스와 공개 API 경계를 유지한다. `source`는 연결·자격정보·Bybit adapter, `portfolio`는 membership·snapshot·현재 snapshot 포인터, `sync`는 작업·원천 사실·계산 버전·계획 결과 발행, `plan`은 불변 계획, `calculation`은 순수 결정 함수를 소유한다. 다른 모듈의 내부 entity·repository·table에 직접 접근하지 않는다.
- PostgreSQL 18을 업무 데이터와 작업 큐에 사용한다. 원천 사실 정체성은 안정적인 provider account와 사건 ID·revision으로 정하고 정정은 superseding fact로 추가한다. Worker는 lease·heartbeat·fencing을 사용하며 외부 호출 중 DB 트랜잭션을 열지 않는다.
- 작업 admission 때 Bybit 기준 상한 `tc`를 고정하고 wallet `measured_at`과 `cashflow_verified_through`를 분리한다. 닫힌 구간의 모든 페이지가 저장된 뒤에만 watermark를 전진시킨다. 30일 초과 공백은 사용자 선택 전에 호출하지 않으며, 2년 조회 한계를 넘어 복구할 수 없는 기존 계획은 마지막 정상 결과를 보존하고 복구 불가로 표시한다.
- 공식 발행은 짧은 단일 트랜잭션에서 후보 데이터, 계산과 포인터 변경을 함께 확정한다. lease 소유권, 삭제 상태, 제한, 소유권 및 예상 포인터 버전을 발행 직전 재검증한다. 계산·달력·표시 정책은 버전으로 저장하고 고정 회귀 벡터를 유지한다.

## UX & Interaction Patterns

- 최초 연결은 검증 단계를 보여주고 성공하면 비밀 입력을 제거한 뒤 정상 `totalEquity`와 측정 시각을 시작 기준으로 제시한다. 계획 기준 snapshot과 기준 시각은 읽기 전용이다. 확인 전 조건·기준 snapshot·정책을 요약하며 취소가 기본 포커스다.
- 현재가치, 여섯 계획 지표, 신뢰 상태는 같은 snapshot·계산 버전에서 원자적으로 갱신한다. 신선도·입력 신뢰도·계산 성격은 독립 축이며 상태명, 원인, 마지막 정상 시각, 영향과 다음 행동을 제공한다. 동기화 중에도 이전 정상 묶음을 유지한다.
- 완료 결과는 종료 후 첫 정상 관측 시각과 지연을 보존한다. 24시간 초과 관측이나 종료와 관측 사이 자금흐름이 있으면 완료 비교를 계산 불가로 표시하고 이후 현재가치와 완료 기록을 분리한다. 핵심 흐름은 광고 없이 결과로 이동한다.
- 핵심 기능은 키보드·스크린리더에서 사용할 수 있고 색상만으로 상태를 구분하지 않는다. 모바일 320 CSS px와 확대 환경에서 핵심 과업을 지원하며 금융값을 브라우저 영속 저장소에 두지 않는다.

## Cross-Story Dependencies

- 최초 비교의 핵심 순서는 **2.1 연결 → 2.2 정상 snapshot → 2.3 조건 intent → 2.4 완전 수집 → 2.5 판정 → 2.6 환산 → 2.7 계산·활성 계획·공식 발행**이다. 검증되지 않은 입력을 정상으로 가정하지 않는다.
- 2.8은 공식 발행 묶음을 표시하고 2.9·2.10은 같은 묶음의 계산·사건 근거를 제공한다. 2.11·2.12는 반복 증분 수집과 지연·정정 재계산을 확장한다. 2.13·2.14·2.15는 중도 종료·자연 완료·후속 계획을 다루며, 2.16은 연결 해제 뒤 기록을 읽기 전용으로 보존한다.
- Epic 1의 identity 삭제 상태 계약을 소비하고, Epic 3의 운영 restriction 판독 기반과 각 검사 지점을 이 Epic의 연결·작업·발행·표시 흐름에 포함한다. Epic 3은 운영자 제어를 확장하고 Epic 5는 전체 계정 삭제를 조정한다. 외부 계정·법률 승인은 자동 시험이나 개발 완료로 대체되지 않는다.
