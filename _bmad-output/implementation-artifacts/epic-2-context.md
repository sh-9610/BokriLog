# Epic 2 Context: Bybit 자산으로 복리 계획을 기록하고 근거와 함께 비교하기

## Goal

읽기 전용 Bybit UTA 자산을 검증된 시작 기준으로 삼아 불변 복리 계획을 만들고, 완전하게 검증된 동기화·외부 자금흐름·계산 근거를 함께 기록해 계획의 진행과 종료 결과를 비교한다. 사용자는 마지막 정상값과 신뢰 상태를 확인하고, 실패 시 부분 데이터가 공식 결과처럼 보이지 않는 핵심 여정을 완료할 수 있다. 연결 해제 뒤에도 같은 Bybit 계정으로 다시 연결해 보존된 계획의 동기화를 이어 갈 수 있다(보완 스토리 2.17). 실제 계정·법률·개인정보 승인 등 출시 게이트는 구현 완료와 별도로 관리한다.

## Requirements & Constraints

- 모든 사용자 소유 조회·변경·작업·발행은 세션에서 얻은 내부 `user_id`로 범위를 제한한다. identity 삭제 상태와 durable 운영 제한은 연결, 계획 변경, 작업 수락, lease, 발행, 표시 경계에서 fail-closed로 확인한다.
- 연결(재연결 포함)은 읽기 전용 권한, 지원 UTA, UID, regional reserved IP, 실제 wallet 조회를 검증한 뒤에만 저장한다. 모호하거나 미지원인 권한·응답은 거부한다. 자격정보는 AES-256-GCM으로 암호화하고 비밀 원문을 다시 반환하거나 로그·브라우저 저장소에 남기지 않는다.
- 정상 현재가치는 Bybit `totalEquity` 원문과 제공자 측정 시각을 사용한다. 계획은 사용자 `USD` portfolio에 귀속되고 첫 정상 snapshot의 `P0`·`t0`를 고정한다. 계획 조건 미리보기 intent는 활성 계획이나 공식 계산 결과가 아니다.
- 외부 자금흐름은 허용된 UTA 사건과 방향·부호 규칙으로만 판정한다. 미인식 유형, 충돌, 필수 페이지 누락, 불완전 입력, 환산 결측은 공식 발행과 watermark 전진을 보류한다. 중복은 멱등 처리하고 정정은 새 사실·계산 버전으로 남긴다.
- `USD`·`USDT` 정규화 외 비-USDT 흐름은 지원되는 현물 경로의 사건 시각 기준 종료 candle로 환산한다. 허용 가능한 가격 근거가 없으면 현재가로 대체하지 않는다. 추정 가격을 사용하면 현재가치와 구분하고 의존 지표 전체에 추정 성격을 전파한다.
- 금액·비율·가격은 canonical decimal string 경계와 `BigDecimal`을 사용한다. 계산은 DECIMAL128 34자리 `HALF_EVEN`, 화면에서만 `HALF_UP` 2자리로 반올림한다. UTC instant를 저장하고 계획 경계와 사용자 표시는 `Asia/Seoul`을 따른다. 정의 불가·범위 초과 값은 0으로 치환하지 않는다.
- 원 사건·snapshot·계산 버전은 허용 보존기간에 추가 전용이다. 동일 입력·snapshot·정책 버전은 재현 가능해야 하며 공식 상태는 검증된 포인터로 한 묶음만 발행한다. 실패 시 마지막 정상 묶음과 원인·다음 행동을 보존한다.
- 연결 생성·재연결·해제와 계획 중도 종료는 민감 행동이다. 재인증 뒤 5분 안에 발급된 일회성 허가(user·session·command·target·확인 hash 귀속)를 성공 트랜잭션에서 한 번만 소비하고 세션 ID를 회전한다. 연결 해제는 자격정보를 지우되 계획·자금흐름·snapshot·계산·근거를 계정 삭제 전까지 읽기 전용으로 보존한다.
- 재연결 정책: 같은 Bybit main UID는 기존 provider account를 재사용하고 활성 계획을 기존 watermark부터 해제 기간을 포함해 다시 동기화하며, 공백이 30일을 넘으면 자동 호출 없이 장기 미동기화 선택 정책을 따른다. 다른 main UID는 기존 활성 계획에 연결하지 않고(먼저 종료), 활성 계획이 없을 때만 새 provider account로 연결하며 이전 계정의 사건·snapshot을 새 계획 입력에 섞지 않는다. 사용자·portfolio당 활성 연결·membership은 하나다.
- IP 미제한 기존 연결은 Day 60 공지 뒤 Day 90부터 새 동기화와 재연결을 정지하고 마지막 정상 결과는 읽기 전용으로 유지한다.

## Technical Decisions

- 모듈형 모놀리스와 공개 API 경계를 유지한다. `source`는 연결·자격정보·Bybit adapter·provider account, `portfolio`는 membership·snapshot·현재 snapshot 포인터, `sync`는 작업·원천 사실·계산 버전·계획 결과 발행, `plan`은 불변 계획, `calculation`은 순수 결정 함수를 소유한다. 다른 모듈의 내부 entity·repository·table에 직접 접근하지 않는다.
- 검증된 Bybit main UID는 `provider=BYBIT`의 안정적인 provider account에 귀속하고 재연결은 그 account를 재사용하되 connection·credential·membership은 새로 만든다. 해제된 이전 connection 행과 과거 membership 구간은 바꾸지 않는다. 제공자 검증 호출은 트랜잭션 밖에서 끝내고 허가 소비·connection·credential·membership은 한 트랜잭션으로 커밋한다.
- PostgreSQL 18을 업무 데이터와 작업 큐에 사용한다. 원천 사실 정체성은 안정적인 provider account와 사건 ID·revision으로 정하고 정정은 superseding fact로 추가한다. Worker는 lease·heartbeat·fencing을 사용하며 외부 호출 중 DB 트랜잭션을 열지 않는다. 해제 이전 연결에 귀속된 늦은 Worker는 재연결 뒤에도 발행하지 못한다.
- 작업 admission 때 Bybit 기준 상한 `tc`를 고정하고 wallet `measured_at`과 `cashflow_verified_through`를 분리한다. 닫힌 구간의 모든 페이지가 저장된 뒤에만 watermark를 전진시킨다. 30일 초과 공백은 사용자 선택 전에 호출하지 않으며, 2년 조회 한계를 넘어 복구할 수 없는 기존 계획은 마지막 정상 결과를 보존하고 복구 불가로 표시한다.
- 공식 발행은 짧은 단일 트랜잭션에서 후보 데이터, 계산과 포인터 변경을 함께 확정한다. lease 소유권, 삭제 상태, 제한, 소유권 및 예상 포인터 버전을 발행 직전 재검증한다. 계산·달력·표시 정책은 버전으로 저장하고 고정 회귀 벡터를 유지한다.

## UX & Interaction Patterns

- 최초 연결은 검증 단계를 보여주고 성공하면 비밀 입력을 제거한 뒤 정상 `totalEquity`와 측정 시각을 시작 기준으로 제시한다. 계획 기준 snapshot과 기준 시각은 읽기 전용이다. 확인 전 조건·기준 snapshot·정책을 요약하며 민감 확인 대화상자는 취소가 기본 포커스다.
- 현재가치, 여섯 계획 지표, 신뢰 상태는 같은 snapshot·계산 버전에서 원자적으로 갱신한다. 신선도·입력 신뢰도·계산 성격은 독립 축이며 상태명, 원인, 마지막 정상 시각, 영향과 다음 행동을 제공한다. 동기화 중에도 이전 정상 묶음을 유지한다.
- 완료 결과는 종료 후 첫 정상 관측 시각과 지연을 보존한다. 24시간 초과 관측이나 종료와 관측 사이 자금흐름이 있으면 완료 비교를 계산 불가로 표시하고 이후 현재가치와 완료 기록을 분리한다. 핵심 흐름은 광고 없이 결과로 이동한다.
- 연결 해제 화면은 즉시 삭제·작업 취소·보존 범위와 Bybit 측 키를 원격 폐기하지 못한다는 한계를 중립적으로 설명한다. 재연결 화면은 최초 연결과 같은 입력·검증 흐름을 쓰고, 확인 단계에서 같은 계정이면 기존 계획을 이어 동기화함(30일 초과면 선택 필요)을, 다른 계정이면 거절 이유와 계획 종료 경로를 설명한다. 재연결 뒤 대시보드는 해제 표시를 거두고 동기화 조작을 되돌린다.
- 핵심 기능은 키보드·스크린리더에서 사용할 수 있고 색상만으로 상태를 구분하지 않는다. 모바일 320 CSS px와 확대 환경에서 핵심 과업을 지원하며 금융값을 브라우저 영속 저장소에 두지 않는다. 자격정보·main UID·금융 상세·행동 허가는 URL·로그·분석 payload에 싣지 않는다.

## Cross-Story Dependencies

- 최초 비교의 핵심 순서는 **2.1 연결 → 2.2 정상 snapshot → 2.3 조건 intent → 2.4 완전 수집 → 2.5 판정 → 2.6 환산 → 2.7 계산·활성 계획·공식 발행**이다. 검증되지 않은 입력을 정상으로 가정하지 않는다.
- 2.8은 공식 발행 묶음을 표시하고 2.9·2.10은 같은 묶음의 계산·사건 근거를 제공한다. 2.11·2.12는 반복 증분 수집과 지연·정정 재계산을 확장한다. 2.13·2.14·2.15는 중도 종료·자연 완료·후속 계획을 다루며, 2.16은 연결 해제 뒤 기록을 읽기 전용으로 보존한다.
- 2.17은 2.1(연결 검증), 2.11(증분 동기화·장기 미동기화 선택), 2.13·2.15(다른 계정일 때의 종료·후속 계획 경로), 2.16(해제 상태·`CONNECTION_REVOKED`)과 Epic 3의 `NEW_CONNECTION` 운영 제한 위에 올라간다. 2.17 전까지 해제 사용자의 새 연결 영구 차단은 승인된 편차였다.
- Epic 1의 identity 삭제 상태·재인증 허가 계약을 소비하고, Epic 3의 운영 restriction 판독 기반과 각 검사 지점을 이 Epic의 연결·작업·발행·표시 흐름에 포함한다. Epic 5는 전체 계정 삭제를 조정하며 이전·새 connection과 credential을 모두 제거해야 한다. 외부 계정·법률 승인은 자동 시험이나 개발 완료로 대체되지 않는다.
