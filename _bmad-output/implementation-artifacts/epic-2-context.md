## Goal

읽기 전용 Bybit 연결 검증부터 `BYBIT` source 하나를 담은 기본 `USD` portfolio, 불변 계획 생성, 신뢰할 수 있는 동기화와 외부 자금흐름 반영, 여섯 지표·근거 조회, 계획 종료와 후속 계획, 연결 해제까지를 하나의 사용자 흐름으로 완성한다. 제품의 핵심 가치를 처음으로 실제 금융 데이터 위에 올리면서 이후 모든 에픽이 쓸 기반 넷 — 제공자 계정·자격정보 소유 경계, 추가 전용 사실과 공식 버전 포인터, 작업 큐와 원자 발행, 결정적 십진 계산 정책 — 을 함께 들인다. 독립 완료 조건은 Epic 3의 운영자 화면과 Epic 4의 광고 없이 핵심 여정과 계획 생명주기가 작동하는 것이다. M2-1~M2-4는 시연 지점이지 출시 승인이 아니며, 실제 Bybit 검증 계정과 reserved IP 왕복은 별도 게이트가 소유한다(그전까지 **연결 정책·실연동 미검증**).

## Requirements & Constraints

- **연결 admission은 전부 통과해야 저장한다.** 읽기 전용 플래그, 메인 UID, 허용 목록에 포함된 운영 reserved IP, 빈 쓰기 permission, 지원 UTA 모드, 실제 지갑 조회 성공과 유효한 총자산. 하나라도 확인 불가·모호하면 저장 없이 fail-closed 거부하고 자동 재시도 escalation을 하지 않는다. 사용자당 활성 연결은 하나이고 신규 연결은 처음부터 IP binding을 요구한다.
- **자격정보는 AES-256-GCM·매번 새 96-bit nonce·정의된 AAD·active key version으로만 저장한다.** key ring은 DB·Git·로그 밖에서 주입하고 decrypt-only key 호환을 유지한다. 평문·부분 연결·응답 원문을 남기지 않는다. 비밀은 화면·URL·브라우저 저장소·로그·분석·광고·오류 응답 어디에도 두지 않으며 성공 뒤에도 마스킹 값조차 재표시하지 않는다.
- **재현성이 계약이다.** 같은 원 입력·스냅샷·계산 버전은 같은 결과를 내고 모든 공식 지표는 스냅샷 ID·계산 버전·기준시각·자금흐름 이력으로 재구성된다. 고정 회귀 벡터의 배포 전 통과율은 100%다.
- **실패를 0으로 대체하지 않는다.** 인증·권한·지원 제외·UID/IP·시간초과·rate limit·장애·응답 오류를 구분 가능한 오류와 다음 행동으로 표시하고 마지막 정상 묶음과 그 시각을 유지한다. 인증·permission·schema·semantic 오류는 자동 재시도하지 않는다.
- **연결 생성·재연결·해제와 계획 중도 종료는 민감 command다** — 재인증 5분 이내 발급된 일회성 허가를 요구하고 성공 시 세션 ID를 다시 회전한다. **데이터를 도입하는 스토리가 그 데이터의 삭제 경로와 시험을 함께 완성하며** 삭제 상태가 저장·허가 소비와 경쟁하면 삭제가 이긴다. 운영 성공률 95%는 자동시험이 아니라 실제 운영 계측으로 평가한다.

## Technical Decisions

- **모듈 소유권.** `source`=연결·자격정보·Bybit adapter, `portfolio`=membership·불변 snapshot·current pointer·발행 순번, `sync`=작업·source fact·source snapshot·계산 결과·plan별 공식 포인터, `plan`=불변 입력과 활성 계획 규칙, `calculation`=부작용 없는 순수 함수. adapter는 provider-neutral DTO만 돌려주고 계산 모듈은 Bybit 타입을 모른다.
- **계획은 connection이 아니라 portfolio에 귀속한다.** MVP는 자동 생성 `USD` portfolio 하나에 활성 `BYBIT` membership 하나뿐이고 membership 구간은 UTC 반개구간이라 겹칠 수 없다. 다중 source·기준통화 변경·transfer matching은 별도 승인 전까지 구현하지 않는다. **`provider_account_id`가 안정 식별자**이며 검증된 메인 UID로 만들고 자격정보·connection 교체에도 재사용한다 — connection ID는 수집 provenance일 뿐 사건 고유키가 아니다.
- **추가 전용 사실 + 검증된 버전 포인터.** 원 사건·자금흐름·스냅샷·계산 버전은 덮어쓰지 않고 정정은 새 superseding 버전이며 current 값을 `max(created_at)`으로 추론하지 않는다. 같은 revision 재수집은 no-op, 같은 ID의 핵심 필드 차이는 격리하고 자동 합산하지 않는다. 검증된 계정 삭제만 예외다.
- **작업 큐와 짧은 트랜잭션.** 동기화 API는 작업 생성·재사용만 커밋하고 202를 돌려준다. Worker가 lease·heartbeat·idempotency key·증가하는 fencing generation으로 소유권을 쥐고 외부 호출 동안 DB 트랜잭션이나 계정 잠금을 열지 않으며, lease를 잃은 Worker는 아무것도 발행하지 못한다. 동일 source 작업은 직렬이다.
- **공식 발행은 `sync`가 소유한 짧은 outer `REQUIRED` 트랜잭션 하나다.** portfolio command도 반드시 여기에 참여하고 `REQUIRES_NEW`·비동기·after-commit은 금지다. CAS 직전에 eligibility·lease·제한·삭제 상태를 재검사하고 component·계산·포인터 중 하나라도 실패하면 전부 롤백한다. MVP portfolio snapshot은 component 하나이며 그 USD 값이 source snapshot 총자산과 같고 측정 시각은 구성·발행 시각과 분리한다.
- **증분 수집.** 작업 admission 직후 제공자 시각으로 상한을 한 번 고정하고(실패하면 이력 작업을 시작하지 않는다) 창은 7일 이내 닫힌 구간, 인접 경계 중복은 source ID로 제거한다. **모든 page가 영속화된 뒤에만 watermark를 전진시키고 부분 page는 발행하지 않는다.** 30일 초과 공백은 사용자 선택 전에 호출하지 않고 조회 가능 범위 밖이면 `복구 불가`로 끝내며 마지막 정상 결과를 보존한다. 측정 시각과 자금흐름 확인 시각은 항상 분리 노출한다. 호출 예산은 공식 한도보다 보수적이며 IP ban은 전 세션 중단과 회로 차단이다.
- **판정·환산 allowlist를 자동 확대하지 않는다.** 정확한 두 유형과 부호가 맞는 사건만 외부 자금흐름이고 수량의 권위는 `cashFlow` 절대값 하나다. USD·USDT만 제품 정규화로 1 USD이고 나머지는 현물 종료 1분봉 종가(최대 5분 이전 fallback)로만 얻는다. 그 값을 쓴 파생 지표는 전부 `추정`이고 총자산 현재가치만 `공식`이다. 미인식·가격 결측은 사건을 버리지 않고 watermark와 공식 결과를 전진시키지 않는다.
- **십진수·시간.** 금액·비율·가격은 경계에서 canonical decimal string이며 JSON number·지수·NaN·locale separator를 거부한다. 계산은 `BigDecimal` + `MathContext(34, HALF_EVEN)`, 표시만 HALF_UP 2자리 한 번이다. 범위를 벗어난 값은 0으로 만들지 않고 범위 오류로 거부한다. 저장은 UTC instant, 계획 경계와 표시는 `Asia/Seoul`이고 주기 경계는 시작 시각에 고정되며 월말 규칙과 가법적 `periods`를 따른다. 사건 정렬은 `(effective_time, provider_account_id, source_id)`이고 같은 millisecond 사건도 모두 독립 보존한다.
- **제한 검사 지점은 이 에픽이 만든다** — admission·lease·publication·display 네 곳에서 유효한 운영 제한과 삭제 상태를 fail-closed로 확인한다. **소유권**은 세션의 내부 `user_id`가 모든 조회·명령·작업·발행을 scope하고 Worker와 발행 시점에도 재검증하며, 타 사용자·미존재 대상은 같은 외부 오류 계약을 쓴다.

## UX & Interaction Patterns

- **세 신뢰 축을 결합하지 않는다.** 신선도·입력 신뢰도·계산 성격은 독립으로 읽히고 `최신 + 검토 필요 + 계산 불가`가 가능하다. 각 축은 상태명·원인·마지막 정상 시각·영향 지표·다음 행동을 이 순서로 펼친다.
- **신선도 판정과 admission은 서버 권위다.** 측정 시각과 자금흐름 확인 시각이 둘 다 15분 이내여야 `최신`이다. 대시보드 진입은 공식 결과가 없거나 마지막 성공 admission 후 5분이 지났을 때만, 탭 재활성화는 5분 이상 hidden일 때만 자동 요청한다. 수동 cooldown은 결과와 무관하게 30초이고 진행 중·cooldown 요청은 외부 호출 없이 기존 job/result를 돌려준다. 클라이언트가 별도 시간 기준을 만들지 않으며 polling과 전 사용자 배치는 없다.
- **원자적 갱신.** 동기화 중에는 이전 묶음을 그대로 두고 신선도만 바꾸며 임시 값·부분 페이지 결과·0 대체값을 노출하지 않는다. 성공하면 한 묶음 전체를 **같은 렌더 커밋**에서 교체하고 실패하면 이전 묶음에 원인·마지막 정상 시각·재시도 가능 여부를 덧붙인다. 다른 측정 시각·계산 버전의 값을 섞지 않으며 음수와 100% 초과를 보존하고 `계산 불가`는 0 대신 이유로 보낸다.
- **자격정보 입력**은 영구 라벨·도움말·필드 오류·오류 요약을 주고 붙여넣기를 막지 않으며, 실패 시 Secret만 지우고 나머지 유효 입력을 보존한 채 비밀 필드로 포커스를 보낸다. **확인 대화상자**(계획 생성 확정·계획 종료·연결 해제)는 대상·비가역 결과·삭제되는 것과 보존되는 것을 먼저 말하고 기본 포커스를 취소에 둔다.
- **재계산은 원 사건을 덮지 않는다.** 조정은 새 버전으로 기록하고 미분류 사건을 공식 행에 섞지 않으며 이전 버전은 읽기 전용으로 남는다. 화면에 내보내는 ID는 복사 가능한 불투명 값이다.
- **계획 입력은 서버가 고정한 스냅샷 값을 읽기 전용으로 쓴다**(기간 1일~1년, 주기 일·주·월). 후속 계획은 생성 직전 새 정상 동기화를 요구하고, 고정된 완료 결과와 이후 현재가치는 끝까지 분리해 보여준다.
- 전역 목적지는 대시보드·조정 이력·설정 셋이고 금융값을 지속 캐시에 두지 않는다. 나머지 접근성·고지 바닥선은 Epic 1에서 그대로 이어진다.

## Cross-Story Dependencies

- **선행 에픽은 Epic 1 전부다.** Story 2.1이 1.8의 재인증과 1.9의 action grant 포트를 `bybit-connection-create` 허가로 처음 소비하고, Story 2.13(계획 중도 종료)·2.16(연결 해제)도 같은 민감 command 계약을 쓴다.
- **Worker는 2.1이 아니라 2.2에서 처음 등장한다.** 2.1은 동기화 작업 큐를 명시적으로 제외하며 lease·heartbeat·fencing과 202 계약은 2.2가 들인다. 2.1의 외부 호출은 요청 문맥 안에서 끝나되 DB 트랜잭션·계정 잠금을 열어 두지 않고, 결과를 받은 뒤 최종 저장 트랜잭션에서 허가·소유권·삭제 상태·운영 제한·기존 연결 여부를 다시 검사한다.
- **핵심 사슬은 순차 의존이다.** 2.1 → 2.2 → 2.3 → 2.4 → 2.5 → 2.6 → 2.7 → 2.8 → 2.9·2.10 → 2.11 → 2.12 → 2.13·2.14 → 2.15 → 2.16. 2.4~2.7은 "입력 수집·검증 → 순수 계산 → 원자 발행 → 화면 표시" 한 사슬을 넷으로 나눈 것이고 각 단계는 앞 단계의 완료 계약 위에서 독립 시험 가능해야 한다.
- **Epic 3과의 순서 긴장은 설계로 해소돼 있다.** Epic 2가 admission에서 "유효한 운영 제한"을 검사하지만 durable restriction을 소유하는 `operations`는 Epic 3이 만들고 그 Story 3.1은 선행으로 Epic 1·Epic 2를 든다. 순환이 아니라 역할 분담이다 — **Epic 2가 제한의 판독·차단 지점 넷을 해당 기능과 함께 선행 구현하고 Epic 3이 그 제한을 만들고 푸는 운영자 표면을 얹는다.** 검사 지점을 뒤로 미루지 않는 것이 Epic 2의 독립 완료 조건이며 Story 3.2도 선행으로 "Epic 2의 restriction 검사 지점"을 든다.
- **Epic 4는 이 에픽을 막지 않는다.** 광고는 공식 결과를 서버에 저장한 **뒤** 중립 전환에서만 시도하므로 Epic 2는 광고 없이 결과로 직접 이동하는 완전한 흐름을 제공해야 한다. **Epic 5**는 전체 계정 삭제 orchestration만 가져가고 모듈별 삭제 경로는 Epic 2 각 스토리가 그 자리에서 완성한다.
- **재연결 정책.** 같은 메인 UID 재연결은 기존 provider account를 재사용하고 기존 watermark부터 다시 동기화하며 공백이 30일을 넘으면 장기 미동기화 선택을 탄다. **다른 메인 UID는 기존 활성 계획에 연결하지 않는다** — 기존 계획을 먼저 종료하고 새 baseline으로 후속 계획을 만들어야 한다.
- **외부 게이트.** 승인된 Bybit 검증 계정·reserved IP·지원 정책 승인은 스토리 완료를 막지 않는 별도 게이트다. 개발·CI는 main/sub UID, 지원·미지원 상태, permission·IP 변화 응답을 담은 fixture로 진행한다.
